# 机制验证工程（4.1 实测脚本集）

> 每课「第四幕 · 4.1 机制验证」里贴出的输出，都由这个目录的脚本真实跑出来。
> 你不必相信我写的数字——`npm run core` 一跑就能自己看到。

## 为什么单独一个工程

课程要证明的机制（定义即数据、编译即翻译、通道归约、策略洋葱、挂起恢复、幂等、沙箱边界……）
都是**通用的 Agent 工程机制**，不绑定任何一家公司的私有代码。所以它们需要一份**自包含**的可运行证据：

- 不需要克隆任何生产仓库
- 不需要数据库 / 消息队列 / 云账号
- 只依赖 `@langchain/langgraph`，全部在内存里跑完

## 跑起来

```bash
cd verify
npm install
npm run check     # tsc --noEmit，类型通过
npm run core      # 课 4 / 5 / 6 / 7 + 课 10 的 interrupt 形状
npm run run       # 课 8 / 9 / 11 / 12 / 13 / 15
npx tsx verify-map.ts   # 课 2 / 3 / 14
```

## 实测环境

| 项 | 值 |

| Node.js | v22.22.2 |
| `@langchain/langgraph` | 1.6.0 |
| `@langchain/core` | 1.3.2 |
| TypeScript | 5.9.3 |
| tsx | 4.23.15 |

> 这些脚本验证的是**机制成立**，不是"某个版本的 API 长这样"。LangGraph 的 API 会演进，
> 但"挂起后节点从头重跑"这类语义属于持久执行模型本身，换版本不会变。

## 一处诚实说明

脚本里的"模型"是桩（stub），不是真 LLM。原因：本课程验证的是**平台骨架**，
不是模型能力——用真模型反而会让输出每次不同，无法作为可复现的证据。
桩模型的行为（决定调哪个工具、产出什么参数）在代码里写死，你能逐行读到。
