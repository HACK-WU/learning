# 验收清单

> 自测项：怎么确认自己真的做成了。逐条勾选，未勾选 = 该项目未完成。

## 必做项

- [ ] **定义与代码分离**：修改 `config/agent.yaml` 的提示词或模型，不碰任何 `.ts` 文件，Agent 行为随之改变
- [ ] **编译产物可复用**：同一份定义连续编译两次，第二次命中缓存（打印日志证明）
- [ ] **状态通道生效**：`approval` 通道的写入走自定义 reducer，两条审批结果按预期合并
- [ ] **中间件拦截生效**：`executeSql` 触发审批，`querySql` 不触发；且把 `wrapToolCall` 注释掉后 `executeSql` 直接执行（证明拦截点确实在中间件）
- [ ] **挂起真不占资源**：审批挂起后 `Ctrl+C` 杀进程，重新启动执行 `npm run resume`，流程从断点继续
- [ ] **拒绝是正常终态**：`npm run demo:reject` 返回结构化拒绝结果，不是异常堆栈
- [ ] **幂等**：同一 `request_id` 提交两次，第二条返回第一次的结果，SQL 只执行一次

## 反例对照项

- [ ] 能说出反例版本里"轮询降低频率为什么仍然不解决问题"
- [ ] 能指出反例中至少 5 处设计缺陷，并对应到本项目的改进点

## 判断力项

- [ ] `设计决策.md` 中的两个权衡，能口头复述"选项 / 选择 / 理由 / 代价"
- [ ] 能解释为什么本项目只做 3 个状态通道，而不是照抄标本系统的 10 个
- [ ] 能给出一份"如果工具数只有 3 个，我会怎么做"的替代结论（即推翻自己的抽象决策）

## 加分项（非必须）

- [ ] 补一个子图委派（主管 Agent 调用工人 Agent）
- [ ] 补一个 token 预算护栏
- [ ] 把文件版 checkpoint 换成 SQLite，验证"换存储不改业务代码"

## 完成标准

8 条必做项全绿 + 3 条判断力项全绿 = 项目完成。加分项不计入完成判定。
