# Agent 工程 · 场景解法库

> **这是什么**：5 道开放设计题。每题给一个真实难题、3 条以上解法谱系、每个解法的机制图与关键代码。
> **怎么用**：先读「🔒 先想」，自己给一个答案，再展开「📖 展开解法」对照。**别一上来就看解法**——这份材料的价值在"你想过之后再看"。
>
> 与另两份产物的分工：**[08-实战经验](../08-实战经验.md)** 讲"会踩什么坑、为什么"（学习态）；**[09-排障速查手册](../09-排障速查手册.md)** 讲"崩了怎么止血"（使用态）；**本库**讲"新要求来了怎么设计"（设计态）。

## 两条通用判据

**判据一：先问"这个约束是谁的"。** 每个设计难题背后都有一个不在你手里的约束（人的响应时间、模型的窗口上限、外部服务的不可控）。解法不是"更聪明的代码"，是**承认这个约束并把代价放到正确的位置**。热更新的约束是"任务已经跑起来了"，幂等的约束是"网络会重试"，上下文压缩的约束是"窗口有硬上限"。

**判据二：每个解法都要问"它坏了会怎样"。** 本库每个解法的机制图上都标了失效点。一个方案的价值不只在"正常时多好"，更在"失效时坏到什么程度"——审批幂等失效是"批两次"，上下文压缩失效是"模型胡编"，两者严重度差一个量级。
