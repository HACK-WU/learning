## 定位与边界

本教程不是任何一家公司产品的使用手册，也不是"最佳实践清单"。它解剖的是**AI Agent 平台的通用工程骨架**——一个真实系统在真实约束下必须回答的那些问题，以及这些问题各自的解法和代价。

> **为什么不再照抄某套私有源码**：本教程早期版本的做法是"挑一套生产系统，把它的实现逐段贴出来讲"。这条路对读者不成立——读者拿不到那个仓库，也读不出"为什么这么写"。所以现在的做法是：**把实现逻辑自己总结归纳成通用机制，给出自包含的核心代码示例，省略部分用伪代码说明**。你要能在自己的机器上跑起来、改动、打断点，才算真的看懂了。

### 三段式（本课程的 DNA）

每课第三幕内部统一走三段，三段是**第三幕的组织方式**，不替代五幕骨架：

| 段 | 名称 | 回答什么 | 证据来源 |
|---|---|---|---|
| 1 | **机制** | 这类系统必须解决什么问题、通行的结构长什么样 | 课程自带的机制实验（`verify/`），可运行、可断言 |
| 2 | **取舍** | 为什么这么做、代价是什么、什么情况下该换 | 约束还原 + 权衡对比 + 可运行的反例 |
| 3 | **重述** | 用当前版本怎么写更好 | 写课时按官方文档核对，不臆造 API（见每课「📖 文档核对」留痕） |

### 三条硬边界

- **不照抄任何私有实现**：课文中不出现"需要你本地有某个仓库才能跑"的命令和路径。所有代码示例要么是课程自带的、要么是通用伪代码。
- **不评价好坏，只讲取舍**：对"看起来过时"的写法，必须交代当时的约束与代价，禁止滑向贬损。
- **不要求跑通全栈**：全部实验在内存里完成，不需要数据库 / 消息队列 / 云账号。

### 可执行基座

| 项 | 值 |
|---|---|
| 机制实验 | `verify/`（14 个脚本段，覆盖 15 课的核心断言） |
| 结课项目 | `projects/数据库变更审批助手/实现/`（TypeScript，真实跑通"挂起 → 进程退出 → 新进程恢复"） |
| 运行时 | Node 22 + `@langchain/langgraph` 1.6.0 + `@langchain/core` 1.3.2 |
| 官方依据 | LangGraph JS / LangChain JS / MCP 规范（逐课在「📖 文档核对」留痕中标注来源与时点） |

> 每课的「4.1 机制验证」都带 `✅ 机制实测于 ...` 留痕，标明是哪台机器、哪个版本、哪个脚本跑出来的输出。没有实测的地方标 `⚠️ 未实测（原因）`，不假装跑过。

## 教学设计判定

### 多角色判定

**单角色，不拆子教程。** 学习者画像为后端 / Agent 开发者，本课程不涉及"开发 vs 运维 / DBA"的职责分野——理解机制、判断设计、动手实现都由同一角色完成。平台部署运维（容器编排 / 多租户运维 / 容量规划）不在本课程范围内。

### 动手环境判定

**命中，阶段 1 首课设「环境准备」（附加课，不计入每阶段 2–4 课配额）。**

环境最小集是"能跑起课程自带的机制实验"，不是"搭起一套生产系统"：

- Node.js 22.x（LangGraph JS 运行时基线）
- npm 10.x + `tsx`（直接跑 TS，无构建步骤）
- `@langchain/langgraph` 1.6.0 / `@langchain/core` 1.3.2 / `zod` 4.x
- 能跑 `verify/` 下的脚本（这是本课程 4.1 实证的主力）
- 数据库 / 消息队列 / 云账号全部**不需要**，所有实验在内存中完成

### 应用实战判定

逐课过三问（场景可得性 / 演进空间 / 非硬凑），配 5 篇：

| 课 | 场景 | 演进两跳 | 判定 |
|---|---|---|---|
| 课 4 声明式定义 | 把硬编码 Agent 改成配置驱动 | 硬编码 → 新增 Agent 要改代码 → 定义即数据 | ✅ 配 |
| 课 6 状态通道 | 单一 messages 改通道化 | 混装一个字段 → 压缩/摘要互相踩 → 分通道 | ✅ 配 |
| 课 7 中间件 | if 判断改中间件 | 散落 if → 改一处漏一处 → 策略层 | ✅ 配 |
| 课 9 多 Agent | 单 Agent 改主管-工人 | 单 Agent 塞满工具 → 上下文爆炸 → 委派 | ✅ 配 |
| 课 10 持久执行 | 审批不丢状态 | 内存等 → 重启丢失 → checkpoint + interrupt | ✅ 配 |

不配实战的课：课 1（环境）、课 2（地图）、课 3（旅程）、课 5（编译器，逻辑内聚、外化为工具收益低）、课 8（模型调用，偏内部机制）、课 11（运行时，账本与幂等是平台内部机制，做成"改造实战"缺可感知的产物）、课 12（MCP 接入，需真实外部服务端才能演示协商与降级）、课 13（成本与上下文，场景分散）、课 14（判断力，本身就是反思课）、课 15（结课项目已覆盖）。

> 按规则，**不配是常态**，不视为缺漏。

### 源码解析判定

**全课不配，理由明确。** 三问逐条：

1. 功能素材：本课程讲的是**平台骨架**（分层 / 编译 / 状态 / 策略 / 持久执行），不是某个库的内部实现；按规则"服务端 / 系统组件不配源码解析"。
2. 认知价值：每课正文本身就是"机制 → 取舍 → 重述"，再拆一份解析篇属重复；真正需要看源码的地方，课程给的是**能跑的最小实现**（`verify/`、`projects/.../实现/`），可读性远高于第三方库的编译产物。
3. 可读性：LangGraph JS 分发的是打包产物（哈希文件名），逐行对照教学价值低。

故不建 `源码解析/` 目录。

- 主要事实来源是**课程自带的机制实验与通用机制归纳**（`verify/` 可跑、可断言，无需查索引）
