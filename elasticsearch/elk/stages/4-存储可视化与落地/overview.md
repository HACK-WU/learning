## 🎯 阶段目标

一句话回答本阶段的核心问题：**采到手、读得懂的日志，怎么才「留得住、用得上」，并在出事时主动叫醒你？**

主角（一条日志）在阶段 2 被「拿得到」（采集进管道）、阶段 3 被「看得懂」（解析成结构化字段）。到本阶段，它终于抵达终点站：**被写进 ES 长期留存、被 Kibana 变成能看懂的图表、并在指标越界时触发告警**。这正是整条故事线的最后一幕，也是整个 ELK 教程的**收束**。

学完本阶段你应该能：

- 用 **data stream + ILM** 给日志定一套「自动换本子、按年龄分级、到期删除」的存储策略，并说清每条后备索引由谁管理、写进谁
- 用 **Kibana** 从零到一搭出自己的检索界面与仪表盘：建 data view、用 KQL 过滤、用 Lens 拖出图表并拼装 dashboard
- 在日志场景给 ES 补上**容量估算、权限与快照**这三块落地运维，并说明它们为什么是「上线前」而非「上线后」的事
- 站在选型会上，用一份**可对照的决策清单**判断「该不该上 ELK、上到哪一步」，并讲清一条日志从产生到告警触发的完整链路（全课收束）

## 📖 本阶段在故事主线中的章节定位（含全课收束）

故事讲的是**一条日志的一生**，全教程分四幕，本阶段是**第 4 幕（最后一幕）**：

1. **看得见全貌**（阶段 1 · 全景与起步）——主角登场，把 ELK 全景与整条路线摊开
2. **拿得到**（阶段 2 · 采集层 Beats）——主角被 Filebeat 从文件里叫醒，搬进统一管道
3. **看得懂**（阶段 3 · 处理层 Logstash）——主角被 Logstash / Ingest 拆成结构化字段、校准时间
4. **留得住、用得上**（本阶段 · 存储可视化与落地）——主角被写进 **data stream 长期留存**（课 10），在 **Kibana** 里变成看得懂的图表（课 11），并在指标越界时**主动触发告警叫醒你**（课 12）——**至此，从「一条日志产生」到「一次告警触发」的完整链路合龙**

> **收束点**：阶段 1 讲的是"主角还在服务器文件里躺着、逐台 grep 找不到"的起点；到本阶段结尾，主角已经走完"产生 → 采集 → 解析 → 存储 → 可视化 → 告警"的整条链。课 12 的知识点 3 用一份「该不该上 ELK」的决策清单 + 知识体系收束，把四个阶段所有线索拧成一股——回答最初的疑问：*到底要不要、以及上到哪一步才算够。*

## 🔧 实操环境速记

macOS arm64 / 18GB 内存 / Docker Compose 起全套容器。版本基线 **Elastic Stack 9.5.3**。

- 命令一律 `docker compose exec <服务> …` 或经 Docker 暴露端口访问（如 Kibana `http://localhost:5601`）
- Filebeat / ES / Kibana 均为 9.5.3 同栈，data stream 相关交互在 Kibana 的 **Stack Management** 里完成
- 本阶段大量操作在 Kibana 界面，正文会用「路径式」描述（如 主菜单 → Stack Management → …）指引；涉及 ES 主课已讲的基础（Data Stream / ILM / 模板 / RBAC / 快照）一律回指，避免重复展开
