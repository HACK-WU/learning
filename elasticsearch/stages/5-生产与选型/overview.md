## 💡 本阶段的关键认知

- **日志/可观测**（ELK）是 ES 最经典的战场，也是很多人接触 ES 的第一个场景
- **向量检索 + RAG** 是 ES 近年最重要的新方向（9.x 密集增强）
- **"该不该用 ES"** 比"怎么用 ES"更难回答——课 14 给一份可直接对照的决策清单
- **认证**：Elastic Certified Engineer，3 小时纯实操，**2026-09-01 考纲升级至 9.3**
- **日志要"换本子"而不是"一本写到底"**：Data Stream 负责自动滚动（rollover），ILM 负责自动过期删除；搜数据流名会**自动跨所有后备索引**
- **向量检索解决的是"意图匹配"而非"字面匹配"**：关键词搜「宠物」只命中写了"宠物"的；向量搜能把"狗"召回并排在"猫"前面
- **RAG 里 ES 只负责"检索"那一半**：检索（ES）→ 拼 Prompt → 生成（LLM），三步缺一不可
- **401 是"你是谁"，403 是"你没权限"**：且 ES 的 403 报错**会直接列出所需权限名**，照着加即可
- **basic license 的坑**：`semantic_text` 能建索引、能建映射，但**一写入就报 `non-compliant for [inference]`**——建时不响、写时才炸
- **分片不是越多越好**（本机实测）：同样 3000 条数据，1/3/50 个主分片的 **p95 是 16.58/16.48/35.90 ms**（50 片慢 2.2 倍），**存储 77.3/88.9/361.9 kb**（4.7 倍），而 **p50 几乎没差别**——代价在长尾不在均值
- **多分片会让聚合不准**（最致命）：单分片 `doc_count_error_upper_bound: 0` 且每桶精确 100；50 分片误差上界 **82**，桶计数直接掉到 95/90。分片越多，top N 截断越狠
- **ES 的事务只到单文档**：`_seq_no` + `_primary_term` 是唯一保障，改 A 再改 B 中间崩了 **A 不回滚**。多文档原子性请交给关系型数据库
- **写入不是实时的**：`GET /_doc/{id}` 走 translog，**实时**；`SEARCH` 走段，**近实时**（默认 1 秒）。批量导入可设 `refresh_interval=-1`，导完再手动 refresh
- **判断标准只有一句**：**ES 是索引副本，不是原始账本**——这份数据丢了能不能重建？能就大胆用，不能就别把 ES 当唯一数据源
- **考纲已变**：Elastic 认证 2026-09-01 起从 8.15 升 9.3，新增 Architecture / semantic search / ES|QL / Security，**移除 runtime fields / 跨集群 / searchable snapshot**——旧攻略的重点别再套用
