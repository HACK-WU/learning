# 验收清单：怎么确认自己真的做成了

> 每条都给出**验证命令**和**预期结果**。能逐条打勾，才说明不是"跑通了"而是"做对了"。
> 全部命令在 `elasticsearch/projects/商品搜索服务/实现/` 目录下执行。

## A. 环境与初始化

| # | 自测项 | 验证命令 | 预期结果 |
|---|--------|---------|---------|
| A1 | 依赖装好了 | `node -e "console.log(require('@elastic/elasticsearch/package.json').version)"` | 输出 `9.5.1` |
| A2 | 连得上集群 | `npm run init` | 显示 `ES 版本 9.5.1 ｜ 节点 3 个` |
| A3 | **索引模板真的匹配上了** | 见下方 A3 详述 | 预览显示 **字段 11 个** |
| A4 | IK 分词插件可用 | 由 A3 隐含验证 | 若 IK 没装，`npm run init` 会直接报 `analyzer [ik_max_word] not found`，根本走不到 A3 |

**A3 详述（这条最容易翻车）**：`npm run init` 的输出里必须有

```
🔍 预览 cap_products_v1：字段 11 个，title.search_analyzer = (未设置 → 沿用索引分析器)
```

如果显示**字段 0 个**，说明索引模板没匹配上——索引照样建得出来、只是 mappings 和 settings 全空，
而且**不报任何错**。最常见的根因是模板 `index_patterns` 写成了连字符 `cap_products-*`，
而索引名用的是下划线 `cap_products_v1`。

| C7 | `--keyword-file` 路径可用 | `node search/search.js --keyword-file=data/keyword.txt` | 显示「来源：文件」，命中 **19 条**（项目已自带该样例文件） |

**C3 详述（刻意避开中文参数）**：

```bash
node search/search.js                      # 内置关键词「苹果手机」，不加筛选
node search/search.js --min-price=6000     # 同样的关键词，加一个价格筛选
```

对比两次输出里**同一条文档**（例如 `苹果 iPhone 15 Pro 钛金属 128G 手机`）的分数，应当**一模一样** ——
价格条件进了 `filter`，只筛选不打分。
（这里特意用数字筛选而不是 `--brand=苹果`：中文参数在 PowerShell 5.1 下会被 GBK 误读，见 C6。）

## I. 整体

| # | 自测项 | 验证命令 | 预期结果 |
|---|--------|---------|---------|
| I1 | 全流程一次跑通 | `npm run demo > demo.log 2>&1; echo $LASTEXITCODE` | 退出码 **0**，日志含 7 个步骤标题 |
| I2 | 可完全重建 | `npm run reset` 然后 `npm run demo` | 从零恢复到同样状态（38 条、别名 → v2） |
| I3 | 模块被 import 时无副作用 | `npm run switch` 的输出里 | **不能出现**「初始化 v1 结构」「🎉 初始化完成」 |
| I4 | 环境可清理 | `npm run reset` | 全部 `cap_*` 索引 / 数据流 / 模板 / ILM 被删除 |

> I3 是本项目调试过程中真实踩到的坑：`reindex-switch.js` 会 `import` `es/schema.js`，
> 如果 `schema.js` 在模块顶层无条件调用 `main()`，切索引就会顺带把整个初始化重跑一遍。
> 修法是 `es/cli.js` 里的 `runIfEntry()`——只在"被直接运行"时才执行 `main()`。
