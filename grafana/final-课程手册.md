## 全课程一句话

> **Grafana 自己不存数据、也不生产数据，它做的是「把散在三个系统的观测数据，拉平到同一张时间轴上」。**

理解了这一点，12 课的取舍都能自己推出来：它要拉平，所以得有插件模型（课 1）；要同一张时间轴，所以时间选择器在 dashboard 级（课 3）；要能跨系统跳，所以 exemplar 和 derivedFields 必须三方配合（课 9）。

## 阶段 1：看得见

> 回答"它到底是个什么东西、怎么让第一个面板出图"。这一阶段打下的三条地基（**不存时序数据 / 时间在 dashboard 级 / 配置才是它的资产**），后面 9 课反复回扣。

### 课 1《Grafana 是谁：一个不存数据的看图工具》

> **一句话**：Grafana 是服务员不是后厨——它不存菜（时序数据），只存菜单（仪表盘配置）；后厨关门它只是没菜上，后厨着火才是真没了。

**核心要点**
- **存什么、不存什么**：92 张表**全是配置**，0 张时序表——这是全课的地基结论
- **插件替换了哪一段**：上游问法与下游画法不变，只换中间翻译层
- **一条查询配什么面板**：instant → Stat，range → Time series，按维度拆 → Table（需 Transform）

![Grafana 定位（阶段 1 路径图）](stages/1-看得见/assets/stage-01-kan-de-jian-path.svg)

**关键命令**：`docker run grafana/grafana:13.2.1` · `/api/health` · 数数据库表

→ [完整讲义](stages/1-看得见/lessons/lesson-01-Grafana是谁：一个不存数据的看图工具.md)

### 课 2《第一个面板：从零到看得见》

> **一句话**：容器起来了不算数，`/api/health` 里 `database: "ok"` 才算数——而且注意**这个冒号后面有个空格**（紧凑 grep 恒假）。

**核心要点**
- **三道坎 → 三个判据**：起来了吗（health）· 进得去吗（登录用 **`user`** 字段，不是 `username`）· 连得上吗（数据源 health）
- **URL 从容器视角写**：`access=proxy` 时用**容器名** `grafana-prom:9090`；写 `localhost` 会 502——因为**拨号的是容器自己**
- 13.2.1 **不强制改密**，默认口令能用；首启后台装 5 个插件约 60 秒，**不阻塞**使用

**关键命令**：`docker run -d --name grafana-lab -p 3001:3000 ...` · `curl /api/health` · `curl -d '{"user":"admin","password":"admin"}' /login`

→ [完整讲义](stages/1-看得见/lessons/lesson-02-第一个面板：从零到看得见.md)

### 课 3《变量与 Dashboard 组织：一张图服务 N 台机器》

> **一句话**：时间选择器在考卷上，不在题目上——所有题共用同一个钟；面板上的"相对时间"只是建议用时，不是真的给这道题加钟。

**核心要点**
- **变量是前端文本替换**：Prometheus **根本不认识** `$host`，探针抓包看到的是替换后的值；内置宏（`$__rate_interval`）才由后端替换
- **多值必须用 `=~`**：`$host` 在多值时拼成 `a|b`，用 `=` 恒不匹配
- **Row 是 `type:"row"` 的面板**，折叠会移动子面板；**Repeat 只存 1 份模板**，前端按值个数复印

```promql
up{instance=~"$host"}    # ✅ 多值正确
up{instance="$host"}      # ❌ 多值时恒不匹配
```

**关键命令**：查 dashboard JSON 看 `templating.list` · 抓包看 `executedQueryString`

→ [完整讲义](stages/1-看得见/lessons/lesson-03-变量与Dashboard组织：一张图服务N台机器.md)

## 阶段 2：查得到

> 回答"怎么把查得出来变成查得对、看得懂"。这一阶段的共同主题是**分清"哪一步在哪执行"**——很多困惑其实是找错了层。

### 课 4《查询编辑器与数据源协议：一次查询的完整旅程》

> **一句话**：Code 是原文，Builder 是填空表，Explain 是解说员；三者共享同一份 `expr`，**切换模式本身不改数据**，但 Builder 装不下的写法会在切换时被丢掉。

**核心要点**
- **不要以为三态平级**：**Code 是超集**——文本能表达 Builder 的全部，反之不能。正确心智是「原文 + 一个有损视图 + 一个只读解说」
- **四层三跳**：浏览器 → Grafana 后端 → 数据源 → 回到前端；后端会**改写**请求（如 `Accept-Encoding: gzip` 覆盖数据源里配的 `identity`）
- **状态码要分内外层读**：外层 200 不代表成功，内层 `{} JSON` 里的 `executedQueryString` 才是真相

| 症状 | 属于哪层 | 怎么查 |
|---|---|---|
| `connection refused` | L3 断了 | 内层 502，查数据源配置与网络 |
| 空白无报错 | L3 通但没数据 | 内层 200，去 `{} JSON` 看 `executedQueryString` |
| `parse error` | L3 通但被拒 | 内层 400，改表达式 |

→ [完整讲义](stages/2-查得到/lessons/lesson-04-查询编辑器与数据源协议：一次查询的完整旅程.md)

### 课 5《Transformations：把查出来的数据捏成想要的形状》

> **一句话**：Transform 是前端的"备菜台"——数据在那一跳就已**原样到达浏览器**，Transform 只是把它择好、摆盘，**一件也没少买**。

**核心要点**
- **它在前端，所以减不了流量**：60 行压成 3 行，网络传输量一点没省。**Transform 省的是你的眼睛，不是带宽**
- **能算的写进 PromQL**：要压成 3 行，优先 `avg by (instance)`；PromQL 做不到的（如两列并排）**才**用 merge
- **排障时先排除它**：Transform 位于浏览器这一层，是"最先看到、也最先被误判"的一环

**关键 Transform**：merge（并帧）· reduce（归约）· groupBy（按字段分组）· rename（改名）

→ [完整讲义](stages/2-查得到/lessons/lesson-05-Transformations：把查出来的数据捏成想要的形状.md)

### 课 6《变量进阶与动态仪表盘》

> **一句话**：变量有四种类型，取值都由前端**现查现填**；链式依赖就是"前端替换"的递归——先替换被引用的，再查依赖的。

**核心要点**
- **不是印好的菜单**：Query 变量的选项是**运行时现查**的，数据源变了选项立刻变——更像"每次打开都重新问一遍厨房"
- **多值拼正则，不是填空**：`${host:regex}` 而非 `$host`
- **Repeat 是前端复印机**：代价是 **N× 查询**，展开 20 台就是 20 条查询

| 类型 | 取值来源 |
|---|---|
| Query | 数据源现查（`label_values(...)`） |
| Custom | 手写固定值 |
| Interval | 预置间隔 |
| 链式 | 引用另一个变量 `$A` |

→ [完整讲义](stages/2-查得到/lessons/lesson-06-变量进阶与动态仪表盘.md)

## 阶段 3：叫得醒

> 回答"怎么让告警真会响、且不乱响"，并打通指标—日志—链路三级下钻。这是全课的**能力高峰**。

### 课 7《告警架构：规则在哪求值、状态怎么迁移》

> **一句话**：Grafana 自己雇了个值班员——它定期去数据源问、自己判断、自己记状态、自己发通知；代价是**Grafana 挂了，告警就不响了**。

**核心要点**
- **求值在 Grafana 内部**：Prometheus 侧 **0 条规则**，数据源完全不知道有告警这回事
- **`for` 是"连续满足"**：实际延迟 = ⌈for / interval⌉ × interval；**恢复不受 `for` 约束**，所以"缓慢触发、快速恢复"
- **No Data 与 Error 是两类独立失败**，各四种取值；**真实宕机走的是 Alerting（up=0），不是 NoData**

> ⚠️ 这个不对称有个副作用：指标在阈值附近抖动时，告警会**反复快速恢复、缓慢触发**，导致通知稀少但状态频繁跳变——课 8 的分组与抑制给出解法。

→ [完整讲义](stages/3-叫得醒/lessons/lesson-07-告警架构：规则在哪求值、状态怎么迁移.md)

### 课 8《告警规则与通知策略实战》

> **一句话**：查询决定"看什么"，条件决定"什么算异常"，评估行为决定"多久看、持续多久、看不清怎么办"；而**条件里的 Reduce 写法，悄悄决定了你会收到几条告警**。

**核心要点**
- **规则三要素**：查询（query）· 条件（condition，含 reduce）· 评估行为（interval / for / No Data）
- **Reduce 决定告警条数**：按 `route` reduce 会得到**每个 route 一条**；reduce 成单值则只收到一条
- **通知策略树**：按标签路由，子策略必须设 `continue: false`，否则一条 critical **同时**命中父策略和子策略，制造重复噪声
- **`repeat_interval` 是下界不是闹钟**：实测配 1m 实际 90s、配 40s 实际 60s——会向上跳到 `group_interval` 的检查点

> 改了告警配置没立刻看到效果，**先算 `repeat_interval`，别急着改第二遍**。

→ [完整讲义](stages/3-叫得醒/lessons/lesson-08-告警规则与通知策略实战.md)

### 课 9《日志与链路：指标之外的另外两只眼》

> **一句话**：Loki 赌你查日志时已经知道"哪个服务"，所以**只给标签做索引**；LogQL 长得像 PromQL，但它**查的是行，不是数**。

**核心要点**
- **高基数陷阱**：`trace_id` / `user_id` **绝不能**提升为 Loki 标签——每个值一个 stream，索引爆炸。留在内容里用 `|~` 检索
- **三级下钻三件套**：exemplar（指标→链路）+ derivedFields（日志→链路）+ tracesToLogs（链路→日志）
- **exemplar 三缺一不可且全部静默**：①应用显式传 `exemplar={'trace_id':...}` ②Prometheus `--enable-feature=exemplar-storage` ③数据源 `exemplarTraceIdDestinations`

| 检查 | 命令 / 位置 | 判据 |
|---|---|---|
| Prometheus 存了没 | `/api/v1/query_exemplars` | 非空且带 `trace_id` |
| Grafana 知道跳哪 | 数据源 `exemplarTraceIdDestinations` | 指向 Jaeger 的 uid |
| 日志可点 | 数据源 `derivedFields` | `matcherRegex` 能匹配 trace_id |

> 这三个条件分布在**应用 / Prometheus / Grafana** 三处，失败时**全部静默**——指标照常显示，只是圆点不存在。

→ [完整讲义](stages/3-叫得醒/lessons/lesson-09-日志与链路：指标之外的另外两只眼.md)

## 阶段 4：管得住

> 回答"怎么让配置可版本化、可迁移、可交接"。这一阶段的主题是**状态存在哪、谁能改、改了会不会被抹掉**。

### 课 10《Provisioning：把点击变成配置文件》

> **一句话**：Provisioning = **启动时的一次 INSERT**——文件进数据库，然后文件就下班了；**uid 必须自己写死**，否则重建一次环境，引用全断。

**核心要点**
- **单向、不可逆**：你后来在 UI 上做的一切，下次启动**都会被文件抹掉**
- **启动期严格校验**：这是课 4/5/6/9「后端不校验」模式的**唯一反转**——alerting provisioning 写错直接崩溃。原因在时机：运行时错了顶多显示异常，**启动期错了就没法提供服务**
- **`editable` 写入、`readOnly` 读出**：只看 `editable` 会误判"配置丢了"

| 三类文件 | 管什么 |
|---|---|
| `datasources/` | 数据源（含 exemplar / derivedFields 配置） |
| `dashboards/` | 面板 JSON + provider |
| `alerting/` | 告警规则 + 通知策略 + 联系人 |

→ [完整讲义](stages/4-管得住/lessons/lesson-10-Provisioning：把点击变成配置文件.md)

### 课 11《权限与服务账号：谁能看、谁能改、程序怎么访问》

> **一句话**：Org 是墙（跨过去 404 装作不存在），User 是钥匙（每个 Org 一把、角色各不同），**Team 只是钥匙串**（方便批量发，本身开不了锁）。

**核心要点**
- **角色是入场券，文件夹权限是座位号**：角色决定"能不能做这个动作"，文件夹权限决定"能对哪些资源做"
- **静默降级比报错更危险**：`folderUid` 放错位置**返回 200** 却落到别处；`hasAcl` 恒 false 是遗留字段。应对只有一条——**验证结果，而不是看状态码**
- **API Key 接口在 13.2.1 已移除**，只剩 `api_key` 遗留表；程序访问改用**服务账号 + token**

> 本课沉淀的纪律第二次生效：**状态被污染时，先起干净对照**（新建 `dave` 从零验证，才拿到可信结论）。

→ [完整讲义](stages/4-管得住/lessons/lesson-11-权限与服务账号：谁能看、谁能改、程序怎么访问.md)

### 课 12《性能、高可用与升级运维》

> **一句话**：排查性能，**先看是不是在渲染，再看响应体多大，最后才数面板**。

**核心要点**
- **三个直觉都被实测推翻**：①"面板多就慢"——80 倍面板只慢 4.5 倍 ②"时间窗长数据多"——`maxDataPoints` 封顶 ③"降级即回滚"——降级后 404 且库已被改
- **SQLite = 单人、PG = 团队**：换 PG 不是为了快，是为了**文件无法共享**这个架构事实
- **HA 会话默认随数据库共享**；token **落库为哈希**；**回滚 = 恢复备份**，不是降级

| 排查顺序 | 看什么 |
|---|---|
| 1 · 渲染 | 是不是在服务端渲染图片 |
| 2 · 响应体 / 基数 | 字节数、序列数 |
| 3 · 面板数 | 影响最小 |
| 4 · 时间窗 | `maxDataPoints` 已封顶，通常不是它 |

→ [完整讲义](stages/4-管得住/lessons/lesson-12-性能、高可用与升级运维.md)

## 结课实战项目《从告警到定位》

> **需求**：告警在半夜响起时，值班的人能在 **3 分钟内**从收到告警走到定位到根因。

| 项 | 内容 |
|---|---|
| 覆盖知识点 | **4 阶段 / 15 个知识点**（阶段1×4、阶段2×4、阶段3×4、阶段4×3，逐个回指课时） |
| 非功能约束 | 性能（`maxDataPoints:1000` + Loki 低基数标签）· 可维护性（脚本生成 JSON + 全量 provisioning）· 错误处理（`ctx.is_valid` 判空 + 推送兜底） |
| 真权衡决策 | 3 个：日志采集（Promtail / 直推 / Docker 驱动）· 告警设计（症状型 / 原因型 / 三类分级）· 配置管理（纯 UI / UI+导出 / 全量 provisioning） |
| 规模 | 多文件工程：`app` / `prometheus` / `provisioning` / `webhook` 分层，含 `up.sh` / `down.sh` 一键启停 |

**三级下钻闭环实测**（同一个 trace_id 在三处全部命中）：

```
[指标 → 链路]  Prometheus query_exemplars：24 组 / 3063 个 exemplar，全部带 trace_id
                取其中一个：c57731cce9f6077bc0b628fd175563fa
[链路 → 日志]  Loki {job="shop"} |~ "c57731..."  → 命中 2 条
[trace 内部]   Jaeger：spans=2
                 根  HTTP /checkout   2.71s
                 子  call-payment     1.71s（占 63%）
```

**产物**：[README.md](projects/从告警到定位/README.md) · [设计决策.md](projects/从告警到定位/设计决策.md) · [反例对照.md](projects/从告警到定位/反例对照.md) · [验收清单.md](projects/从告警到定位/验收清单.md) · [实现/](projects/从告警到定位/实现/up.sh)

**本项目最有价值的一个坑**（事实核查新发现，前 12 课全漏）：

> 比率型告警 `A / B` 在 **A 无数据时返回空（不是 0）** → reduce 得 nil → `humanizePercentage: can't convert <nil> to float`。
> **它只在系统健康时暴露**——测告警一律在故障态（分子有值），所以长期潜伏。
> 修法：`(A / B) or (B * 0)`。
> 口诀：**写了「A / B」就问一句「A 没数据时会怎样」**——答案是"变空"，不是"变 0"。

## 考点速记

> 每条都是**实测过的**，不是文档抄的。适合复习与面试。

### 定位与架构

- Grafana **不存时序数据**：92 张表全是配置，0 张时序表
- 插件替换的是**中间翻译层**：上游问法与下游画法都不变
- 登录字段是 **`user`** 不是 `username`（`username` 返回 400 `form-auth.invalid`）
- `/api/health` 里是 `"database": "ok"`，**冒号后有空格**

### 查询与变量

- 变量是**前端文本替换**；Prometheus 不认识 `$host`
- 多值必须 **`=~`**，用 `=` 恒不匹配；拼正则用 `${var:regex}`
- **Code 是超集**：Builder 装不下的写法切一次就丢
- Transform 在**前端**，**减不了流量**
- 时间是 **dashboard 级**；面板 `timeFrom` 只是显示建议，后端不认

### 告警

- 求值在 **Grafana 内部**，数据源侧 0 条规则 → **Grafana 挂了告警就不响**
- `for` 是**连续满足**：延迟 = ⌈for/interval⌉ × interval；**恢复不受 for 约束**
- **真实宕机走 Alerting（up=0），不是 NoData**
- Reduce 写法决定**收到几条告警**
- `repeat_interval` 是**下界不是闹钟**（配 1m 实测 90s）
- 子策略必须 `continue: false`，否则一条告警发两处
- 模板里 `$labels` **只含查询返回的标签**；range query 要先 reduce 才能用 `$values.B.Value`

### 日志与链路

- Loki **只给标签做索引**，LogQL **查的是行不是数**
- `trace_id` / `user_id` **绝不能**提升为标签（每个值一个 stream）
- exemplar 生效三条件缺一不可，**且失败全部静默**
- `prometheus_client` **不会自动挂 exemplar**，必须显式传参
- Jaeger 端口可能因宿主机冲突顺延（16686 → 16687）

### 治理

- Provisioning **单向不可逆**，UI 改动下次启动被抹掉
- **uid 必须写死**，否则重建引用全断
- 运行时**不校验**、启动期**严格校验**、此外还有**静默降级**
- **HA 会话随数据库共享**；token 落库为**哈希**；**回滚 = 恢复备份**
- 排查性能：**渲染 → 响应体/基数 → 面板数 → 时间窗**

## 决策清单

| 你要决定什么 | 判断依据 | 出处 |
|---|---|---|
| 数据源连不上 | URL 是否从**容器视角**写（容器名，不是 localhost） | 课 2 |
| 图表空白但无报错 | 看内层 `executedQueryString` 是不是被改写/替换错了 | 课 4 |
| 数据行数太多 | 先问"能在 PromQL 里聚合吗"，能就别用 Transform | 课 5 |
| 要不要用 Repeat | 代价是 **N× 查询**，20 台就是 20 条 | 课 6 |
| 告警延迟对不上 | 算 `⌈for/interval⌉ × interval`，不是 `for` 本身 | 课 7 |
| 收不到告警 | 先算 `repeat_interval`，再查策略树 `continue` | 课 8 |
| exemplar 圆点不出现 | 按 应用传参 → Prometheus 开关 → 数据源配置 三处查 | 课 9 |
| 改的配置不生效 | 先怀疑**状态残留**，起干净实例对照 | 课 10 / 11 |
| 权限"说不清" | 角色=入场券、文件夹权限=座位号；**验证结果别看状态码** | 课 11 |
| dashboard 慢 | 渲染 → 响应体 → 面板数 → 时间窗，别一上来数面板 | 课 12 |
| 要不要上 provisioning | 要跨环境迁移 / 团队交接就要；uid 必须写死 | 课 10 |
| 单机还是 HA | SQLite=单人、PG=团队；换 PG 是为了共享不是快 | 课 12 |
