**课 8 交付的三个知识点**：
1. **federation**：`/federate` 端点返回的是**带毫秒时间戳的当前值**（不是历史序列）；**不搬历史**（查 1 小时前返回 0 条，全局节点历史从联邦配置时刻开始）；**不解决容量问题**（全局节点要存下全部数据，实测 10×100 万 → 全局仍 1000 万），它扩的是**采集能力**不是存储能力；配置三要素 `metrics_path: /federate` + `params: match[]`（不写返回空且不报错）+ `honor_labels: true`；**TYPE 全变 untyped 但不影响 rate()**（固定时刻对比：叶子 1.2 = 全局 1.2）；`honor_labels=false` 时 `job`/`instance` 被改写成联邦 target（**丢的是溯源信息，条数不变**）。
2. **HA 与数据一致性**：双副本**互不感知**，各自独立采集与存储，**数据永远不相等**（连续 6 次采样平均差 **9.63**、最大 **23.11**，成因是抓取定时器相位不同）；**Prometheus 自己不去重**（它不知道对方存在）；去重在后端，靠 **`replica` 标签保留两份 + 查询时 `max/avg without(replica)` 聚合**；VM 的 `dedup.minScrapeInterval` 只在**标签完全相同**时介入，带 replica 时不合并（**这是正确行为**）。
3. **external labels 的正确用法**：只加在**出站数据**（federate / remote write），**不影响本地查询**（本地查不到 cluster，告警规则里也用不了）；`cluster` 必须**全局唯一**；HA 副本**必须带 `replica`**——无 replica 时后端 dedup 合并成一份，看似干净，实则**值在副本间无规律跳变**（实测 4605.37~4670.70）且**失去"某个副本掉线"的感知能力**。

**课 8 回收的伏笔**：

**课 7 交付的三个知识点**：
1. **remote write 协议与队列**：三层结构（TSDB WAL → shard 队列 → HTTP 客户端）；v3.14.0 指标名已变（`samples_out_total`→`samples_total`、`dropped_total` 已移除、`bytes_sent_total`→`bytes_total`）；`in − sent` **不可相减**（标签不同，有约 -1450 恒定偏移）；`pending` 可超 `capacity`（实测 1199 > 1000）因为有 WAL 兜底；500/503 是**可重试错误**（`failed_total` 始终为 0）；积压会完整补发（恢复期 **2.00x**）；**真正丢数据的位置是 WAL 被截断**（截断由 TSDB 保留期驱动，与发送确认**解耦**——实测 45 分钟两侧磁盘只增不减）；shard 解决"发得慢"不解决"发不出"（后端 5xx 时 shards 恒为 1）。
2. **remote read**：三种读取模式（SAMPLES / STREAMED_XOR_CHUNKS / STREAMED_CHUNKS）；**失败是静默的**（`status` 仍是 `success`，原因只在 `warnings`）；VM 单节点版**不支持** `/api/v1/read`（400 `unsupported path requested`）；代价 **2.69x**（本地 1.6ms vs 远端 4.4ms）；**external_labels 三段式**（write 附加 → read 附加到选择器 → 返回前剥离，**显式指定反而 0 条**）；告警与规则求值**只走本地 TSDB**。
3. **Agent 模式**：`--agent` 是**独立 flag**（3.0 转正，非 `--enable-feature=agent`）；**拒绝任何 `rule_files`，含 recording rules**（`field rule_files is not allowed in agent mode`，进程拒绝启动）；能力边界用 HTTP 状态码区分（查询类 **422** = 端点存在但模式禁用，状态类 200）；无 `head_series` / `head_chunks`；同起点实测内存 **-25%**、磁盘 15 分钟 1.2x / 45 分钟 1.63x；WAL 只留 **4h**（`retention.max-time=4h`）；自监控**必须外置**（查不了自己，但 `/metrics` 可用）。

**环境实测备注（课 2 新增）**：
- **手写 `curl` 查 PromQL 时，`{` 和 `}` 必须 URL 编码**，否则返回 `HTTP 400 parse error: unexpected "="`。与引号无关——单引号、双引号、反斜杠转义都无法解决。**推荐写法**：`curl -s -G 'http://host:port/api/v1/query' --data-urlencode 'query=up{job="x"}'`（让 curl 自动编码）。浏览器和 Grafana 会自动编码，所以只在手写 curl 时撞上。**这是连续两课都踩到的同类问题（课 1 是 wget 的 body 参数，课 2 是 curl 的 URL 参数），写讲义时凡涉及命令行传参都必须实测。**
- 本机 `honor_labels` **没有 `auto` 取值**（布尔字段），写 `auto` 会导致 Prometheus 启动失败退出码 2。
- **PowerShell 传参陷阱（第三次印证）**：`for c in ...; do docker rm -f $c; done` 这种内联 bash 循环里的 `$c` 会被 PowerShell 吃掉，导致命令失效（表现为"container name already in use"，实为清理未生效）。**一律把循环写进 `.sh` 脚本文件再执行**。
