### 多角色判定（Step 1.1）

- **主线角色**：后端应用开发者——在 Python 里写跨机器协作的服务。
- **判定过程**：命中信号 ① 官方文档分角色组织？gRPC 文档确有「语言侧」与「运维/部署」之分，但本课程只涉语言侧与调用语义，不涉集群运维；② 现实分岗位？分布式系统的运维确实由 SRE 承担；③ 知识块可切分？可以，但切出去的内容（集群部署、监控告警、容量规划）在仓库里已有 k8s / Prometheus / Grafana / 各中间件课程覆盖。
- **判定结果**：**不拆子教程**。理由：信号只命中 1 条；运维内容已有既有课程承接，本课程只需提及级引用；用户已确认不做子教程。主线中涉及运维的知识（如服务发现依赖注册中心）只写一句 + 指向对应课程。

### 四个判定（Step 1.1）

| 判定 | 结果 | 依据 |
|------|------|------|
| 多角色 | 不拆 | 见上 |
| 动手环境 | **设「环境准备」课** | 技术域，4.1 与 Phase 3 均要求读者自己跑代码；阶段 1 首课固定为环境准备，不计入「每阶段 2–4 课」配额 |
| 应用实战 | 逐课判定（见下表） | 三问：场景可得性 / 演进空间 / 非硬凑 |
| 源码解析 | **不配** | 本课程是应用开发主题，不是库 / SDK / 框架主题。讲的是「怎么设计跨机器协作」，不是「grpcio 内部怎么实现」。服务端组件（Redis）也不在探源范围内 |

#### 应用实战逐课判定

| 课 | 场景可得性 | 演进空间（≥2 跳） | 非硬凑 | 结论 |

| 课 4 时钟、顺序与一致性光谱 | 无自然场景 | 纯理论，无「基础 → 问题 → 综合」 | 强配会变成抄概念 | **不配** |
| 课 5 接口契约与 gRPC | 有（订单服务对内接口） | REST/JSON → proto 契约 → gRPC 四形态 | 全部落在本课知识点 | **配** |
| 课 6 超时、重试、幂等 | 有（扣款接口超时） | 直接重试 → 幂等键 → 超时预算 + 重试上限 | 是本课知识的直接组合 | **配** |
| 课 7 熔断、限流、隔离 | 有（下游挂了拖垮自己） | 无保护 → 超时 → 熔断 + 舱壁 | 本课知识即可成立 | **配** |
| 课 8 服务发现与负载均衡 | 有（实例扩缩容） | 硬编码地址 → 注册中心 → 客户端 LB + 健康检查 | 需少量注册中心知识，点到为止 | **配** |
| 课 9 分布式事务与 Saga | 有（跨服务下单） | 本地事务 → 两阶段 → Saga 补偿 | 本课知识即可成立 | **配** |
| 课 10 事务性发件箱与幂等消费 | 有（下单后发消息） | 写库后发消息 → 发件箱 → 中继 + 幂等消费 | 本课知识即可成立 | **配** |
| 课 11 分布式锁与 fencing token | 有（定时任务防重复） | SET NX → 锁续期 → fencing token | 本课知识即可成立 | **配** |
| 课 12 分区、复制与读写一致性 | 有（订单按用户分片） | 单库 → 分片 → 副本 + 读己之写 | 需少量分片知识，固在本课 | **配** |
| 课 13 分布式任务与计算选型 | 无（选型类，偏决策） | 决策对比为主，演进空间弱 | 强配会变成 Celery 教程 | **不配**（改由 4.1 做选型对照表；Celery 有独立课程） |
| 课 14 跨服务可观测性与故障定位 | 有（一次跨服务慢请求） | 单服务日志 → traceId 串联 → 指标 + 日志 + 链路三合一 | 本课知识即可成立 | **配** |

> 结果：14 课中配 10 篇应用实战（课 3、5、6、7、8、9、10、11、12、14）。不配的 4 课各有明确理由，属"按需配套是常态"。
