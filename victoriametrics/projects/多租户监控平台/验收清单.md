## 四、理解验收（能说清才算会）

### 决策类

- [ ] 说清**决策 1**：为什么每租户一个 vmagent，而不是单 vmagent + 标签？
- [ ] 说出决策 1 的翻转条件（答对要点：租户少且互信时，单 vmagent 更划算）
- [ ] 说清**决策 2**：为什么每租户一个 vmalert？（答对要点：`-datasource.url` 只有一个，共用会导致假告警 + 真告警不响）
- [ ] 说清**决策 3**：为什么错误率要按 path 聚合？（答对要点：全站口径稀释故障）
- [ ] 说清**决策 4**：高基数治理为什么以采集层为主？（答对要点：现实中常改不动应用代码）
- [ ] 说出决策 4 的「根治」方案是什么（答对要点：应用层压根不产出该标签）
- [ ] 说清**决策 5**：为什么 `absent(up)` 检测不出采集中断？（答对要点：历史序列仍在，`absent()` 恒为 0）

### 踩坑类

- [ ] 说出**坑 1**：`labeldrop` 该写在哪个配置段？（答对：`metric_relabel_configs`）
- [ ] 说出 `relabel_configs` 与 `metric_relabel_configs` 的作用对象区别
- [ ] 说出**坑 4**：vmalert 的 `-remoteWrite.url` 为什么不能手写 `/api/v1/write`？（答对要点：vmalert 会自动补，写了会路径重复 → 400）
- [ ] 说出**坑 6**：采集中断检测的正确表达式（答对：`absent(last_over_time(up[2m]))`）
- [ ] 说出**坑 7**：配了 `unauthorized_user` 会造成什么后果？
- [ ] 说出**坑 8**：清理 bind mount 数据时清 docker volume 会怎样？（答对：清了个寂寞，旧数据一条不少）

### 静默失败识别

- [ ] 说出本项目 8 个坑里**有几个是静默失败**（答对：**6 个**）
- [ ] 说出静默失败的共同特征（答对要点：不报错、能跑通、只是功能悄悄不生效或数字悄悄是错的）
- [ ] 说出**验证原则**：为什么本项目要做 14 项断言 + 6 项故障演练，而不是"跑起来就行"
