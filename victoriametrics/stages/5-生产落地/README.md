**核心结论（2026-09-02 实测）**

1. **快照是硬链接的冻结视图**——快照文件与原始数据同一 inode（`links=3`），建快照 `df` 仅增 **184 KB**；
   判断磁盘占用必须用 `df`，`du` 会把硬链接重复计数（实测 `du` 增 54 KB 而 `df` 增 184 KB）。
2. **vmbackup 拒绝无快照备份**（`-origin cannot be empty`），是设计而非缺陷。
3. **增量备份**：首次 7,169,266 B，第二次仅 **136,362 B（1.9%）**；备份期间 20 次写入全成功，不阻塞服务。
4. **迁移实测**：vmctl remote-read 迁 1058 万样本 / 195.4 MB 用时 **5.76 秒**，样本层面幂等可安全重跑。
5. **删除是墓碑机制**：`delete_series` 返 204 且日志确认 `Deleted 20000 series`，但删 5 万条后磁盘
   **反增 2,348 KB**、`/series/count` 不降——**不可逆、无回收站**，删除前必须确认备份时间点早于删除。
6. **RTO / RPO 实测**：RTO = **2,548 ms**（纯 vmrestore 1,126 ms）；RPO 由备份频率决定，
   实测灾后写入的 500 条数据全部丢失。

## 阶段决策清单

- [ ] 什么时候该用 vmagent 替代 Prometheus 抓取
- [ ] 告警规则放 vmalert 还是 Grafana
- [x] 备份频率与保留策略怎么定：按可容忍 RPO 定；本环境 7 MB/2.76 秒可高频执行；快照不宜长期保留（阻止空间回收）
- [x] 迁移到新集群的步骤与回滚方案：Prometheus 存活用 `remote-read`，停机窗口用 `prometheus`，VM 间用 `vm-native`；迁移幂等，中断可重跑；跨租户靠 URL 路径指定（无 account-id 参数），实测 240 序列 / 30 ms
- [x] 删除后空间何时回收：不会自动回收（等 120 秒无效），需 `POST /internal/force_merge`（仅存储层有此端点），触发后 1 秒内完成，释放 small 分区
- [x] 快照保留多久：不宜长期保留。快照自身仅占 68 KB，但阻止 1,128 KB 被回收（16 倍）；删快照可立即释放，代价完全可逆
- [x] 写入成功如何验证：必须用 `/api/v1/export`。返 204 不代表成功——JSON 喂给行协议端点 `/import/prometheus` 会静默全丢
