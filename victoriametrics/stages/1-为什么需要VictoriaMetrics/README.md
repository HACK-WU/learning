# 阶段 1：为什么需要 VictoriaMetrics

> 故事章节：**撞上天花板的那天**
> 返回：[课程目录](../../02-课程目录.md) ｜ [学习路径总览](../../01-学习路径总览.md)

## 阶段目标

- **目标**：说清 Prometheus 单机的天花板在哪，以及 VictoriaMetrics 用什么方式绕过去；在本机跑通第一个 VictoriaMetrics
- **学习重点**：五个天花板 / VM 的诞生与定位 / 生态位对照 / 单节点部署 / 写入落盘的可见性机制
- **必须掌握**：
  - 能独立启动单节点 VictoriaMetrics，完成写入与查询
  - 能解释「写入返回 204 却查不到数据」的完整原因（这是本阶段最有价值的一课）
  - 能说清 Prometheus 单机的五个天花板分别是什么，以及 VM 各自的应对方式

## 为什么从「天花板」讲起

你已经有 Prometheus / PromQL 基础，也有 InfluxDB 基础。所以这门课不打算从「什么是时序数据库」讲起——
那是对你时间的浪费。

真正值得先想清楚的问题是：**Prometheus 明明跑得好好的，为什么会需要另一个东西？**

这个问题答得越具体，后面每一个设计决策（为什么要 TSID、为什么要拆三件套、为什么要有 vmagent）
就越不需要死记——它们都是对这五个天花板的逐个回应。

## 关键伏笔

课 2 你会亲手撞上一个现象：**写入接口返回 204（成功），但立刻查询却查不到数据**。

这个现象背后藏着 VictoriaMetrics 的两个核心设计（内存缓冲 + 查询缓存），
但完整解释要等到课 3 讲查询语义时才揭晓。课 2 会先给你**三招能立刻执行的解法**，
让你不卡住，同时把这个悬念留着——带着问题学机制，比先学机制再遇问题记得牢得多。
