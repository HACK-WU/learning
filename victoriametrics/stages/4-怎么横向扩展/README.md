## 阶段核心结论（随课程推进更新）

### 课 10 已验证

- **租户 ID 边界**：`2^32-1` 可用（204），`2^32` 报 400；**空 ID 返 204 静默进 tenant 0**（危险）
- **projectID 平级**：`7` = `7:0`（20 条），`7:9` 独立（10 条）
- **租户数据分散所有节点**：tenant 66 的 100 条，两节点各 100 → 无法固定租户到特定节点
- **vmauth 认证**：无凭证/错密码 **401**，正确凭证 **200**
- **租户绑定**：backend 只见 `['100']`、frontend 只见 `['200']`；越权返 **400 `missing route`**
- **⚠️ 路径拼接**：`url_prefix + 原始路径`，须补 `prometheus`/`influx` 协议段（连踩两次 400）
- **⚠️ 数据隔离✅ 资源隔离❌**：大租户写入后他人查询 **0.0018s → 0.0132s（7.4 倍）**，全局 tsid 缓存 **2932 → 10932**
- **⚠️ 限流只卡并发**：8ms 查询 30/60 并发**零 429**；0.8s 查询 40 并发 → **429×36**
- **限流按用户隔离**：backend 429×26 时 frontend 全 **200**
- **高可用**：停任一 vmselect 后端查询不中断；`/-/reload` 热重载立即生效；vmauth 多实例无状态
- **单节点 vs 集群路径不兼容**：`/write` vs `/insert/<T>/influx/write`
- **附带**：`-search.maxPointsPerTimeseries` 默认 30000（超限返 422）
- **⚠️ 负载均衡结果抖动**：后端 dedup 配置不一致时，同一查询连查 12 次得 5/10 交替 → 必须统一所有 vmselect 的 dedup

### 课 9 已验证

- **副本必配 dedup**：RF=2 后无 dedup 聚合 = **600**（翻倍），配 dedup = **300**（正确）
- **dedup 间隔 = 采集间隔**：12 个样本（间隔 5s）用 `dedup=30s` 只剩 **3 个**；`dedup=5s` 恢复 12 个
- **高可用成立**：停一节点，有副本+dedup 结果保持 **300 不变**（对比课 8 无副本的 **1000→509**）
- **⚠️ 副本缺口不自动补齐**：故障期写 100 条，节点恢复后仍是 **100 / 0**
- **⚠️ 副本失败只留日志**：HTTP 仍返 204；指标 `vm_rpc_rows_incompletely_replicated_total` 5 次失败后**仍为 0**，可靠性存疑
- **⚠️ RF>1 禁用慢节点重路由**：启动日志明确警告，慢节点会拖慢整体写入
- **最小推荐配置**：**3 个 vmstorage 配 RF=2**（2 节点配 RF=2 故障期会退化成单副本）

### 课 8 已验证

- **三件套分工**：vminsert（写入代理，14.8MB）/ vmselect（查询聚合，33.2MB）/ vmstorage（哑存储，84.5MB）
- **shared-nothing**：vmstorage 节点**互不相识、互不通信**，既不提供对外写入也不提供查询（实测均 HTTP 400）
- **故障隔离**：停掉 vmselect 后写入仍 HTTP 204（课 8 实测）
- **一致性哈希**：按 `metric name + 所有标签` 哈希，同一条序列 20 个样本**全部落到同一节点**
- **分片均匀度**：1000 条序列分到 2 节点 = **509 / 491**（接近理想 50/50）
- **⚠️ 旧数据不迁移**：扩容后 229 条旧数据全留在原节点，`-storageNode` 只在启动时读取
- **⚠️ 静默降级**：停掉一个 vmstorage，count 从 1000 → 509，**不报错**
- **多租户**：tenant 0/42/100 各 5 样本互不干扰；`查 7` 看不到 `7:9` 的数据

## 阶段决策清单：什么时候上集群

**继续用单节点**
```
✓ 活跃序列 < 1000 万
✓ 写入速率 < 100 万样本/秒
✓ 没有多租户需求
✓ 单机硬件还能加
```

**该考虑集群**
```
⚠ 活跃序列接近或超过 1000 万
⚠ 写入速率持续 > 100 万样本/秒
⚠ 需要多团队/多客户数据隔离
⚠ 查询压力大且波动明显（可只扩 vmselect）
```

> 官方原话：*"It is recommended using single-node version instead of cluster version
> for ingestion rates lower than a million of data points per second."*
> 以及：*"Single-node version is easier to configure and operate...
> so think twice before sticking to cluster version."*
