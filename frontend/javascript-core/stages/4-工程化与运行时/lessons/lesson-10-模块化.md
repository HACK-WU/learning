# 第 10 课：模块化

> 所属阶段：阶段 4《工程化与运行时》｜ 水平：入门 ｜ 本课知识点：CommonJS 与 ESM、import·export 全语法、循环依赖与动态导入
> 故事情节：主角的项目从 1 个文件长到 30 个文件，`require` 和 `import` 混用炸了——这一课把"代码怎么组织"这件事一次讲透
> 🎯 **本课承载「决策参考」目标**：CommonJS vs ESM 的选型对比 + 翻转条件
> ⏳ **状态：骨架（正文待 Phase 2 填充）**

## 🎯 本课目标

- 说清 ESM 的"**实时绑定**"与 CommonJS 的"**值拷贝**"差异及后果，解释为什么 tree-shaking 只在 ESM 上成立
- 用命名导出 / 默认导出 / 转发写出多模块项目，解释导入绑定为什么是**只读**的
- 解释 ESM 循环依赖为何不报错却拿到 `undefined`，给出破环手段，用 `import()` 做代码分割

## 📌 知识点清单（含关键点）

### 知识点 1：CommonJS 与 ESM

- 关键点：语法差异 / 值的拷贝（`require`）vs 实时绑定（`import`） / 运行时加载 vs 编译时静态分析 / tree-shaking 的前提 / 在 Node 中如何启用 ESM（`package.json` 的 `type` 字段与 `.mjs`/`.cjs`）

### 知识点 2：import·export 全语法

- 关键点：命名导出与默认导出（以及混用的坑）/ `export ... from` 转发 / `import` 的提升 / 只读绑定与"导入变量是常量"的直觉 / 模块是单例（多次 import 只执行一次）

### 知识点 3：循环依赖与动态导入

- 关键点：ESM 循环依赖为何不报错但拿到 `undefined`（TDZ 回扣课 1）/ CommonJS 的处理差异（拿到不完整的 `exports`）/ 破环手段（提取第三模块、改为函数内延迟引用）/ 动态 `import()` 与代码分割
