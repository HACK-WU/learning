# TypeScript 课程手册

> 这是 **5 阶段 / 15 课 / 49 知识点**学完后的**汇总速查手册**（Phase 4 产出）。
>
> **怎么用**：复习时快速回顾脉络（第一、二节）→ 遇到岔路口查决策清单（第三节）→ 写代码查工具类型 / 报错码（第六、七节）→ 想不起来细节就点链接回课。
>
> 标记约定：**「实测」= 有本机实测数据支撑的结论**（区别于经验教条）；**「⏳」= 经验性建议**，请按自己项目情况验证。
> 完整论证、示例代码、实测产物都在各课原文里，本手册只给结论和入口。

## 一、全书脉络（30 秒回顾）

### 故事主线

**一个「类型」在团队里的身份蜕变：从注释 → 到契约 → 到可编程的约束 → 到被治理的对象。**

你接手一个跑了很久的 JS 项目，没人答得上「`formatUser(data)` 要传什么」。JS 把类型信息全丢在了人的脑子里——TS 的答案就是把这些信息**写进代码，让编译器替每个人记住**。

### 5 阶段速览

| 阶段 | 身份 | 一句话 | 课 |
|------|------|--------|-----|
| 1 类型思维启蒙 | 注释 | 类型是什么、不是什么——擦除式超集，编译后消失 | 1-3 |
| 2 收窄与控制流 | 活约束 | 写个 `if`，类型自己变窄，契约开始生效 | 4-7 |
| 3 泛型与类型编程 | 可编程 | 类型能被计算、推导、组合，一份代码适配无数形状 | 8-9 |
| 4 工程化与类型声明 | 团队契约 | 契约走出单文件，在工程与 CI 里被强制执行（按 TS 7） | 10-12 |
| 5 深入与架构 | 被治理的对象 | 知道它能挡住什么、代价是什么、何时该收手 | 13-15 |

### 贯穿全书的三句话

1. **类型是契约，不是装饰。** 它挡住的不是「写错字」，而是「你和别人对代码的理解不一致」。
2. **类型系统不是证明系统。** 它挡常见错误，不保证消灭所有错误——`as` 是承诺不是检查，外部数据必须运行时验证。
3. **会写 ≠ 该写。** 类型体操、严格度、乃至 TS 本身，都是成本与收益的权衡，不是「越猛越好」。

## 三、决策清单（6 处岔路口）

> 全书刻意设了 6 个「停下来想一想」的决策点。下面是每处的最简结论，完整论证回课。

### 1. 注解 vs 推导（课 2）

**默认推导，只在四处显式标注**：公开 API 边界（函数签名）、无法推导处（裸参数）、要锁定类型防拓宽处、复杂字面量。

> 推导能防漂移、少样板；到处写注解反而制造「类型是负担」的错觉。

### 2. enum vs 字面量联合（课 4）

**默认字面量联合**。需要运行时遍历时用 `as const` 数组 + `typeof ARR[number]`（一份取值、两种用途、零产物）。

| 场景 | 选 |
|------|-----|
| 业务状态 / 配置 / 字符串取值 | 字面量联合 |
| 要遍历取值 + 要类型 | `as const` 数组 + 索引访问 |
| 要反向映射（日志里 `0` 显示成 `"Pending"`） | `enum` |
| 跨模块共享的枚举 | **别用 `const enum`**（`isolatedModules` 下受限） |

> `enum` = 「类型 + 运行时对象」二合一，是 TS 擦除原则唯一的冲突点。

### 3. any vs unknown（课 6）

**入口一律 `unknown`，边界处收窄；`any` 只当中转站且立即收窄。**

- `any`：放弃检查，**会传染**，沿数据流扩散直到某处崩溃。
- `unknown`：安全顶层类型，**逼你先验再用**。
- 信任边界：`JSON.parse` / 网络响应 / 用户输入 → `unknown` → 运行时校验 → 精确类型。

### 4. TS 7 配置取舍（课 10）

**新项目 `strict: true` 全开（TS 7 默认即如此），可再加 `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`（默认关的官方推荐项）。**

- 老项目：按课 10 六步渐进收紧，迁移期可先 `strict: false`。
- 对外库：公开 API 严格，内部实现可适度放松（但 `.d.ts` 会暴露对外签名用到的内部类型）。

### 5. 类型体操值不值（课 13 · 七步放弃标准）

**按顺序问自己，任何一个「否」就停手：**

```
① 手写类型能不能解决？    能 → 手写
② 能不能用代码生成解决？  能 → 生成（来自外部事实时几乎总是生成更优）
③ 是不是「调用点极多 + 手写会漏」？  不是 → 别写
④ 能写成尾递归吗？        不能 → 重新设计（否则约 50 层就爆）
⑤ 算不出来时有兜底吗？    没有 → 补上再写（不能退化成 never 还浑然不觉）
⑥ 配了类型测试吗？        没有 → 补上再写
⑦ 团队里至少两个人看得懂吗？ 不是 → 别写，或先教会一个人
```

> 前两步（手写 / 生成）就能拦下大多数冲动。

### 6. 该不该上 TS（课 15 · 判断条件清单）

> 📌 本清单口径与 Phase 5 的「场景解法库」保持一致。

**先看「算不算得上」**：

| 信号 | 倾向 |
|------|------|
| 多人长期维护（≥2 人，≥1 年） | ✅ 上 |
| 对外提供公共 API / SDK | ✅ 上（类型即文档） |
| 项目足够大（几千行以上，跨模块） | ✅ 上 |
| 一次性脚本 / 原型 / 演示 / 竞赛 | ❌ 不上 |
| 生命周期 < 几周 | ❌ 不上 |
| 单人维护且几百行以内 | ➖ 可不上 |
| 团队没人愿意维护类型 | ⚠️ 先小范围试点 |
| 构建/工具链不支持 | ➖ 用 JSDoc 路线 |
| 数据来源全外部、形状不稳定 | ✅ 上，但**必须配运行时校验** |

**再看「上多严」**：新项目 `strict: true` 全开；老项目六步渐进；对外库公开 API 严格；脚本工具 `strict: true` 即可不必上高阶开关。

**三条替代方案**：JSDoc + `checkJs`（不改构建拿收益）、运行时校验（真正拦住外部数据）、测试 + 评审（拦逻辑错）。**三者与 TS 互补，最稳组合是「类型 + 运行时校验 + 测试」。**

## 四、关键实测结论（本书的硬事实）

> 这些是本课最值钱的东西——不是转述文档，是**本机实测**得来的。数值会随版本 / 机器变，**结论的结构稳定**。

| # | 结论 | 实测数据 | 出处 |
|---|------|---------|------|
| 1 | 递归深度有上限 | 非尾递归约 50 层（TS2589）；尾递归约 1000 层；结构比较约 100 层（TS2321） | 课 13 / 实战 |
| 2 | 类型算不出会**静默** | 退化成 `never` → 万能赋值 → **什么都不报**（比报错难读更危险） | 课 13 |
| 3 | 类型体操的编译代价 | 复杂体操约 2.9x 更慢；**简单体操测不出差异**（实战 0.87x） | 课 13 / 实战 |
| 4 | TS 7 报错收敛度高 | 8 种形状只 1-4 行；变长主因是「源类型无名」（405 vs 89 字符，4.6 倍） | 课 14 |
| 5 | 语法错误 = 后面全停；类型错误照样 emit | Parser 造不出 AST 时 Binder/Checker 不执行；`noEmitOnError` 默认 `false` | 课 14 |
| 6 | **类型管不住外部数据** | 只有断言 → 运行时 `TypeError`；加守卫 → 可控业务错误 | 课 6/15/实战 |
| 7 | 共享类型文件放大改动爆炸半径 | 集中放置的净重建是分层的 3.7x~5.7x | 课 15 |
| 8 | 工具兼容性判据 | **只看它要不要 `import "typescript"`**：要 → TS 7 下不可用；不要 → 与 TS 版本无关 | 课 12 |
| 9 | JSDoc vs TS 收益边界 | 简单参数错误下报同一条 TS2345；复杂泛型下 TS 明显更强 | 课 15 |
| 10 | 迁移顺序 | 从叶子开始迁第 2 步就报错；跳过叶子先迁入口 0 错（类型信息自下而上流动） | 课 15 |

## 五、TS 7 速查

> 版本事实基线核查于 2026-09-03/04，来源官方博客「Announcing TypeScript 7.0」+ 本机实测。

### 新默认值

`strict: true`、`module: esnext`、`noUncheckedSideEffectImports: true`、`libReplacement: false`、`stableTypeOrdering: true`（不可关）、`rootDir: ./`、`types: []`。

### 变硬错误（照 5.x 老教程会撞墙）

`target: es5`、`downlevelIteration`、`moduleResolution: node/node10/classic`、`module: amd/umd/systemjs/none`、`baseUrl`、`esModuleInterop/allowSyntheticDefaultImports: false`、`alwaysStrict: false`。

### 新 CLI 参数

`--checkers N`（类型检查并行度，默认 4）、`--builders N`、`--singleThreaded`。

### 生态限制与工具兼容

- Vue / MDX / Astro / Svelte / Angular 模板等**依赖 TS API 的工作流**，TS 7 下暂只能用 TS 6。
- typescript-eslint 8.69 的 peer 是 `typescript: ">=4.8.4 <6.1.0"`，TS 7 在范围外 → 官方解法是 npm 别名并存：`"typescript" → @typescript/typescript6`（给工具）、`"@typescript/native" → typescript@7`（给你）。
- `tsc --noCheck` 可用但 `--help` 里查不到（实测）。

## 六、内置工具类型速查

> 都能手写（课 9 逐一手写过），记住「干什么用」即可。

| 工具类型 | 作用 | 一句话 |
|---------|------|--------|
| `Partial<T>` | 全变可选 | `{ [K in keyof T]?: T[K] }` |
| `Required<T>` | 全变必填 | `-?` 去掉可选 |
| `Readonly<T>` | 全变只读 | `+readonly` |
| `Pick<T, K>` | 挑字段 | 保留 K |

| `Record<K, T>` | 造映射 | 键 K 值 T |

| `Extract<U, E>` | 联合提取 | `U extends E ? U : never` |
| `NonNullable<T>` | 去 null/undefined | `T extends null \| undefined ? never : T` |
| `ReturnType<F>` | 取函数返回 | `infer R` |
| `Parameters<F>` | 取函数参数 | `infer P`（元组） |
| `Awaited<T>` | 拆 Promise | 递归 `infer` |

## 七、常见报错码速查

> 本课程实测出现过的错误码，按「看一眼就知道往哪查」组织。

| 错误码 | 含义 | 常见诱因 / 排查 |
|--------|------|----------------|
| `TS2589` | 类型实例化/递归深度超限 | 非尾递归层数太深；改尾递归或降低嵌套 |
| `TS2321` | 类型比较栈溢出 | 两个深层类型互相比较；给类型起名字可缓解 |
| `TS2322` | 类型不匹配赋值 | enum 名义性 / 联合收窄问题 |
| `TS2345` | 参数类型不匹配 | 最常出现；看报错里的「源 vs 目标」 |
| `TS2353` | 多余属性检查 | 直接字面量赋值多了字段；用变量中转会消失 |
| `TS2339` | 属性不存在 | 联合类型上访问了非交集属性，先收窄 |
| `TS2741` | 缺少属性 | 缺必填字段；interface 加必填 = 破坏性变更 |
| `TS2687` | 同名全局声明冲突 | 你的全局 `interface` 与 `lib.dom` 撞名 |
| `TS2688` | 类型包名无法找到 | `--types ["x"]` 写法错误或包不存在 |
| `TS2834` / `TS2835` | 缺扩展名 import | 2835 有候选（提示 Did you mean），2834 无候选 |
| `TS5112` | 有 tsconfig 时不能传文件路径 | 加 `--ignoreConfig` |
| `TS2591` / `TS2584` | 找不到全局/API | `types: []` 或 `lib` 缺对应环境（`console` 在 `lib.dom`） |
| `TS2430` | 接口声明冲突 | `extends` 与交叉类型的行为差异 |
| `TS2451` | 变量与全局冲突 | 顶层 `let status` 撞 DOM 全局，改名 |
| `TS5108` / `TS5102` / `TS5090` | tsconfig 硬错误 | 用了 TS 7 已废弃的选项（如 `baseUrl`） |
| `TS1005` | 语法错误 | 语法错误会让后面全停（Binder/Checker 不执行） |
