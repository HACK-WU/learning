## 二 · 运行前提（本机环境）

### ⚠️ 三条必读

**1. Windows 无 Python 运行时 —— 所有 Python 脚本必须走 WSL**

```bash
wsl -d Ubuntu -- /root/otel-course/lab03/.venv/bin/python /mnt/d/projects/learning/.probe/<脚本>
```

**2. PowerShell 会破坏内联 bash 的引号与重定向**

多行 bash、含 `>` / `|` / `head` 的命令，一律写成 `.sh` 文件再执行，或用 `wsl -d Ubuntu -- bash -c '<命令>'`。
课 9 开发中踩过三次：内联 `grep -o "..."` 被引号破坏、`head` 管道失效、`> /dev/null` 被 PowerShell 抢走。

**3. 管道截断用 PowerShell 的 `Select-Object -First N`，不要用 WSL 内的 `head`**

```powershell
wsl -d Ubuntu -- <命令> | Select-Object -First 20
```

## B · 分档实测属性名

**文件**：`l9_b_semconv_optin.py` + `l9_b_run.sh` ｜ **依赖**：`flask`、`opentelemetry-instrumentation-flask`

### 机制

`OTEL_SEMCONV_STABILITY_OPT_IN` 是**分域独立**开关：

| 取值 | 效果 |
|---|---|
| 不设 | 旧名（默认，向后兼容） |
| `http` | 只产出新名 |
| `http/dup` | 新旧名都产出（**迁移期推荐**：先改看板再切） |
| `database` | 只影响 DB 域 —— 对 HTTP 属性**毫无影响** |
| `http/dup,database/dup` | 逗号分隔可同时开多域 |

### 运行

```bash
# 全 5 档（推荐）
wsl -d Ubuntu -- bash /mnt/d/projects/learning/.probe/l9_b_run.sh

# 指定档位
wsl -d Ubuntu -- bash /mnt/d/projects/learning/.probe/l9_b_run.sh http http/dup

# 只看属性名横向对比
wsl -d Ubuntu -- bash /mnt/d/projects/learning/.probe/l9_b_run.sh 2>&1 \
  | grep '\[KEY\]' | sort | uniq -c | sort -rn
```

### 输出（本机实测）

| 档位 | 属性数 | 说明 |
|---|---|---|
| `default` | **12** | 全旧名 |
| `http` | **10** | 全新名 |
| `http/dup` | **22** | 旧 12 + 新 10 并存 |
| `database` | **12** | 与 default 完全相同 → 证明分域独立 |
| `database/dup` | **12** | 同上 |

### ⚠️ 关键陷阱：必须子进程隔离

**不要**在单进程内循环切换档位。`trace.set_tracer_provider()` 全局只允许设置一次，第二次起会**静默失败**：
只打印一行 `Overriding of current TracerProvider is not allowed`，不抛异常，但后续档位抓到 **0 个 span** ——
得到"某档位不产出属性"的假结论。

实测证据：

```
default      n=12  new=False  old=True
http         n=0   new=False  old=False   ← 静默假结果
http/dup     n=0   new=False  old=False   ← 静默假结果
```

这就是 `l9_b_run.sh` 存在的理由：每档一个独立进程。

### 复用场景

升级 OTel SDK 后，跑一遍确认你的看板查询该改成哪些属性名；或排查"新文档说的属性我这儿查不到"。

### 换成别的框架

改脚本里 3 处：import 对应的 `instrumentation-*`、`instrument_app()` 调用、路由定义。其余（子进程隔离、InMemorySpanExporter 抓属性）可完全复用。

## C · Cardinality 爆炸实测

**文件**：`l9_c_cardinality.py` ｜ **依赖**：`opentelemetry-sdk` ｜ **参数**：见下

### 核心判据（可直接记）

> **放大倍数 = 新加维度的基数。**
> 序列数 = 各维度基数的**乘积**，不是相加。
> 加一个 `user.id`（1 万用户）= 序列数 **×10000**，不是 +10000。

### 运行

```bash
PY=/root/otel-course/lab03/.venv/bin/python

# 默认（5 路由 × 3 状态码 vs +10000 用户）
wsl -d Ubuntu -- $PY /mnt/d/projects/learning/.probe/l9_c_cardinality.py

# 自定义维度基数
wsl -d Ubuntu -- $PY /mnt/d/projects/learning/.probe/l9_c_cardinality.py --routes 20 --users 50000

# 追加推演维度（不实测，只推演）
wsl -d Ubuntu -- $PY /mnt/d/projects/learning/.probe/l9_c_cardinality.py \
  --extra deployment.environment=4 k8s.pod.name=200

# 改成本模型
wsl -d Ubuntu -- $PY /mnt/d/projects/learning/.probe/l9_c_cardinality.py \
  --interval 30 --bytes 1.5

# 跳过实测只推演（快，基数大时用）
wsl -d Ubuntu -- $PY /mnt/d/projects/learning/.probe/l9_c_cardinality.py --skip-real
```

### 参数表

| 参数 | 默认 | 说明 |
|---|---|---|
| `--routes` | 5 | 路由维度基数 |
| `--status` | 3 | 状态码维度基数 |
| `--users` | 10000 | 高基数维度基数 |
| `--extra` | 无 | 追加推演维度，格式 `name=cardinality` |
| `--interval` | 15 | 采样间隔（秒） |
| `--bytes` | 2.0 | 每样本压缩后字节 |
| `--skip-real` | 关 | 跳过实测，只做推演 |

### 输出（默认参数，本机实测）

```
[低基数]  理论组合=15       实测时间序列=15
[高基数]  理论组合=150,000  实测时间序列=150,000
  放大倍数 = 10,000x   ← 恒等于新加维度的基数 10,000

=== 基数乘法推演 ===
  + http.route                 x5        =>              5
  + http.response.status_code  x3        =>             15
  + user.id                    x10000    =>        150,000
  + deployment.environment     x4        =>        600,000
  + k8s.pod.name               x200      =>    120,000,000  ← 灾难起点

=== 存储成本估算（每 15s 一采样点，每样本 2.0 字节）===
  低基数   序列=        15    0.2 MiB/天     0.1 GiB/年
  高基数   序列=   150,000    1,647.9 MiB/天   587.4 GiB/年
```

### ⚠️ 成本数字的边界

**数量级推演，不是精确报价。** 真实占用取决于后端压缩算法、保留策略、索引方式。
用它**比较两个方案谁贵多少倍**是可靠的；用它**预测账单绝对值**不可靠。

### 复用场景

改看板要加维度、有人提议把 `user.id` / `request.id` 塞进指标标签时，先跑一遍量化代价。

## D · 弃用属性扫描器

**文件**：`l9_d_migrate.py` ｜ **依赖**：**仅标准库**（无需 OTel 运行时）｜ **两种模式**

### 运行

```bash
PY=/root/otel-course/lab03/.venv/bin/python

# 模式 1：扫真实代码目录
wsl -d Ubuntu -- $PY /mnt/d/projects/learning/.probe/l9_d_migrate.py scan <目录>

# 限定扩展名 + 导出 JSON
wsl -d Ubuntu -- $PY /mnt/d/projects/learning/.probe/l9_d_migrate.py scan <目录> \
  --ext .py .js --json report.json

# 排除样板文件
wsl -d Ubuntu -- $PY /mnt/d/projects/learning/.probe/l9_d_migrate.py scan <目录> \
  --exclude legacy_attrs.py

# 模式 2：内置演示（讲清 1:1 / 拆分 / 带条件三种迁移）
wsl -d Ubuntu -- $PY /mnt/d/projects/learning/.probe/l9_d_migrate.py demo
```

### 参数表

| 参数 | 说明 |
|---|---|
| `scan <目录>` | 扫描真实代码 |
| `demo` | 跑内置样例（默认，不传参时） |
| `--ext` | 限定扩展名，默认 13 种（含 `.md`/`.yaml`） |
| `--exclude` | 额外排除的文件名 |
| `--no-self-exclude` | 不排除本脚本（默认排除） |
| `--json` | 导出 JSON 报告 |

### 输出解读

扫描结果按**迁移类型**分类，直接对应不同的处理方式：

| 类型 | 标记 | 处理方式 |
|---|---|---|
| 1:1 重命名 | `rename` | schema processor 可自动处理 |
| 一对多拆分 | `split` | **必须** transform processor |
| 带条件迁移 | `conditional` | 须人工判断语义 |
| 已移除无替代 | `removed` | 删掉或换自定义属性 |

内置演示的关键结论：

```
⚠️ http.target -> url.path + url.query 无法用 rename 表达：
    http.target = '/users/42?page=1'
    -> url.path  = '/users/42'
    -> url.query = 'page=1'
结论：1:1 用 schema processor；拆分/带条件一律用 transform processor。
```

### 🔧 本次增强（相对原版）

原版只能扫**写死在文件里的示例字符串**，扫不了真实项目。改造后：

- 支持 `scan <目录>` 扫真实代码，递归遍历、自动跳过 `node_modules` / `.venv` / `.git` 等
- 按迁移类型分类并统计工作量（`rename` / `split` / `conditional` / `removed` 各多少个）
- 输出 `文件:行号` 定位 + JSON 导出
- **自排除**：映射表本身含有全部旧属性名，默认排除本脚本，否则自扫描会全量误报

实测（`--ext .py` 扫本目录）：扫到 51 个候选属性名，弃用 1 个。

### ⚠️ 映射表是快照

`DEPRECATED` 表逐条核对于 2026-09-03（官方 main 分支，基线 v1.43.0）。
**升级 OTel SDK 后请用 `l9_scan_dep.py` 重新核对**，方法见下节。

## 辅助 · 官方源码抽取弃用清单

### 输出（本机）

```
官方 model/ 下共检出 348 条带 deprecated 标记的条目
  metric  97   gen_ai 58   db 30   span 14   rpc 14   net 13   http 13 ...
```

### ⚠️ 准确率局限（重要）

本脚本用正则从 note 文本里**猜**替代名（`Replaced by` / `use X instead` / `Split into`），
**准确率不是 100%，且会漏检**。

实测对比：脚本检出 HTTP 域 **13 条**，而人工核对官方 YAML 得到 **14 条** ——
漏掉的是 `http.target`（官方写的是 `reason: obsoleted`，不是 `Replaced by` 句式）。

**权威做法**：直接读官方 YAML 原文，尤其查 `renamed_to` 字段：

```bash
wsl -d Ubuntu -- cat /root/semconv/model/http/deprecated/registry-deprecated.yaml
wsl -d Ubuntu -- cat /root/semconv/model/db/deprecated/registry-deprecated.yaml
```

定位：适合"快速看哪些属性被弃用了"；**不适合**"直接照抄替代名"。
课 9 的正式映射表是人工逐条核对得到的，不是本脚本自动生成的。

## 三 · 常见组合流程

**场景 1：升级 OTel SDK 后做属性迁移**

```bash
# 1. 确认新旧基线
l9_a_semconv_ver.py
# 2. 扫代码里有多少处用了弃用属性
l9_d_migrate.py scan ./src --ext .py --json before.json
# 3. 按类型分批处理（rename 批量改，split/conditional 人工改）
# 4. 切档验证：先 http/dup 新旧并存 → 改看板 → 再切 http
l9_b_run.sh
# 5. 改完复扫
l9_d_migrate.py scan ./src --ext .py --json after.json
```

**场景 2：评估要不要给指标加维度**

```bash
# 先量化代价，再决定
l9_c_cardinality.py --extra <你的维度>=<基数>
```

**场景 3：排查"属性查不到"**

```bash
# 三步定位：是不是版本问题 → 是不是档位问题 → 是不是属性名被弃用了
l9_a_semconv_ver.py          # 本机 schema 上限够不够
l9_b_run.sh                  # 当前档位实际产出哪些属性名
l9_d_migrate.py scan ./src   # 代码里是不是还在用旧名
```
