## ⚠️ 本课新发现的环境陷阱

### 陷阱 1：PowerShell 会抢管道（课 10 已记录，本课再次踩到）

**现象**：`wsl.exe ... | tail -40` 在 PowerShell 下报 `tail is not recognized`。

**原因**：管道由 PowerShell 解释，它找不到 `tail`。

**规避**：**把所有管道和重定向放进 `.sh` 脚本内部**，脚本内 `exec > /path/to.log 2>&1` 输出，再用 `read_file` 读日志。

### 陷阱 2：Windows 无 Python，须走 WSL

**现象**：`python D:/...py` 报 `Python was not found`，提示装 Microsoft Store 版本。

**规避**：一律用 `wsl.exe -d Ubuntu -- bash /mnt/d/projects/learning/.probe/xxx.sh`，脚本内用 `python3`。

**注意**：WSL 内路径是 `/mnt/d/...`，不是 `D:/...`。

### 陷阱 3：孤儿 docker-proxy 占住端口

**现象**：容器已 `docker rm`，但端口仍 `Bind for 0.0.0.0:34317 failed: port is already allocated`；`ss -ltnp` 显示 `docker-proxy` 仍在 LISTEN。

**规避**：
- 优先**不映射宿主端口**，改用 `docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}'` 拿容器 IP 直连
- 需要映射时，先用 `ss -ltnp | grep <port>` 确认端口真空闲

### 陷阱 4：`bpf()` 返回 EINVAL 不代表不支持

**现象**：空 attr 调 `bpf(BPF_MAP_CREATE)` 返回 `-1, errno=22 (EINVAL)`。

**判定**：EINVAL 是**参数错误**，不是权限拒绝（EPERM=1 / EACCES=13）。**能返回 EINVAL 恰恰说明系统调用可达。** 真正的能力验证要用 bcc 编译并挂载。

### 陷阱 5：bcc 常量需显式导入

**现象**：`NameError: PerfType_SOFTWARE` / `AttributeError: type object 'BPF' has no attribute 'PerfType_SOFTWARE'`。

**正确写法**：
```python
from bcc import BPF, PerfType, PerfSWConfig
b.attach_perf_event(ev_type=PerfType.SOFTWARE,
                    ev_config=PerfSWConfig.CPU_CLOCK,
                    fn_name="do_sample", sample_freq=99, cpu=-1)
```

### 陷阱 6：`bpf_perf_event_data` 是前向声明

**现象**：`error: incomplete definition of type 'struct bpf_perf_event_data'`。

**规避**：函数签名用 `int do_sample(struct pt_regs *ctx)`，不要用 `struct bpf_perf_event_data *ctx`。

### 陷阱 7：Go 依赖会触发工具链自动升级

**现象**：`go mod tidy` 时输出 `requires go >= 1.25.0; switching to go1.26.8`，并自动下载。

**说明**：这是正常行为，不是错误。首次会较慢，后续有缓存。

### 陷阱 8：pprof 库字段名是 `Function` 不是 `Functions`

**现象**：`p1.Functions undefined (type *profile.Profile has no field or method Functions)`。

**正确**：`len(p1.Function)`。
