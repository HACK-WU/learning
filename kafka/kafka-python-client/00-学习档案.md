## 定位与边界

现有 [Kafka 主教程](../02-课程目录.md) 的 [课 9：代码开发实战](../stages/4-实战与架构落地/lessons/lesson-09-代码开发实战.md) 已讲三大客户端选型、producer/consumer 最小实现、事务与 `read_committed`；[应用实战/09](../应用实战/09-代码开发实战.md) 已讲错误处理、优雅关闭与坏消息兜底。

**本子教程不复制上述内容**，而是把"能跑通的脚本"推进到"敢上生产的长驻程序"，主线是**客户端侧工程**：确认语义、分区与序列化、事务、吞吐调优、位移与再均衡、并发模型、asyncio 集成、可观测与测试。

- 先修建议：[主教程课 9](../stages/4-实战与架构落地/lessons/lesson-09-代码开发实战.md)、[主教程课 8：交付语义与幂等](../应用实战/08-交付语义与幂等.md)、[主教程课 15：监控与可观测](../stages/6-运维与可观测/lessons/lesson-15-监控与可观测.md)。
- 本线重点：三库分工、协议与源码理解、吞吐工程、事务 EOS、Schema Registry、并发与异步、客户端可观测。
- 暂不承诺：Kafka Streams（无 Python 官方实现）、ksqlDB、云厂商托管控制台、某家公司内部 SDK。

## 分工双主线（本子教程核心设计）

> 用户 2026-09-20 确认采用"分工双主线"。判据：**这层的教学目的，哪个库讲得最清楚**。不是把两个库各讲一遍。

| 层 | 用哪个库 | 为什么是它（不可替代的价值） | 承担课程 |
|---|---|---|---|
| 理解层 | `kafka-python` | 纯 Python，**唯一能读源码**、把协议细节摊开给学员看的库 | 课 4、5、6 |
| 生产层 | `confluent-kafka` | librdkafka C 内核；**高吞吐、事务 EOS、Schema Registry** 三样是独占能力 | 课 7、8、9、10 |
| 场景层 | `aiokafka` | 仅在"async 原生 + 不依赖 Schema Registry"条件下才是正解 | 课 11 |

分工同时保住了"源码解析"这个差异化价值——confluent 是 C 扩展读不了源码，由 kafka-python 独占承担。

## 故事主线

- **主角**：一个 Python 服务。
- **冲突**：它从"能跑通的脚本"（发 10 条收 10 条一切正常）出发，要变成"敢上生产的长驻程序"——而挡在中间的是确认语义、吞吐天花板、再均衡、并发模型与可观测。
- **收束**：学习者能按场景在三个库之间做有依据的选型，并能为"为什么这么配"给出实测或源码级的理由，而不是抄默认配置。

## 主教程三处 API 缺陷（2026-09-21 实测确证，逐条跑过）

修复 06 时实测发现，原代码的缺陷比"方法名写错"**严重得多**——照抄会在三个不同位置分别崩：

1. **`commitSync()` 不存在**。提交方法实测只有 `commit` / `commit_async` / `committed`。
   ⚠️ 重要更正：`commitSync` 在 **kafka-python 3.0.11 与 kafka-python-ng 2.2.3 下实测均不存在**（两库 `hasattr` 皆为 `False`）。
   此前"是 kafka-python-ng 系写法"的说法**被实测证伪**——它是纯 Java 命名。09 的坑说明已同步更正。
2. **listener 必须继承 `ConsumerRebalanceListener`，回调是单参数** `on_partitions_revoked(partitions)`。
   原 `def on_revoke(consumer, partitions)` 是 Java 接口风格，传进去报
   `TypeError: listener must be a ConsumerRebalanceListener`。
   正确导入路径：`kafka.consumer.subscription_state`（**不在** `kafka.coordinator.consumer`）。
3. **回调里不能调 `commit()`**（最隐蔽）。同步 listener 运行在 IO 线程，阻塞式 `commit()` 抛
   `RuntimeError: Cannot block on net.run() from the IO thread itself` → 包装为
   `KafkaError: User rebalance callback throws an error`。
   **正解**：回调只打标记，回主循环再 `commit()`。

**终检**：修正后代码原样抽出，在真实 3 节点集群跑通——消费 12 条、2 批提交成功、
revoke 触发 3 次、换届补提交路径验证可用。验证用 topic 已清理，集群恢复原状（仅剩 `__consumer_offsets` / `acl-deny-demo` / `sec-ops-demo`）。
