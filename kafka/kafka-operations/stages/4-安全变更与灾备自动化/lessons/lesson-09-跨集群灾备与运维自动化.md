# 第 9 课：跨集群灾备与运维自动化

> 所属阶段：阶段 4《安全变更与灾备自动化》｜水平：入门｜状态：正文待 Phase 2 分批生成
> 故事情节：主机房真的不可用了——“我们有备份”必须变成“另一座集群能接班，而且我们知道少了什么”。

## 🎯 本课目标

- 从 RPO/RTO、数据方向、隔离和业务切换成本选择跨机房拓扑。
- 设计 MirrorMaker 2 的同步、切换、回切和数据一致性验证。
- 把 Admin/CLI 运维动作封装成幂等、可审计、支持 dry-run/verify 的 runbook。

## 知识点清单

### 知识点 1：RPO/RTO 与跨机房拓扑

- 关键点：本地集群 + 跨集群镜像与单集群跨机房的取舍
- 关键点：RPO、RTO、网络中断、数据积压和成本
- 关键点：客户端就近访问、故障域隔离和切换控制面

### 知识点 2：MirrorMaker 2、切换与回切演练

- 关键点：复制方向、Topic 映射、offset 迁移和重复/遗漏风险
- 关键点：切换前冻结、追平判据、流量切换和回切条件
- 关键点：演练记录、差异核对和恢复后的清理动作

### 知识点 3：Admin 自动化、runbook 与演练证据

- 关键点：幂等检查、dry-run、执行、verify、回滚和审计输出
- 关键点：CLI 封装、Admin API 和权限隔离的边界
- 关键点：用故障注入与定期演练验证“文档能不能救命”

## 本课在故事主线中的位置

这是整条运维故事的收束：集群不只要被守住，还要在最坏的场景里有另一套可接班的系统和一套有人真正演练过的动作。
