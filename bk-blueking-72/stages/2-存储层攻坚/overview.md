## 核心结论（先给答案）

1. **helm release 显示 `failed` 不等于部署失败** —— 本次 8 个 release 全 `failed`，但根因是 `--timeout 600s` 撞上镜像拉取 2 分钟/Pod，超时后 Pod 继续启动，最终 mongodb / mysql8 / rabbitmq / redis-master 正常就绪。**看 Pod 状态，不看 release 状态**。
2. **退出码 137 不等于 OOM** —— 本次 redis-cluster 崩溃 137，直觉判 OOM，但实测容器无 limits、节点 39G 可用、无 OOM 事件。K8s 事件原文才是权威：`failed liveness probe`。
3. **大镜像会被"掐断"，且是跨产品线的共性故障** —— `connection reset by peer` 在 BK-Lite（fusion-collector）和蓝鲸 7.2（elasticsearch）两条线上**完全相同**。小镜像正常、大镜像在 `failed to copy` 阶段被断开，重试策略可救回大部分。
4. **先核验再下结论** —— 本阶段两次差点下错结论（137=OOM、release failed=部署失败），都被证据推翻。
