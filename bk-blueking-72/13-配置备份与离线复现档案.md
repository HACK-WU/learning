## 四、部署流程（离线可读版）

### 4.1 源码布局

```text
/root/bk72/
  install/
    blueking/                      ← helmfile 主目录（已备份）
      *.yaml.gotmpl                ← 套餐定义
      environments/default/        ← 52 个 values 文件（已备份）
      charts/                      ← 17 个本地 tgz
      scripts/                     ← 安装钩子脚本
    bk-config/                     ← 各 SaaS 品牌资源（非模块清单）
  bin/  tools/  cert_bak/  demo/
```

### 4.2 helmfile 套餐与 seq 分批

`base-blueking.yaml.gotmpl` 定义 19 个 release，用 `labels.seq` 分批：

| seq | release | 说明 |
|---|---|---|
| first | bk-repo, bk-auth, bk-apigateway | 地基：制品库、认证、网关 |
| second | bk-iam, bk-ssm, bk-console | 权限、密钥、控制台 |
| third | bk-user, bk-iam-saas, bk-iam-search-engine, bk-gse, bk-cmdb, bkpaas-app-operator, bk-paas, bk-applog, bk-ingress-nginx, bk-ingress-rule | 主体业务 |
| fourth | bk-job | 作业平台 |
| fifth | bk-nodeman | 节点管理 |

按批次安装：

```bash
cd /root/bk72/install/blueking
helmfile -f base-blueking.yaml.gotmpl -l seq=first  sync
helmfile -f base-blueking.yaml.gotmpl -l seq=second sync
# ... 依次推进
```

### 4.3 监控套餐（独立入口）

`monitor.yaml.gotmpl` 是聚合入口，管 5 个子 helmfile：

```yaml
helmfiles:
  - path: ./monitor-storage.yaml.gotmpl     # kafka / influxdb / consul
  - path: ./04-bkmonitor.yaml.gotmpl        # bk-monitor 本体
  - path: ./04-bkmonitor-operator.yaml.gotmpl
  - path: ./04-bklog-collector.yaml.gotmpl
  - path: ./04-bklog-search.yaml.gotmpl
```

## 五、必须记住的两个坑

### 5.1 helm status=failed ≠ 组件挂了

`helm list` 里 **28 个 release 有 12 个标 `failed`**（bk-cmdb、bk-elastic、bk-mysql8、bk-paas 等），
但它们的 Pod 全在跑。

**`failed` 是最后一次 helm 操作的退出状态**（多为安装时 Job 超时），不代表运行时状态。
这批是排障时手工修 Pod/Job 恢复的，helm 状态未同步。

> **判断组件是否可用，看 Pod 状态，不要看 helm status。**
> 后果：在此状态下跑 `helmfile sync/destroy` 可能覆盖手工修复结果。

### 5.2 bk_monitorv3 不是 chart 名

`bk_monitorv3` 是**桌面应用代号**，真正的 chart 是 `blueking/bk-monitor`（v3.8.27），
release 名 `bk-monitor`。桌面图标添加用 `-a "bk_monitorv3"`。
