# 改名与物料全面核查说明

> 执行时间：2026-09-24
> 触发：用户指出「当前部署的也不是 bk-lite」，要求改名 + 全面核查物料是否遗漏

---

## 一、为什么改名

### 1.1 证据：实际部署的是蓝鲸 7.2.19 社区版

```text
assets/config-backup/blueking/VERSION  ->  7.2.19
```

`version.yaml` 里的模块清单全是**完整版**模块：

```text
bkrepo / bkauth / bk-user / bkiam / bkiam-saas / bkiam-search-engine / bkssm
bk-apigateway / bk-console / bk-gse-ce / bk-gse-ee ...
```

蓝鲸 **Lite** 轻量版只有 4 个模块，且不含 bkci / bkjob / bknodeman / bkmonitorv3。
而实测集群里这些全都有（`helm list` 28 个 release）。

**结论**：目录名 `bk-lite` 与实际内容完全不符，属**命名错误**。

### 1.2 新名称

```text
bk-lite  ->  bk-blueking-72
```

命名依据：产品（blueking）+ 主版本（7.2），与同级目录 `k8s` / `kafka` / `consul` 风格一致。

### 1.3 改名做了什么

| 动作 | 范围 | 结果 |
|---|---|---|
| 目录重命名 | `D:/projects/learning/bk-lite` | ✅ |
| 文档内路径引用 | 22 个 md | ✅ 残留 0 |
| 脚本内路径引用 | 14 个 sh/ps1 | ✅ 残留 0 |
| 报告/索引标题 `蓝鲸 bk-lite` | 3 篇 | ✅ 改为「蓝鲸 7.2 CE」 |
| 评审清单标题 | 1 篇 | ✅ |
| 复审记录错误路径注释 | 1 处 | ✅ |

### 1.4 刻意**没有**改的引用

这些是**真实存在的另一条产品线**，改了反而错：

```text
/opt/bk-lite                        BK-Lite 的实际安装目录（支线，真实存在）
bk-lite.tencentcloudcr.com/bklite   BK-Lite 的镜像 registry（真实域名）
TencentBlueKing/bk-lite             BK-Lite 的 GitHub 仓库（真实仓库）
/root/bk-lite-b                     本机临时工作目录（真实路径）
```

> **判断原则**：改的是「本工作区的路径引用」和「张冠李戴的标题」，
> 不是把所有 "lite" 字样删干净 —— 盲目全局替换会把真实产品名改没。

## 三、核查方法（可复用）

```bash
# 1. 改名前先扫描引用范围，不要直接全局替换
grep -rn --include='*.md' -iE 'bk-lite' .

# 2. 区分「路径引用」与「真实产品名」
#    路径引用：projects/learning/bk-lite        -> 改
#    产品名：  /opt/bk-lite、*.tencentcloudcr.com -> 不改

# 3. 改完必须回扫残留
grep -rn --include='*.md' -E 'projects/learning/bk-lite' . | wc -l   # 应为 0

# 4. 文档一致性：拿集群真值对文档数字
helm list -n blueking --no-headers | wc -l
kubectl get pods -n blueking --no-headers | awk '{print $3}' | sort | uniq -c
```

**核心纪律（沿用既有铁律）**：

1. **先核验再下结论** —— 组件数、Pod 数一律实测，不照抄文档
2. **区分快照与终态** —— 旧文档是过程记录，加标注而非重写，保留存真价值
3. **改名不是删字** —— 明确哪些该改、哪些不该改，避免误伤真实实体
