## 一、当前主要问题（一句话）

**GSE 对所有请求返回 403**，导致监控 `bk-monitor` 的 migrate Job 失败，
进而监控的 5 个页面组件卡在 `Init:0/1` 起不来。

**根因已最终锁定**（2026-09-23）：**ESB 签名密钥 ≠ GSE 校验密钥**。
ESB 用自己那把（`0e82d670...`）签 RS512 JWT，GSE 用 `bk-gse` gateway 的公钥
（`0e18be8a...`）验签，两者不是一对。闭环验证：用 ESB 私钥签 → ESB 公钥验通过、
GSE 公钥验 `InvalidSignatureError`。

根子在官方同步设置 `SYNC_ESB_JWT_KEY_GATEWAY_NAMES` 只含 `bk-esb`/`apigw`，
**不含 `bk-gse`**，故 bk-gse 未被同步成 ESB 的密钥。

详见 [09-排障速查手册.md](09-排障速查手册.md) 6.12。

## 四、回答三个核心问题

### Q1：镜像拉取地址，文档有记录么？

**有，但分散且有一处误导**：

- ✅ 真实地址 `hub.bktencent.com` 在多个 assets 脚本和 lesson 里出现过（拉镜像踩坑时记的）
- ❌ 但没有一份**集中对照表**（哪个组件用哪个镜像）
- ⚠️ [10-访问指南.md](10-访问指南.md) 里的 `docker.paas.example.com` 是占位域名，**会误导**

**本文件即为补齐的集中对照表。**

### Q2：监控开源，其他也都开源吗？

**大部分开源，但 GSE 是例外**：

- ✅ 开源（MIT 为主）：bk-monitor、bk-nodeman、bk-cmdb、bk-iam、bk-user、
  blueking-apigateway、blueking-paas、bk-repo、bkmonitor-datalink
- ❌ **GSE 未开源**：GitHub 上只有 `bk-gse-sdk`（插件 SDK），
  没有 GSE 服务端源码仓库。GSE 是蓝鲸的**底层管控通道**，
  从官方文档看属于核心基础设施，未对外开放源码。

**这解释了排查困境**：GSE 是最关键的组件（所有其他平台都依赖它），
却恰好是唯一拿不到源码的。

### Q3：不开源的话，拉到镜像能拿到源码吗？

**分两类，结论不同**：

| 类型 | 镜像内形态 | 能拿源码? |
|---|---|---|
| **解释型**（Python/Django） | 直接是 `.py` 文件 | ✅ **能**，且是可读源码 |
| **编译型**（C++/Go） | 只有二进制 | ❌ **不能**，只有机器码 |

**实测证据**：

```text
[nodeman] .py 源码数量: 1333        ← 镜像内直接是源码
[monitor] .py 数量: 217             ← 镜像内直接是源码
[gse] 源码文件(.cc/.h/.py/.go): 0   ← 一个都没有
[gse] bin/: gse_data 339MB 二进制    ← 只有编译产物
```

**所以**：

- 对 **nodeman / monitor / iam / user / apigateway**：即使不查 GitHub，
  `kubectl exec` 进容器就能直接读源码，**比查 GitHub 还准**（正是运行的版本）
- 对 **GSE**：镜像里 0 个源码文件，只有 339MB 的 `gse_data` 二进制。
  理论上能 `strings` 提取字符串常量、用 IDA/Ghidra 反汇编，
  但**拿不到可读源码**，工程量也极大

## 五、对当前排障的直接建议

GSE 403 排查受阻的根本原因就是**拿不到 GSE 源码**。可行的替代路径：

1. **读 SDK 推断协议**：`bk-gse-sdk` 虽是客户端 SDK，但含消息槽/信令协议定义，
   可反推服务端行为
2. **`strings` 提字符串**：从 `gse_data` 二进制里提取错误码/路径/提示语，
   可能能定位 403 的判定分支
3. **查 bk-nodeman 源码**：nodeman 是 GSE 的主要调用方（已开源，1333 个 .py），
   看它怎么构造 GSE 请求、怎么带认证 —— **这是最实际的突破口**
4. **抓包**：在 GSE Pod 内 tcpdump 看实际收到的请求头

**推荐先走 3**：nodeman 源码在手且开源，它对 GSE 的调用方式是现成的正确参照，
比反编译二进制可靠得多。
