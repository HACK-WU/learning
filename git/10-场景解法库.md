## 1. 新仓库与身份

```bash
git init -q -- my-project
cd my-project
git config user.name  "Zhang Wei"
git config user.email "zhangwei@example.com"

# 关掉环境噪声，保证演练可复现
git config commit.gpgsign false
git config tag.gpgsign   false
git config core.autocrlf false
```

**为什么设 `core.autocrlf false`**：跨平台团队里换行符自动转换会让
"什么都没改却显示整个文件都变了"。统一关掉，用 `.gitattributes` 显式管理。

## 2. 提交规范与 commit-msg 钩子

`cat > .githooks/commit-msg`

```bash
#!/usr/bin/env bash
set -uo pipefail

msg_file="${1:-}"
[[ -n $msg_file && -f $msg_file ]] || exit 0

first_line=$(head -1 -- "$msg_file")

# 豁免自动生成的信息，否则全是假阳性
case "$first_line" in
    Merge*|Revert*|"Merge pull request"*) exit 0 ;;
esac

# Conventional Commits：type(optional-scope)!?: subject
if ! printf '%s' "$first_line" | grep -qE '^(feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert)(\(.+\))?!?: .+'; then
    echo "commit-msg: 不符合 Conventional Commits" >&2
    echo "            实际：$first_line" >&2
    echo "            应为：feat(scope): 简短描述" >&2
    exit 1
fi

if (( ${#first_line} > 72 )); then
    echo "commit-msg: 主题行 ${#first_line} 字符，超过 72" >&2
    exit 1
fi
exit 0
```

## 3. pre-commit：调试残留与大文件

`cat > .githooks/pre-commit`

```bash
#!/usr/bin/env bash
set -uo pipefail

# ── 1. 调试残留 ──────────────────────────────────────────
# ⚠️ --cached 必须在模式之前：写成 `git grep -n -E 'x' --cached` 会
#    exit 128（fatal: must come before non-option arguments），
#    而下面的 if 会把 128 当成"没找到" → 静默放行，等于没装。
# ⚠️ 排除 .git：否则钩子文件里的 console.log 字样会命中钩子自己（"自咬"）。
if git grep --cached -n -E -I \
        -e 'console\.log' -e 'debugger' -e 'TODO-FIXME' \
        -e 'BEGIN RSA PRIVATE KEY' \
        -- . ':(exclude).git' >/dev/null 2>&1; then
    echo "pre-commit: 检出调试残留或私钥，已阻止提交" >&2
    git grep --cached -n -E -I \
        -e 'console\.log' -e 'debugger' -e 'TODO-FIXME' \
        -e 'BEGIN RSA PRIVATE KEY' \
        -- . ':(exclude).git' >&2
    exit 1
fi

# ── 2. 大文件（阈值 512KB）────────────────────────────────
# git ls-files -s 输出：<mode> <sha> <stage> <path>
# ⚠️ 用 -z + read -d $'\0'：文件名可能含空格
while IFS= read -r -d $'\0' rec; do
    [[ -n $rec ]] || continue
    sha=$(printf '%s' "$rec"  | cut -d' ' -f2)
    path=$(printf '%s' "$rec" | cut -d' ' -f4-)
    [[ -n $sha ]] || continue
    size=$(git cat-file -s "$sha" 2>/dev/null || printf '0')
    if (( size > 512 * 1024 )); then
        echo "pre-commit: 文件超过 512KB（${size} 字节）：$path" >&2
        echo "            大文件请走 LFS，或加入 .gitignore" >&2
        exit 1
    fi
done < <(git ls-files -s -z --cached)

exit 0
```

## 4. pre-push：保护分支与禁止强推

`cat > .githooks/pre-push`

```bash
#!/usr/bin/env bash
set -uo pipefail

# stdin 格式：<local ref> <local sha> <remote ref> <remote sha>
# 每行一个待推送的 ref，必须逐行读，不能只看第一行
while read -r local_ref local_sha remote_ref remote_sha; do
    [[ -n $local_ref ]] || continue
    branch="${remote_ref#refs/heads/}"

    if printf '%s' "$branch" | grep -qE '^(master|main|release/.*)$'; then
        echo "pre-push: $branch 是受保护分支，禁止直接推送，请走 PR" >&2
        exit 1
    fi

    # remote_sha 全零 = 新建分支，不算 force
    [[ $remote_sha =~ ^0+$ ]] && continue

    if printf '%s' "$branch" | grep -qE '^(master|main|release/.*)$'; then
        if ! git merge-base --is-ancestor "$remote_sha" "$local_sha" 2>/dev/null; then
            echo "pre-push: 对 $branch 不是快进更新，疑似 force push，已阻止" >&2
            exit 1
        fi
    fi
done
exit 0
```

**⚠️ 客户端钩子拦不住 `--no-verify`。** 真正的强制必须靠服务端 `pre-receive`。

## 5. 钩子自检（装了 ≠ 生效）

```bash
#!/usr/bin/env bash
# 唯一算数的检验：造一个必然违规的提交，看退出码
selftest() {
    local dir="$1" rc=0

    printf 'console.log("probe")\n' > "$dir/.probe.js"
    git -C "$dir" add -f -- .probe.js

    # ⚠️ 铁律：先证明探针进了索引，再判断有没有被拦。
    #    否则 "nothing to commit" 的失败（rc≠0）会被误读成"钩子生效"。
    if ! git -C "$dir" diff --cached --quiet -- .probe.js; then
        if git -C "$dir" commit -q -m 'test: probe' >/dev/null 2>&1; then
            echo "❌ pre-commit 没生效"; rc=1
        else
            echo "✅ pre-commit 拦住了"
        fi
    else
        echo "❌ 自检前置失败：探针没进索引（被 .gitignore 排除？）"; rc=1
    fi
    git -C "$dir" reset -q --hard HEAD 2>/dev/null || true
    rm -f -- "$dir/.probe.js"
    return "$rc"
}
```

**四种失效场景**（实测）：无执行位（exit 0 + 一行 hint）· `--cached` 位置错（exit 128 被当"没找到"）·
钩子自咬 · `core.hooksPath` 目录不存在。

## 6. 用 core.hooksPath 做团队共享钩子

```bash
mkdir -p .githooks
# ... 把三个钩子写进 .githooks/ ...
chmod +x .githooks/pre-commit .githooks/commit-msg .githooks/pre-push
git add .githooks
git commit -m 'build: add team git hooks'

# 每个克隆都要执行一次（.git/hooks 不会被版本控制）
git config core.hooksPath .githooks
```

**为什么**：`.git/hooks` 不进版本控制，换机器就没了。
`.githooks` 在版本库里，但**必须显式设 `core.hooksPath` 才会生效**——这一步常被忘。

## 7. 误操作救援：reset --hard

```bash
git reflog                                   # 找那次提交
git reset --hard <sha>                       # 回去
```

**实测**：

```
删除后 lost.txt 不存在
reflog 找到: d3a0249（与原 sha 完全一致）
救援成功，内容=v1
```

**边界**：只对**提交过**的东西有效。从没提交过的工作不进 reflog。

## 8. 误操作救援：误删分支

```bash
git reflog | grep 'commit: <那次提交的信息>'   # 找 sha
git branch feature/x <sha>                    # 重建指针
```

**原理**：分支是指针不是容器。删掉的是名字，提交还在。

## 9. 安全强推：force-with-lease

```bash
git fetch origin                                    # ① 前提：先 fetch
git push --force-with-lease origin master:master    # ② 用分支名，别用 HEAD
```

**实测语义对照**：

| 场景 | 结果 |
|---|---|
| `origin/master` == 远端 tip，但历史分叉 | **放行**（`forced update`） |
| fetch 之后别人又推了 | **拒绝**（`! [rejected] (stale info)`） |
| 用 `HEAD:master` 推 | **退化为无条件 force** |

**记住**：lease 只保证「我上次 fetch 之后远端没再动过」，**不检查历史包含关系**。

## 10. bisect 定位坏提交

```bash
# ① 探针放到仓库外（放仓库里会变成未跟踪文件，bisect start 会被拒）
probe=$(mktemp /tmp/probe.XXXXXX.sh)
cat > "$probe" <<EOF
#!/usr/bin/env bash
grep -q 'bad' "$(pwd)/version.txt" && exit 1
exit 0
EOF
chmod +x "$probe"

git bisect reset >/dev/null 2>&1 || true
git bisect start
git bisect bad HEAD
git bisect good HEAD~99

# ② bisect run 找到坏提交时返回非 0 —— set -e 下必须用 if 捕获
if ! out=$(git bisect run "$probe" 2>&1); then :; fi
printf '%s\n' "$out" | grep -E 'is the first bad commit'

# ③ bisect log 必须在 reset 之前取
git bisect log | grep -A1 'first bad commit'
git bisect reset
rm -f "$probe"
```

**实测**：100 个提交中定位第 63 个坏提交，只需 **6 步**（log₂100 ≈ 6.64）。

**⚠️ 三个连环坑**：探针在仓库里 · 提交内容重复导致 `nothing to commit` 且 `HEAD~N` 越界 · `run` 返回非 0 中断脚本。

## 11. 定位历史里的大文件

```bash
git rev-list --objects --all --reflog \
  | git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' \
  | awk '$1=="blob" {print $3, $4}' | sort -rn | head -20
```

**⚠️ 必须加 `--reflog`**：只查 `--all` 会漏掉"已从分支删除、但仍被 reflog 挂着"的对象——
而那恰恰是最该清理的。

## 12. 历史瘦身三步走

```bash
# 第一步：重写历史
git filter-branch -f --prune-empty \
  --index-filter "git rm -r --cached --ignore-unmatch -- <path>" \
  --tag-name-filter cat -- --all

# 第二步：三步清理（缺一不可）
git for-each-ref --format='%(refname)' refs/original/ | xargs -n1 git update-ref -d
git reflog expire --expire=now --all
git gc --prune=now --aggressive
```

**实测**：

```
重写前 1252 KB → filter-branch 后 1268 KB（⚠️ 上升，因为 refs/original 备份）→ 清理后 188 KB
```

**⚠️ 瘦身后全员必须重新克隆。** 强行 `--allow-unrelated-histories` 合并会把大文件拉回来（实测 YES）。

## 13. 冲突解决与 diff3

```bash
git config merge.conflictStyle diff3     # 显示共同祖先，好判断得多
# 解决后：
grep -nE '^(<<<<<<<|=======|>>>>>>>)' -r . || echo "无残留标记"
git add <file>
git commit
```

**记住**：`git add` 的语义是「我确认过了」，**不是**「冲突已解决」。它不检查内容。

## 14. rebase 与 merge 的选择

```bash
# 判断标准只有一个：这些提交有没有别人在用
git merge --no-ff feature     # 已推送 → 保留分叉（2 个父指针）
git rebase master             # 未推送 → 变直线（1 个父指针）
```

**黄金法则**：**只 rebase 尚未推送给他人的提交。**

## 16. 用裸仓库模拟远端做团队演练

```bash
# 远端
git init -q --bare remote.git
git -C remote.git config receive.denyNonFastForwards false

# 两名成员（各自设身份，否则 blame/log 失真）
for who in zhang li; do
    git init -q "$who"
    git -C "$who" config user.name  "Zhang Wei"
    git -C "$who" config user.email "zhangwei@example.com"
    git -C "$who" remote add origin "$(pwd)/remote.git"
done

# 种子提交
echo '# Playbook' > zhang/README.md
git -C zhang add -A && git -C zhang commit -q -m 'docs: init'
git -C zhang push -q -u origin HEAD
```
