## 🚫 适用边界与反模式

### 什么时候不该用 shell

> "不该用"比"怎么用"更值钱——这是从"会用"到"用对"的分界线。

| 场景 | 为什么不适合 | 该用什么替代 | 依据 |
|------|-------------|-------------|------|
| **要解析/生成嵌套数据（JSON/YAML/XML）** | 字符串表达不了嵌套。本机**无 jq** 是天然实锤：`grep -o '"errors": [0-9]*'` 能抠出 `12/3/27`，但**丢掉与 name 的对应关系**，答不出"哪个 service" | Python（`json` 模块） | 课 13 实测 |
| **需要真正的错误处理**（异常类型、传播、回滚） | `arr[10]` 越界返空、`$((v+1))` 非数字当 0、**都不报错** | Python / Go | 课 4 / 课 5 实测 |
| **逻辑超 200–300 行且有分支** | 无命名空间、无模块系统、无类型 | Python | 课 13 |
| **必须跨平台一致** | macOS 自带 **bash 3.2**，`declare -A` 等 bash 4+ 特性直接不工作 | Python / Go | 课 13 |
| **需要单元测试与重构保障** | 无测试框架（本机 bats 未装），重构靠人肉 | Python | 课 12 |
| **高频调用的热路径** | 每次外部命令一个 fork，WSL2 下 0.549ms/次 | 进程内实现（awk / Python） | 课 10 / 课 13 实测 |

**反向提醒**：这些场景**用 shell 更合适**——容器 entrypoint、CI 编排、无依赖部署、把几个命令串起来。
判据是「**这段逻辑在做什么**」，不是「团队用什么语言」。

### 高频反模式（能跑，但迟早出事）

这 12 条里，**前 6 条是"静默失败"家族**——它们共同构成本课程最重要的一个判断：
**不要用「没报错」判断「做对了」。**

1. **用退出码判断操作成功** —— 退出码 0 只说明"没报错"，不代表产物对。备份脚本退出 0 但产物损坏。**关键操作必须有独立的产物校验**（课 3 误区 16）
2. **`local x=$(cmd)` 捕获失败** —— 拿到的永远是 `local` 自己的 0，cmd 的失败被吞（课 2 / 课 4 / 课 11 三课反复出现）
3. **`for f in $(ls)` / `$(find ...)`** —— 文件名含空格就碎。实测 9 个文件数出 **16 个**（课 10 实测）
4. **管道里 `while` 改变量，期待外面可见** —— 子 shell 是复印件，改完随退出丢弃，`count` 永远是 0（课 8 实测）
5. **`cat file \| while read` 读最后一行** —— 末行无换行符时**静默丢弃**，2 行读成 1 行（课 3 / 课 5 实测）
6. **`grep ... \|\| true`** —— 同时吞掉 `grep` 返回 2 的**真错误**（文件不存在），把故障伪装成"无匹配"（课 11 实测）
7. **用 `$$` 判断是否在子 shell** —— 永远同一个 PID，**必须 `$BASHPID`**（课 8 实测）
8. **`trap ... KILL` 兜底** —— `trap` 返回 0 不报错，但 handler **永不执行**。你以为有保护，实际裸奔（课 9）
9. **依赖"进程死了锁自动释放"** —— 只杀父进程不够，继承 fd 的**孤儿子进程**还持锁（课 9 实测）
10. **`rm -f lockfile` 解锁** —— 删文件**不影响**已持有的锁（fd 仍指向同一 inode），且有竞态（课 9）
11. **`xargs -I{} sh -c '...{}...'`** —— `-I` 是**文本替换**，文件名含引号时 `sh -c` 语法错误（课 10 实测）
12. **`xargs` + `awk` 的 `END`** —— **每批执行一次**。1 万文件时输出 3 个小计而非总数，**不报错只是结果悄悄变**（课 10 实测）

## 🔥 高频故障模式

> 每条固定**五段式**：症状 → 根因 → 排查 → 修复 → 预防。
> 全部症状均为**可观测**的具体现象。

### 故障 1：脚本"执行成功了"，但什么都没做

- **症状**：退出码 0，无报错，但目标文件没生成 / 数据没写入 / 计数器是 0
- **根因**：shell 的错误几乎全是静默的。全课共 **171 处**「静默 / 不报错 / 零报错」记录，遍布 13 课。典型来源：
  - `local x=$(cmd)` 吞掉失败 → 后续逻辑基于空值继续跑
  - `grep ... \|\| true` 把真错误变成 0 → `[[ $count -gt 0 ]]` 静默为假
  - `declare -x arr=(...)` 导出数组**静默失败**，子进程拿到空（课 4 实测）
  - nameref 与目标同名 → **赋值静默失效**，只 warning（课 6 实测）
- **排查**：
  ```bash
  bash -n script.sh                    # 先排语法（30 秒内能排除一大类）
  bash -x script.sh 2>&1 | tail -50    # 看展开后的真实命令
  ```
- **修复**：关键操作后加**独立的产物校验**：
  ```bash
  tar -czf "$out" "$src" || die "打包失败"
  [[ -s $out ]] || die "产物为空: $out"          # 别信退出码，验字节数
  ```
- **预防**：`set -Eeuo pipefail` + `shopt -s inherit_errexit`；**永远分开写** `local x` 与 `x=$(cmd)`

---

### 故障 2：`set -e` 加了，错误还是跑过去了

- **症状**：脚本里某条命令明显失败，但脚本继续往下跑
- **根因**：`set -e` 的真实语义是「**未被测试过的**失败命令才退出」，不是"任何失败都退出"。它有**七个洞**，且方向不一致——有的放走错误（漏网），有的拦下正常代码（误伤）。最关键的一条：**在 `if` / `&&` / `||` / `!` 中的命令被豁免，且豁免会沿调用链向内传染到整个函数体**
- **排查**：确认严格模式的真实状态。⚠️ **在顶层查，别在 `$( )` 里查**——命令替换内 `set +o` 会谎报 `set +o errexit`，`$SHELLOPTS` 同样丢失 `errexit`（根因是 `errexit` 不继承进子 shell，实战项目 D6 实测）：
  ```bash
  echo "$SHELLOPTS"    # 看是否含 errexit:nounset:pipefail:errtrace
  ```
- **修复**：补齐四个字母与一个 shopt：
  ```bash
  set -Eeuo pipefail
  shopt -s inherit_errexit    # 让 errexit 继承进命令替换的子 shell
  ```
- **预防**：记住七个洞的位置；`|| true` 必须改写成检查 `$?` 并区分退出码

---

### 故障 3：`set -e` 把正常代码杀掉了

- **症状**：`i=0; (( i++ ))` 之后脚本直接退出，rc=1
- **根因**：**误伤**（与故障 2 方向相反）。`(( ))` 的返回值是表达式的**值**，后置自增返回自增**前**的值。值 0 → 退出码 1 → `set -e` 判定失败
- **排查**：`bash -x` 看退出前最后一条命令是不是算术表达式
- **修复**：三选一
  ```bash
  (( ++i ))          # 前置自增，返回自增后的值（非 0）
  (( i++ )) || true  # 显式豁免
  [[ $((i++)) -ge 0 ]]  # 放进条件，天然豁免
  ```
- **预防**：凡是算术自增，一律写 `(( ++i ))` 或放进 `if`

---

### 故障 4：循环里改的变量，出了循环就没了

- **症状**：`count=0; cat f \| while read l; do ((count++)); done; echo $count` 输出 **0**
- **根因**：管道右侧是**子 shell**，是调用环境的**复印件**——完整继承一切，但所有修改随退出丢弃
- **排查**：看数据是不是从**管道**喂进去的。子 shell 六来源：管道两侧、`$( )`、`( )`、`&`、外部命令、被执行的脚本
- **修复**：改用重定向（首选，零子 shell）
  ```bash
  while read -r l; do ((count++)); done < f
  ```
  或从命令喂：`while read -r l; do ...; done < <(cmd)`
- **预防**：需要把状态改动带回调用方时，**不用管道也不用 `$( )`**。三条出路：重定向 / nameref 出参 / 临时文件

---

### 故障 5：临时目录泄漏 / 清理没跑

- **症状**：`/tmp` 下堆积 `tmp.XXXX`；或 Ctrl-C 后残留文件；或锁不释放
- **根因**：三种独立成因
  - **命令替换吞掉登记**：`d=$(mktemp_func)` 开子 shell，函数内 `TMP_DIRS+=(...)` 不回传 → 泄漏。`BASH_SUBSHELL` **1→2** 是铁证（实战项目实测）
  - **EXIT trap 里 `$?` 是 0**：被信号杀死时 EXIT trap 拿到的 `$?` 是 **0**，实际退出 143 → 清理逻辑判断错（课 9 实测）
  - **孤儿持锁**：只杀父进程，继承 fd 的子子进程继续持锁（课 9 实测）
- **排查**：
  ```bash
  trap -p                          # 看当前装了哪些 handler
  ls -la /proc/*/fd 2>/dev/null | grep "$LOCK"   # 谁还持有锁
  ```
- **修复**：
  ```bash
  cleanup() {
      local rc=$?        # ⚠️ 必须是第一行，否则被后续命令污染
      [[ -n ${WORK_DIR:-} ]] && rm -rf -- "$WORK_DIR"
      exit $rc           # 保留真实退出码，别裸 exit
  }
  trap cleanup EXIT
  ```
- **预防**：用 nameref 出参登记临时资源（`declare -n _out=$1`），不用 `$( )`；清理函数第一行存 `$?`

---

### 故障 6：Ctrl-C 之后脚本退出码是 0

- **症状**：手动中断脚本，上层调度系统判定为**执行成功**，触发后续流程
- **根因**：若脚本正在等**外部命令**且没装 trap，bash 会把信号处理推迟到当前命令返回，退出码是 **0**。纯计算脚本才会返回 130
- **排查**：区分两种场景
  | 场景 | 退出码 |
  |---|---|
  | 纯 bash 计算循环 | **130** |
  | 正在等外部命令（如 `sleep` / `scp` / `tar`） | **0** |
- **修复**：显式装 INT/TERM trap，落 EXIT trap 保证清理
- **预防**：调度系统**不能只看 0/非 0**，关键任务要校验产物；脚本侧装 `trap 'exit 130' INT`

### 故障 7：文件名含空格，脚本数出奇怪的数字

- **症状**：9 个文件数出 16 个；或循环只执行一次；或 `Unterminated quoted string`
- **根因**：三种渐进的错误
  - `for f in $(find ...)`：**单词分割 + glob 展开 + 缓冲**三重错误
  - 加引号 `for f in "$(find ...)"`：所有文件名变成**一个字符串**，更错
  - `xargs -I{} sh -c '...{}...'`：`-I` 是**文本替换**，遇到含引号的文件名直接语法错误
- **排查**：用 `find ... -print0 | xargs -0` 复现，对比数字
- **修复**：**只有 NUL 分隔是安全的**
  ```bash
  find . -type f -print0 | xargs -0 -r bash -c 'for f in "$@"; do ...; done' _
  #                                    ⚠️ 末尾的 _ 是 $0 占位符，省掉会吞掉第一个文件
  ```
- **预防**：POSIX 只禁止 `/` 和 NUL 两个字符，**空格、tab、引号、换行全部合法**。只要脚本遍历目录，文件名就是外部输入

### 故障 8：日志是空的，但退出码 0

- **症状**：日志文件 0 字节，脚本报告成功
- **根因**：三种可能，都极难发现
  - **`&>` 在 dash 下静默失效** → 日志 0 字节但退出码 0（课 7）
  - **命令不存在时也会创建重定向文件**（重定向先于命令查找）→ 得到空的占位文件（课 1）
  - **全缓冲 + SIGKILL** → 缓冲区内容**蒸发**，实测 0 字节（课 7 实测）
- **排查**：`wc -c` 验字节数，别只看文件在不在
- **修复**：可移植写 `>log 2>&1`（不用 `&>`）；长任务加 `stdbuf -oL`
  ```bash
  cmd > log 2>&1              # 可移植（dash 也认）
  stdbuf -oL cmd | ...        # ⚠️ 要加在真正做缓冲的进程上，加在过路的 cat 上无效
  ```
- **预防**：重定向顺序从左到右复制指针；写日志后 `[[ -s $log ]]` 校验

---

### 故障 9：管道后接 `head`，脚本偶发失败

- **症状**：`cmd | head -5` 偶发非零退出，或日志里出现 141
- **根因**：**SIGPIPE**。`head` 读够就退出，写端收到 SIGPIPE → 退出码 **141**
- **排查**：`echo "${PIPESTATUS[@]}"` —— ⚠️ **必须立刻存**，任何命令都会重置它
- **修复**：显式处理 141，或用 `sed 5q` / `awk 'NR<=5'` 替代 `head`（它们读完不提前退出）
- **预防**：`set -o pipefail` 会让 141 冒出来，**不能无脑忽略**，要区分"真失败"与"下游提前关闭"

---

### 故障 10：脚本行为"很玄学"，与代码不符

- **症状**：同样的脚本在不同环境/不同调用方式下行为不一致
- **根因**：四类环境干扰源
  - **`BASH_ENV` 非空** → 非交互 bash 会先 source 它，凭空多出变量与函数（课 8）
  - **hash 缓存** → 改了 PATH 仍用旧版本，`hash -d` 才生效（课 1）
  - **`/bin/sh` 是 dash** → `&>`、`echo -e`、`local` 行为全不同（课 3 / 课 12 实测）
  - **库文件重复 source** → `declare -r` + `set -e` 下被 `readonly variable` 报错中断，**后续变量全未定义**（实战项目实测）
- **排查**：
  ```bash
  echo "BASH_ENV=${BASH_ENV:-（空）}"
  echo "$0 / ${BASH_SOURCE[0]}"     # 是被执行还是被 source
  ls -l /bin/sh
  ```
- **修复**：库文件加 include guard
  ```bash
  [[ -n ${_MYLIB_LOADED:-} ]] && return 0
  _MYLIB_LOADED=1
  ```
- **预防**：脚本首行 `#!/usr/bin/env bash`（不要 `#!/bin/sh`）；库里用 `return` 不用 `exit`（`exit` 会杀掉 source 它的 shell）

---

### 故障 11：参数被当成命令执行了（注入）

- **症状**：传一个文件名，脚本执行了意料之外的命令
- **根因**：**注入的本质不是"用没用 eval"，而是"数据会不会被 shell 重新解析"**。同一 payload 实测：
  | 写法 | 结果 |
  |---|---|
  | `eval "grep -r '$p' ."` | 读出 `TOP-SECRET-TOKEN` |
  | `grep -r -- "$p" .` | 零输出、退出码 1，**完全免疫** |
  | `ssh host "cmd $x"` | **无 eval 同样危险**（远端 shell 会解析） |
- **排查**：搜索脚本里的 `eval`、无引号 `$var` 出现在命令位置、`ssh ... "$var"`
- **修复**：三原则按优先级
  1. **白名单正则** `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`（8 个边界用例全覆盖，含**空串**）
  2. **参数数组 + `--`**：`cmd -- "$x"`。⚠️ `--` 不是万能的——`tar -czf -- out.tar.gz` 构建失败，带参数的选项内部顺序优先于 `--`
  3. `printf %q` 兜底
- **预防**：**glob 注入不需要 eval 也不需要分号**——传 `*` 作文件名，无引号 `cat $target` 会把目录下所有文件读一遍

---

### 故障 12：脚本越跑越慢，CPU 全花在"启动进程"上

- **症状**：处理几千条数据耗时几分钟；`top` 里大量短命进程
- **根因**：**循环内 fork**。每次外部命令一个进程，WSL2 下实测 **0.549ms**/次（vs bash 纯算术 0.0035ms，**157×**）
- **排查**：翻到每个 `for`/`while`，问「**循环体里有没有外部命令**」
- **修复**：三个实测过的方向（倍数均为 WSL2 实测）
  | 改法 | 倍数 |
  |---|---|
  | `basename` ×2000 → `${p##*/}` | **345×** |
  | `expr` ×2000 → `$(( ))` | **540×** |
  | 循环内调外部命令 → 交给单个 awk | **1000×** |
- **预防**：微优化收益普遍 < 2×（去掉 `cat` 只有 **12%**，`[[ ]]` vs `[ ]` 只有 **1.2×**）。
  **数量级优化只有一个方向——减少 fork 次数。** 优化过的 shell（awk 45ms）可以比 Python（63ms）更快

## 🧭 三条取证纪律

这三条是"排查手法本身会骗人"的教训，来自实战项目实测——**错误的取证手段会让你得出完全相反的结论**。

### 1. 查严格模式状态：别在命令替换里查

实测对照（`set -e` 已开启的前提下）：

| 取证方式 | 顶层执行 | 命令替换 `$( )` 内 |
|---|---|---|
| `set +o \| grep errexit` | `set -o errexit` ✅ | **`set +o errexit`** ❌ 谎报为 off |
| `echo "$SHELLOPTS"` | 含 `errexit` ✅ | **不含 `errexit`** ❌ 同样丢失 |

**结论**：两者**都不能跨命令替换取证**——命令替换开子 shell，而 `errexit` 默认不继承进去（`inherit_errexit` 未开时）。
断言函数内部正是命令替换，**取证手段污染了被取证对象**（实战项目 D6）。

**正确做法**：
```bash
shopt -s inherit_errexit    # 打开后，子 shell 里 errexit 也是 on，取证才可信
echo "$SHELLOPTS"           # 在顶层查，不要在 $( ) 里查
```

**⚠️ 修脚本时别只改取证方式**——根因是 `errexit` 不继承进子 shell。只换取证命令而不开 `inherit_errexit`，命令替换内部的失败**依然会被吞**。

### 2. 日志标签带尾空格，`[INFO]` 永远匹配不上

标签是 `printf '%-5s'` 补齐的，`INFO` 实际是 **`[INFO ]`**（带一个尾空格）。
用 `grep '\[INFO\]'` 去匹配**永远匹配不上**。

### 3. `PS4` 不做 printf 格式化

PS4 里写 `%(%H:%M:%S)T` 会**原样输出字面量**。要时间戳只能用 `$(date +%T)`，代价是每行 trace fork 一次。
