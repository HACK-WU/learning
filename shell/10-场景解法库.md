## 1. 脚本开头模板

```bash
#!/usr/bin/env bash
#                 ↑ 不要写 #!/bin/sh——八成是 dash，`&>` / `local` / `echo -e` 行为全都不同
set -Eeuo pipefail
shopt -s inherit_errexit   # 让 errexit 继承进命令替换的子 shell
IFS=$'\n\t'                # 收紧默认分隔符（注意：这会影响未加引号的展开，务必全程加引号）

readonly PROGNAME="${0##*/}"
readonly VERSION='1.0.0'
```

**四个字母，不只是三个**：`set -Eeuo pipefail` 的 `E` 让 ERR trap 进函数。少 `-E` 则函数内的错误不触发 trap。

| 选项 | 作用 | 少了会怎样 |
|---|---|---|
| `-E` | ERR trap 继承进函数 | 函数内错误不触发 trap |
| `-e` | 未被测试的命令失败即退出 | 错误静默跑过去 |
| `-u` | 未定义变量即报错 | 拼写错误的变量名静默为空 |
| `-o pipefail` | 管道任一失败即失败 | 只取最后一段，吞错 |
| `inherit_errexit` | `-e` 继承进 `$( )` | 命令替换内部的失败被吞 |

## 2. 参数解析与四层校验

```bash
usage() {
    # ⚠️ --help 走 stdout 且退出码 0，这样才支持 `prog --help | less`
    cat <<'EOF'    # 定界符加引号 = 整段不展开
用法: prog.sh -c <config> [-n] [-v] <target>
  -c <config>  配置文件路径（必需）
  -n            dry-run，只打印不执行
  -v            详细输出
  -h            显示帮助
EOF
}

CONFIG=''; DRY_RUN=0; VERBOSE=0

while getopts ':c:nhv' opt; do
    case $opt in
        c) CONFIG=$OPTARG ;;
        n) DRY_RUN=1 ;;
        v) VERBOSE=1 ;;
        h) usage; exit 0 ;;
        :) printf '错误：选项 -%s 需要参数\n' "$OPTARG" >&2; exit 2 ;;   # 缺参数 = 用法错误
        \?) printf '错误：未知选项 -%s\n' "$OPTARG" >&2; usage >&2; exit 2 ;;
    esac
done
shift $((OPTIND - 1))
```

**四层校验**（课 11）：存在 → 类型 → 范围 → 依赖。**只解析不校验，错误会推迟到业务逻辑里才炸，错误信息与根因毫无关联。**

```bash
# ① 存在
[[ $# -ge 1 ]] || { printf '错误：缺少 <target>\n' >&2; exit 2; }
[[ -n $CONFIG ]] || { printf '错误：-c 为必填\n' >&2; exit 2; }

# ② 类型（⚠️ 前导零是八进制：08/09 会直接报错，用 10# 修复）
[[ $timeout =~ ^[0-9]+$ ]] || { printf '错误：--timeout 必须是整数\n' >&2; exit 2; }
(( 10#$timeout > 0 )) || { printf '错误：--timeout 必须为正\n' >&2; exit 2; }   # ③ 范围

# ④ 依赖
[[ -f $CONFIG ]] || { printf '错误：配置文件不存在: %s\n' "$CONFIG" >&2; exit 3; }
```

**退出码语义要分开**（课 11）：参数缺失是**用法错误（2）**，文件不存在是**输入问题（3）**。混了调用方无法区分。

⚠️ **`getopts` 不支持长选项** —— `--file` 会被拆成 `-f -i -l -e`。
⚠️ **两次调用 `getopts` 要重置 `OPTIND`** —— 否则第二轮静默什么都不解析。

## 3. 错误处理与 die

```bash
readonly EX_USAGE=2 EX_INPUT=3 EX_DEPEND=4

die() {
    local rc=$1; shift
    printf '[ERROR] %s\n' "$*" >&2     # ⚠️ 一律 printf，不用 echo（跨 shell 行为不一致）
    exit "$rc"
}

# 错误信息要带上下文：「文件不存在」与「文件不存在: /data/c.yaml（参数 --config）」
# 排障成本差一个数量级
[[ -f $f ]] || die "$EX_INPUT" "文件不存在: $f（参数 --config）"
```

**错误栈**（课 11）——需要 `set -E` 才进函数：

```bash
trap 'rc=$?; printf "[ERROR] 第 %s 行失败（退出码 %s）\n调用栈: %s\n" \
      "${BASH_LINENO[0]}" "$rc" "${FUNCNAME[*]:-main}" >&2; exit $rc' ERR
```

⚠️ **ERR trap 里用 `$LINENO` 指向的是 trap 函数内部的行。指出错行要用 `${BASH_LINENO[0]}` + `${BASH_SOURCE[1]}`。**

**⚠️ 需要完整调用栈时，不要用命令替换** —— `$( )` 开子 shell 会丢失中间帧，还会导致栈被打印两次。改用全局变量传出结果。

## 4. 临时目录与清理

```bash
WORK_DIR=''

cleanup() {
    local rc=$?        # ⚠️ 必须是第一行：被信号杀死时 EXIT trap 里的 $? 是 0，实际退出 143
    if [[ -n $WORK_DIR ]]; then
        if (( rc == 0 )); then
            rm -rf -- "$WORK_DIR"
        else
            # 失败时保留现场——清理干净了就没有证据可查
            printf '[WARN] 执行失败，保留临时目录: %s\n' "$WORK_DIR" >&2
        fi
    fi
    exit "$rc"         # ⚠️ 别裸 exit，那会把失败伪装成成功
}
trap cleanup EXIT

# mktemp：模板至少 6 个 X（POSIX/BSD 要求，本机 GNU 虽然接受 3 个）
WORK_DIR=$(mktemp -d -t myprog.XXXXXXXX)   # 权限 700
```

**⚠️ 登记临时资源不能用命令替换**：

```bash
# ❌ 错：$( ) 开子 shell，函数内的 TMP_DIRS+=(...) 不回传 → 泄漏
d=$(create_tmpdir)

# ✅ 对：nameref 出参（见场景 8）
create_tmpdir d
```

清理的三个独立成因（课 9 实测）：命令替换吞登记 · EXIT trap 的 `$?` 是 0 · 孤儿子进程继承 fd 继续持锁。

## 5. 遍历文件（NUL 安全）

```bash
# ✅ 唯一安全的方式（配合第 6 节的 read 写法）
while IFS= read -r -d '' f; do
    printf '处理: %s\n' "$f"
done < <(find . -type f -print0)

# ✅ 交给外部命令批量处理
find . -type f -print0 | xargs -0 -r bash -c 'for f in "$@"; do ...; done' _
#                                    ⚠️ 末尾 _ 是 $0 占位符，省掉会吞掉第一个文件
#                                                    -r：空输入时不执行（GNU 默认会执行一次）

# ✅ find 自带批量（-exec + 是 1 个进程，\; 是 N 个）
find . -type f -exec grep -l pattern {} +
```

**❌ 三种渐进的错误**（课 10 实测：9 个文件数出 16 个）：

```bash
for f in $(find . -type f); do      # ❌ 单词分割 + glob 展开 + 缓冲，三重错误
for f in "$(find . -type f)"; do    # ❌ 全部变成一个字符串，只循环一次（更错）
find . | xargs -I{} sh -c 'cat {}'  # ❌ 文本替换，含引号文件名 → Unterminated quoted string
```

**⚠️ 文件名可含空格、tab、引号、换行——POSIX 只禁止 `/` 和 NUL。**
只要脚本遍历目录，**文件名就是外部输入。**

## 6. 逐行读取

```bash
while IFS= read -r line || [[ -n $line ]]; do
    ...
done < file
```

**五个部分缺一不可**：

| 部分 | 缺了会怎样 |
|---|---|
| `-r` | 反斜杠被当转义（`a\tb` → `atb`） |
| `IFS=` | 首尾空白被吃掉 |
| `line` | — |
| `\|\| [[ -n $line ]]` | **末行无换行符时静默丢失**（2 行读成 1 行） |
| `< file`（而非管道） | 管道开子 shell，循环里的变量出不去 |

**整文件读入数组**（课 5）：

```bash
mapfile -t lines < <(cmd)     # ✅ 进程替换，数组留在当前 shell
# ⚠️ mapfile 一次性读入内存，不适合超大文件
```

## 7. 数组与关联数组

```bash
services=()                                   # ⚠️ set -u 下必须先初始化
services+=('web server')                      # 元素可含空格

for s in "${services[@]}"; do                 # ⚠️ 引号必须——漏了 3 个变 5 个且零报错
    printf '%s\n' "$s"
done

printf '共 %d 个\n' "${#services[@]}"         # ⚠️ 长度是 ${#arr[@]}，${#arr} 是第 0 个元素字符数

declare -A cnt=()                             # ⚠️ 关联数组必须 declare -A
[[ -v cnt[$k] ]] && (( cnt[$k]++ )) || cnt[$k]=1
# ⚠️ 判键存在用 -v；[ -n "${m[k]}" ] 在值为空时误判
# ⚠️ set -u 下自增不存在的键会崩，用 ${cnt[$k]:-0}
```

**⚠️ 关联数组不保序**（哈希序），需要顺序时用索引数组。
**⚠️ 追加整个数组要 `arr+=("${other[@]}")`**，`arr+=$other` 只追加第 0 个。

## 8. 函数返回多个值（nameref 出参）

```bash
parse_path() {
    local input=$1
    declare -n _out_dir=$2 _out_base=$3    # ⚠️ nameref 变量永远带 _ 前缀
    _out_dir="${input%/*}"
    _out_base="${input##*/}"
}

parse_path '/a/b/c.txt' dir base
printf 'dir=%s base=%s\n' "$dir" "$base"    # dir=/a/b base=c.txt
```

**⚠️ nameref 撞名会失效，两种撞名的静默程度不同**（本机实测复核，2026-09-04）：

```bash
# ① 课 6 变体：函数内 local 与 nameref「目标」同名 → 赋值静默失效
f(){ local d; declare -n _o=$1; _o="set"; }; d=orig; f d; echo "[$d]"
# 实测输出 [orig]，且 ⚠️ 连一条 warning 都没有——最危险的一种

# ② 实战项目变体：nameref 变量自身与传入名同名 → circular name reference
f(){ declare -n d=$1; d="set"; }; d=orig; f d; echo "[$d]"
# 实测输出 [set]，但伴随 3 条 warning: d: circular name reference
```

**规避**：nameref 变量一律 `_` 前缀（如 `_ra_nref_`），函数内局部量也带前缀隔离。实测隔离写法正常返回 `[set]`。

**⚠️ 不要试图用 `$( )` 返回状态改动** —— 它吞掉的不只是退出码，还有数组登记（临时目录泄漏）、调用栈中间帧、测试里的 stub 计数。

## 9. 注入防护与白名单

```bash
# ① 白名单（首选）——8 个边界用例全覆盖，含空串
validate_name() {
    [[ $1 =~ ^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$ ]] || {
        printf '非法名称: %q\n' "$1" >&2
        return 1
    }
}

# ② 参数数组 + --（传外部命令时）
grep -r -- "$pattern" .

# ③ printf %q 兜底
printf '执行: %q\n' "$cmd"
```

**注入的本质不是"用没用 eval"**，而是"数据会不会被 shell 重新解析"（课 13 实测）：

| 写法 | 结果 |
|---|---|
| `eval "grep -r '$p' ."` | 读出 `TOP-SECRET-TOKEN` |
| `grep -r -- "$p" .` | 零输出、退出码 1，**完全免疫** |
| `ssh host "cmd $x"` | **无 eval 同样危险**（远端 shell 会解析） |

**⚠️ `--` 不是万能的**：`tar -czf -- out.tar.gz` 构建失败——**带参数的选项内部顺序优先于 `--``。

**⚠️ glob 注入不需要 eval 也不需要分号**：传 `*` 作文件名，无引号 `cat $target` 会把目录下所有文件读一遍。

## 10. 并发与限流

```bash
# 4 路并发（实测：8 台机器串行 1611ms → 4 路 404ms，约 4×）
run_batch() {
    local -a pids=()
    local max_jobs=4
    local item

    for item in "$@"; do
        while ((${#pids[@]} >= max_jobs)); do
            local still=()
            for pid in "${pids[@]}"; do
                kill -0 "$pid" 2>/dev/null && still+=("$pid") || wait "$pid"
            done
            pids=("${still[@]}")
            ((${#pids[@]} >= max_jobs)) && sleep 0.1
        done
        do_work "$item" & pids+=($!)
    done

    local rc=0
    for pid in "${pids[@]}"; do
        wait "$pid" || rc=1      # ⚠️ 裸 wait 才拿得到退出码；if wait 拿不到
    done
    return "$rc"
}
```

**⚠️ 限流的目的是保护下游，不是优化自己** —— 8 路全开实测确实更快（204ms vs 404ms），但会打爆数据库连接与 API 限流。
**⚠️ 并发时用全局变量汇总结果没用** —— 后台是子 shell，改了不回传。用临时文件。

## 11. 文本处理（awk 一次遍历）

```bash
# ✅ 一次遍历完成多个统计（读三遍文件是 3 倍磁盘 IO）
awk -F, '
    NR == 1 { next }                    # 跳过表头
    $3 == "ERROR" { err++ }
    $3 == "WARN"  { warn++ }
    { by_svc[$1]++ }
    END {
        printf "ERROR=%d WARN=%d\n", err, warn
        for (s in by_svc) printf "%-12s %d\n", s, by_svc[s]
    }
' app.log

# ✅ 多文件用 FNR（当前文件行号）与 FILENAME 区分
awk 'FNR == 1 { printf "== %s ==\n", FILENAME } { print }' *.log
```

**⚠️ `xargs` + `awk` 的 `END` 每批执行一次** —— 1 万文件时输出 3 个小计而非总数，**不报错只是结果悄悄变**。需要全局汇总时不要用 `xargs` 分批，直接 `find -exec awk {} +` 或让 awk 自己读文件列表。

**格式规整时用字段（`$3`）比正则更稳** —— 不受正文中出现关键词的干扰。

## 12. 日志与可观测

```bash
log() {
    # ⚠️ 一律 printf，不用 echo：dash 下 echo -e/-n 行为不同，同一脚本日志格式会变
    # ⚠️ 变量绝不能放进格式串：x="100%done"; printf "$x\n" → 1000one
    printf '[%(%F %T)T] %-5s %s\n' -1 "$1" "$2" >&2
}
log INFO  '开始处理'
log ERROR '失败'
```

**⚠️ 日志标签带尾空格**：`%-5s` 补齐，`INFO` 实际是 `[INFO ]`（带一个尾空格）。
用 `grep '\[INFO\]'` **永远匹配不上**。

**调试 trace**：

```bash
PS4='+${BASH_SOURCE}:${LINENO}:${FUNCNAME[0]}: ' bash -x script.sh 2>&1 | tail -80
```

**⚠️ `PS4` 不做 printf 格式化** —— 写 `%(%H:%M:%S)T` 会原样输出字面量。要时间戳只能 `$(date +%T)`，代价是每行 trace fork 一次。
**⚠️ `set -x` 输出到 stderr** —— `2>&1` 会把 trace 混进业务数据。
**⚠️ `set +x` 保护不了敏感信息** —— 密码写在 `set +x` **之前**，明文已经进 trace 了。**先关 trace，再碰敏感数据。**

**子 shell 层级**：看 `PS4` 首字符重复次数（`+` 一层，`++` 两层），比显式写 `$BASH_SUBSHELL` 直观。

## 13. 库文件（include guard）

```bash
# lib/core.sh
[[ -n ${_MYLIB_CORE_LOADED:-} ]] && return 0    # ⚠️ 必须：declare -r + set -e 下
_MYLIB_CORE_LOADED=1                            #   重复 source 会被 readonly variable
                                                #   报错中断，后续变量全未定义

readonly MYLIB_VERSION='1.0.0'

mylib_hello() {
    local name=$1
    printf 'hello %s\n' "$name"
}
```

**⚠️ 库里用 `return` 不用 `exit`** —— `exit` 会杀掉 source 它的 shell。
**⚠️ 取脚本路径用 `${BASH_SOURCE[0]}`** —— 被 source 时 `$0` 是调用者的名字。

```bash
# 使用方
_LIB_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)/lib"
source "$_LIB_DIR/core.sh"
```

## 14. 锁与单例

```bash
LOCK_FILE='/var/lock/myprog.lock'

exec 9>"$LOCK_FILE" || exit 1
if ! flock -n 9; then
    printf '另一个实例正在运行\n' >&2
    exit 1
fi
# 锁在 fd 9 上，进程退出（含被杀）时内核自动释放
```

**⚠️ `rm -f lockfile` 不能解锁** —— 删文件不影响已持有的锁（fd 仍指向同一 inode），且有竞态。
**⚠️ 进程死了锁会自动释放，但只杀父进程不够** —— 继承 fd 的**孤儿子进程**还持锁（课 9 实测）。
**⚠️ 别用 `$$` 做唯一锁文件名** —— PID 会复用，且 `mktemp` 的原子性无法靠 `$$` 模拟（TOCTOU）。
**⚠️ `kill -- -$$` 杀进程组通常无效** —— 脚本一般不是组长，`-$$` 组不存在；用真 PGID 会**误杀调用者**。

## 15. 可测性结构与 stub

```bash
#!/usr/bin/env bash
set -Eeuo pipefail

main() {
    local dir=$1
    # 通过"可替换的命令变量"留出接缝——测试时替换成 stub
    local find_cmd=${RA_FIND_CMD:-find}
    $find_cmd "$dir" -type f -print0
}

# ⚠️ main 守卫用 if 块，不要照抄 [ ... ] && main "$@"
#   后者在 set -e 下被 source 时返回 1，会直接杀死测试脚本
if [[ ${BASH_SOURCE[0]} == "$0" ]]; then
    main "$@"
fi
```

**⚠️ stub 的计数不能用 shell 变量传递** —— `$( )` 开子 shell，实测 `out=20 hits=0`，断言永远为 0。**写进文件**：

```bash
# stub
#!/usr/bin/env bash
echo hit >> "$RA_STUB_HITS"    # 计数落文件
echo "stub output"
```

**⚠️ 断言严格模式不要在 `$( )` 里查** —— 命令替换内 `set +o` 会谎报 `set +o errexit`，`$SHELLOPTS` 也**不含** `errexit`（根因：`errexit` 不继承进子 shell）。先在顶层 `shopt -s inherit_errexit`，再断言。

## 16. 何时换 Python

**四条否决项**，命中任意一条就不该用 shell：

| # | 信号 | 为什么不适用 |
|---|---|---|
| 1 | 要解析/生成**嵌套数据结构**（JSON/YAML/XML） | 字符串表达不了嵌套。本机**无 jq** 是天然实锤：`grep -o '"errors": [0-9]*'` 能抠出数字，但**丢掉与 name 的对应关系** |
| 2 | 需要**真正的错误处理** | `arr[10]` 越界返空、`$((v+1))` 非数字当 0，**都不报错** |
| 3 | 逻辑超 **200–300 行**且有分支 | 无命名空间、无模块系统、无类型 |
| 4 | 需要**单元测试与重构**，或必须跨平台一致 | macOS 自带 **bash 3.2**，`declare -A` 等 bash 4+ 特性直接不工作 |

**⚠️ 不是重写，是迁移核心逻辑。** shell 保留编排，Python 接管计算：

```bash
# ✅ shell 负责找文件与编排，Python 负责解析（整个脚本无一行 bash 在解析日志）
find logs -name '*.log' -print0 | xargs -0 python3 summarize.py
```

**⚠️ 换语言是复杂度管理手段，不是性能优化手段。** 实测优化过的 shell（awk 45ms）比 Python（63ms）**更快**——循环里 fork 才是性能问题的根因，而那靠消灭循环解决。
