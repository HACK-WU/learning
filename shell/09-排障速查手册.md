## 🚨 前 60 秒：三板斧

不管什么症状，先做这三步——它们能排除一大类问题，成本不到一分钟。

```bash
bash -n script.sh                     # ① 语法检查（不执行）
bash -x script.sh 2>&1 | tail -80     # ② 看展开后的真实命令（trace 走 stderr）
echo "${PIPESTATUS[*]:-}"             # ③ 管道各段退出码（必须紧跟管道，见下方警告）
```

**⚠️ 第 ③ 步的致命细节**：`PIPESTATUS` **会被任何命令重置**。
`cmd1 | cmd2; echo; echo "${PIPESTATUS[@]}"` 拿到的是 `echo` 的结果。**必须下一行立刻存进数组**：

```bash
cmd1 | cmd2
rcs=("${PIPESTATUS[@]}")    # 立刻存，隔一行就没了
```

## 🔍 按症状倒查

### 症状：脚本"成功了"但什么都没做

| 检查 | 命令 |
|---|---|
| 严格模式真开着吗 | `echo "$SHELLOPTS"` ⚠️ **在顶层查，别在 `$( )` 里查**——命令替换内 `set +o` 会谎报 `set +o errexit`，`$SHELLOPTS` 同样丢失 `errexit`。根因是 `errexit` 不继承进子 shell，见 [取证纪律 1](08-实战经验.md#1-查严格模式状态别在命令替换里查) |
| 数组导出是否静默失败 | `declare -p arr` 在父子进程分别执行对比 |
| nameref 是否撞名 | 函数内 `local x` 与传入的 nameref 目标同名 → **静默失效** |
| 产物真的生成了吗 | `[[ -s $out ]] \|\| echo "产物为空"` |

**最常见成因**：`local x=$(cmd)` 吞掉失败 → 后续基于空值继续跑。**改成 `local x` 单独一行再赋值。**

---

### 症状：错误被吞了 / 该停没停

```bash
echo "$SHELLOPTS"    # 应含 errexit:nounset:pipefail:errtrace
```

缺什么补什么：

```bash
set -Eeuo pipefail        # 四个字母，不只是三个
shopt -s inherit_errexit  # 让 errexit 继承进命令替换的子 shell
```

**`set -e` 的七个洞**：记住最容易中的三条——
① 在 `if` / `&&` / `||` / `!` 中的命令被豁免，**且豁免向内传染到整个函数体**
② `local x=$(cmd)` 吞码
③ 命令替换开子 shell，`errexit` 默认不继承进去

---

### 症状：`set -e` 把正常代码杀了

看退出前最后一条命令是不是**算术表达式**：

```bash
i=0; (( i++ ))     # ❌ 后置自增返回自增前的值 0 → 退出码 1 → set -e 杀掉
(( ++i ))          # ✅ 前置自增
(( i++ )) || true  # ✅ 显式豁免
```

---

### 症状：变量出了循环就没了 / 计数永远是 0

**根因**：子 shell 是复印件。六来源——管道两侧 · `$( )` · `( )` · `&` · 外部命令 · 被执行的脚本。

**判断自己在不在子 shell**：

```bash
echo "$BASHPID"     # ✅ 会变
echo "$$"           # ❌ 永远同一个，看不出来
```

**修复**（按优先级）：

```bash
while read -r l; do ((c++)); done < file          # ① 重定向（首选，零子 shell）
while read -r l; do ((c++)); done < <(cmd)        # ② 进程替换
declare -n _out=$1                                 # ③ 函数返回用 nameref 出参
```

---

### 症状：临时文件泄漏 / 锁不释放 / Ctrl-C 后残留

```bash
trap -p                                    # 装了哪些 handler
ls -l /proc/*/fd 2>/dev/null | grep "$L"   # 谁还持有这个锁
ps -ef --forest | grep -A3 <pid>           # 有没有孤儿子进程
```

**三个独立成因**：
1. **命令替换吞掉登记** —— `d=$(mktemp_func)` 开子 shell，`TMP_DIRS+=(...)` 不回传。用 nameref 出参
2. **EXIT trap 里 `$?` 是 0** —— 被信号杀死时，EXIT trap 拿到的 `$?` 是 **0**（实际退出 143）。**清理函数第一行必须 `local rc=$?`**
3. **孤儿持锁** —— 只杀父进程不够，继承 fd 的子子进程继续持锁

**⚠️ `rm -f lockfile` 不能解锁**：删文件不影响已持有的锁（fd 仍指向同一 inode），且有竞态。

---

### 症状：Ctrl-C 后退出码是 0（上层误判成功）

| 场景 | 退出码 |
|---|---|
| 纯 bash 计算循环 | **130** |
| 正在等外部命令（`sleep`/`scp`/`tar`）且无 trap | **0** |

bash 会把信号处理**推迟**到当前命令返回（实测：T+0.5s 发 INT，`sleep 3` 完整跑完 3004ms 才响应）。

```bash
trap 'exit 130' INT TERM    # 显式装
```

### 症状：文件名/空格/换行导致数字不对

**只有 NUL 分隔是安全的。** POSIX 只禁止 `/` 和 NUL——**空格、tab、引号、换行全部合法**。

```bash
find . -type f -print0 | xargs -0 -r bash -c 'for f in "$@"; do ...; done' _
#                                    ⚠️ 末尾 _ 是 $0 占位符，省掉会吞掉第一个文件
#                                                    -r：空输入时不执行（GNU 默认会执行一次）
```

**三种渐进的错误**：
- `for f in $(find ...)` → 9 个文件数出 **16 个**
- 加引号 `for f in "$(find ...)"` → 全部变成一个字符串，**只循环一次**
- `xargs -I{} sh -c '...{}...'` → 文本替换，含引号文件名直接 `Unterminated quoted string`

**读行要写全五个部分**：

```bash
while IFS= read -r line || [[ -n $line ]]; do
    ...
done < file
```

`-r` 防反斜杠被当转义 · `IFS=` 防首尾空白被吃 · `|| [[ -n $line ]]` **防末行无换行被静默丢弃**（2 行读成 1 行）。

---

### 症状：日志是空的 / 0 字节但退出码 0

```bash
wc -c "$log"    # 别只看文件在不在
```

三种成因：
1. **`&>` 在 dash 下静默失效** → 改用 `>log 2>&1`
2. **命令不存在时也会创建重定向文件**（重定向先于命令查找）→ 得到空占位文件
3. **全缓冲 + SIGKILL = 缓冲区蒸发**，实测 0 字节

```bash
cmd > log 2>&1        # ✅ 可移植，dash 也认
stdbuf -oL cmd | ...  # ⚠️ 要加在真正做缓冲的进程上；加在过路的 cat 上无效
```

### 症状：管道后接 `head` 偶发失败 / 出现 141

**SIGPIPE**。`head` 读够就退出，写端收到 SIGPIPE → 退出码 **141**。

```bash
cmd | head -5
rcs=("${PIPESTATUS[@]}")    # 立刻存
[[ ${rcs[0]} -eq 141 ]] && echo "下游提前关闭，非真失败"
```

或改用 `sed 5q` / `awk 'NR<=5'`（读完不提前退出）。

### 症状：脚本行为玄学 / 换个环境就不一样

```bash
echo "BASH_ENV=${BASH_ENV:-（空）}"      # 非交互 bash 会先 source 它
echo "$0 / ${BASH_SOURCE[0]}"            # 被执行 vs 被 source
ls -l /bin/sh                            # 八成是 dash
type -a cmd                              # 查 hash 缓存与实际解析到的命令
```

**四类干扰源**：`BASH_ENV` 非空 · hash 缓存（改了 PATH 仍用旧版，需 `hash -d`）· `/bin/sh` 是 dash · 库文件重复 source

```bash
# 库文件 include guard（否则 declare -r + set -e 下被 readonly variable 报错中断）
[[ -n ${_MYLIB_LOADED:-} ]] && return 0
_MYLIB_LOADED=1
```

**⚠️ 库里用 `return` 不用 `exit`**——`exit` 会杀掉 source 它的 shell。

### 症状：脚本很慢

**翻到每个 `for`/`while`，问：循环体里有没有外部命令？** 这是唯一值得做的判断。

| 慢 | 快 | 倍数 |
|---|---|---|
| `basename` ×2000（2419ms） | `${p##*/}`（7ms） | **345×** |
| `expr` ×2000（2716ms） | `$(( ))`（5ms） | **540×** |
| 循环内调外部命令（3145ms） | 交给单个 awk（3ms） | **1000×** |
| `find -exec \;`（9 进程） | `find -exec +`（1 进程） | 9× |

**别做这些微优化**：去掉 `cat |` 只有 **12%**，`[[ ]]` vs `[ ]` 只有 **1.2×**。

---

### 症状：怀疑注入 / 参数被当命令执行

**注入的本质不是"用没用 eval"，而是"数据会不会被 shell 重新解析"。**

| 写法 | 实测结果 |
|---|---|
| `eval "grep -r '$p' ."` | 读出 `TOP-SECRET-TOKEN` |
| `grep -r -- "$p" .` | 零输出、退出码 1，**完全免疫** |
| `ssh host "cmd $x"` | **无 eval 同样危险**（远端 shell 会解析） |

**三原则**（按优先级）：
1. 白名单正则 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`
2. 参数数组 + `--`。⚠️ `--` 不是万能的：`tar -czf -- out.tar.gz` 构建失败，**带参数的选项内部顺序优先于 `--`**
3. `printf %q` 兜底

**glob 注入不需要 eval 也不需要分号**：传 `*` 作文件名，无引号 `cat $target` 会把目录下所有文件读一遍。

## 📋 退出码速查

| 码 | 含义 |
|---|---|
| 0 | 成功 —— **但 0 ≠ 真的成功** |
| 1 | 通用失败 / `grep` 无匹配 |
| 2 | **用法错误**（参数不对）；也是 `return` 在非 source 顶层的报错码 |
| 126 / 127 | 不可执行 / 命令未找到 |
| 128+N | 被信号 N 杀死（**与主动 `exit 143` 无法区分**） |
| 130 | SIGINT（仅纯计算脚本；等外部命令时是 **0**） |
| 139 | SIGSEGV（栈溢出，**stderr 零输出**） |
| 141 | SIGPIPE（管道后接 `head` 必现） |

**三个反直觉之处**：
- `$?` 只有 8 位 → `exit 256` 得到 **0**
- `$?` 只记最近一条命令，会被 `echo` 和赋值冲掉
- `pipefail` 报的是**最后一个非零**段，不是第一个失败段

## 🧰 取证命令速查

| 想看什么 | 命令 | 注意 |
|---|---|---|
| 语法 | `bash -n script.sh` | 不执行 |
| 展开后的命令 | `bash -x script.sh` | trace 走 **stderr** |
| trace 加上下文 | `PS4='+${BASH_SOURCE}:${LINENO}:${FUNCNAME[0]}: '` | **PS4 不做 printf 格式化**，`%(%H:%M:%S)T` 会原样输出字面量 |
| 子 shell 层级 | 看 `PS4` 首字符重复次数 | `+` 一层，`++` 两层。比显式写 `$BASH_SUBSHELL` 直观 |
| 严格模式状态 | `echo "$SHELLOPTS"` | ⚠️ **不要 `set +o`** |
| 装了哪些 trap | `trap -p` | WSL 下 `/proc/<pid>/status` 的 `SigIgn` 读不到（pid 命名空间受限），**只能靠这个** |
| 变量属性 | `declare -p var` | 看属性与类型 |
| 命令真实来源 | `type -a cmd` | 查 hash 缓存与解析顺序 |
| 管道各段退出码 | `rcs=("${PIPESTATUS[@]}")` | **紧跟管道，隔一行就没** |
| 后台任务退出码 | `wait $pid` | 裸 `wait` 能被 `set -e` 捕获，`if wait` 不能 |
| 锁被谁持有 | `ls -l /proc/*/fd 2>/dev/null \| grep "$L"` | 找孤儿进程 |
| 文件字节数 | `wc -c "$f"` | 别只看文件在不在 |

## ⚡ 三条取证纪律（会让结论完全相反）

1. **查严格模式别在命令替换里查** —— `set -e` 开着时，命令替换内 `set +o` 输出 `set +o errexit`（谎报 off），`$SHELLOPTS` 也**不含** `errexit`。根因是 `errexit` 不继承进子 shell，需 `shopt -s inherit_errexit`（实战项目 D6 实测）。**别只换取证命令——不开 `inherit_errexit`，命令替换内部的失败依然被吞**
2. **日志标签带尾空格** —— `printf '%-5s'` 补齐，`INFO` 实际是 `[INFO ]`。用 `grep '\[INFO\]'` **永远匹配不上**
3. **`set +x` 保护不了敏感信息** —— 顺序错了一样泄露：密码写在 `set +x` **之前**，明文已经进 trace 了。**先关 trace，再碰敏感数据**
