# 课 8 Calico 跨节点排障脚本

## 这是什么

2026-10-09 运维专项课 8 的排障取证链。背景是：**集群搭好了，但跨节点 Pod 100% 丢包**。

这 11 个脚本是一次完整的排障追踪，从现象出发逐层下探，直到定位决定性根因。
讲义里的结论全部来自它们的实际输出。

## 排障时间线

| 脚本 | 排什么 |
|---|---|
| `01-跨节点连通性初判.sh` | 确认故障现象：跨节点 Pod 是否真的不通 |
| `02-CNI与calico网卡诊断.sh` | CNI 配置、cali 接口是否存在 |
| `03-BGP对等状态诊断.sh` | calico-node 就绪探针失败原因、bird BGP 邻居 |
| `04-calico接口与路由诊断.sh` | calico 接口与路由表 |
| `05-抓包定位报文死在哪.sh` | 部署 netprobe DaemonSet，抓包定位报文丢失点 |
| `06-边抓包边ping同步诊断.sh` | 抓包与 ping 同步，避免时间错位误判 |
| `07-双节点同步抓包比对.sh` | 两节点同时 tcpdump，精确比对报文在哪一跳消失 |
| `08-切换VXLAN封装.sh` | 改 IPPool 从 IPIP 切 VXLAN |
| `09-VXLAN封装核验.sh` | 核验封装是否生效 |
| `10-VXLAN封装验收.sh` | VXLAN 方案验收 |
| `11-UDP4789决定性验证.sh` | **决定性**：直接测 UDP 4789 裸端口连通性 |

## 最值得看的一个

`11-UDP4789决定性验证.sh`——它不测 Calico，而是先用 `nc -u` 直连对端 4789 端口、抓包验证，并拿普通 UDP 端口（9999）做对照。

设计思路是 **先验证底层假设，再怀疑上层组件**：若 VXLAN 端口本身不通，任何封装方案都无效。这比"改配置看有没有好"可靠得多。

对应讲义里那条记住：**数字异常先怀疑测量方法**，以及 **探针状态 ≠ 实际可用**（calico-node 显示 0/1，但四项流量验收全过）。

## 怎么跑

脚本通过 SSH 连两台虚机（`192.168.122.19` / `192.168.122.54`），**虚机必须处于 running**。

```bash
wsl -- bash -lc "virsh list --all"   # 确认 k8s-cp1 / k8s-w1 在跑
wsl -- bash -lc "bash /mnt/d/projects/learning/k8s/子教程/运维专项/assets/课8-Calico排障/01-跨节点连通性初判.sh"
```

`08` 会**改集群 IPPool 配置**，属变更操作，跑之前先确认当前封装模式。

## 最终结论

封装失效 → 改为无封装（host-gw）解决。终态：跨节点 Pod 5/5 通、DNS ✅、Service 跨节点 ✅。
