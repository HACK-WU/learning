## 复杂度四门槛核查

> ⚠ **注**：课程设计要求「复杂度四门槛核查」，但仓库中**未定义**这四个门槛的具体内容。这是主 agent 的**可量化定义**——如与原设计不符，请覆盖。

| 门槛 | 判定标准 | 实测 | 通过 |
|------|---------|------|------|
| **① 数据规模** | ≥5 图层 × 各自 z_depth × ≥72 帧（3 秒 @24fps）| 6 图层 × z_depth[0..5] × 72 帧 | ✓ |
| **② 变换种类** | ≥5 种：平移/旋转/缩放/绕任意点/缓动/贝塞尔路径 | **8 种**：平移(视差)/摆动(正弦)/旋转/绕任意点旋转(手臂)/缓动/缩放/贝塞尔路径/跟随摆动 | ✓ |
| **③ 合成深度** | ≥5 层真实 z 排序 + 存在跨图层遮挡 | 6 层排序：草(z=5)遮主角(z=4) → 主角挡树(z=3) → 树在地面(z=2)上 | ✓ |
| **④ 交付验收** | MP4 + GIF 双格式 + ffprobe 全项通过 | 79,698 B + 1,092,584 B；分辨率/帧率/帧数/像素格式全 ✓ | ✓ |

**结论：全部通过 ✓**

## 一个意外的实证

跑完流水线后，得到一个**整门课最重要的对比**：

```
capstone.mp4    79,698 B     ←  H.264 + I/P/B 帧间压缩
capstone.gif 1,092,584 B     ←  LZW + 无帧间压缩
                            ─────────────
                            GIF 比 MP4 大 13.7×（同样的 3 秒）
```

**这不是 bug，是课 9 知识点 3 的现实验证**——

- 课程讲过「P/B 帧只存残差」「稳定画面压得小」
- 但只有跑完流水线、把同一个场景用两种格式各编一次，这个 13.7× 的数字才真正**长在你手里**
- **需求文档「帧间一致性」主张的工程意义**：不只是"好看"，是"压得动"

> 💡 如果你改 `ai_nodes.json` 让主角每帧随机跳色（人为制造"闪烁"），跑出来的 MP4 会**比现在大得多**——但 GIF 几乎不变。**这正是课 9 结尾那个 demo 的真实版本**。

## 修改建议（动手试）

| 改什么 | 预期看到 |
|--------|---------|
| `ai_nodes.json` 把 `character.path.p0` 改到 [60, 600] | 主角一帧就跑到画面外 |
| `ai_nodes.json` 删掉 `character.keyframes` 中的 `scale` 字段 | 主角不会呼吸/挤压，固定大小 |
| `animation_pipeline.py` 顶部 `ss = 2` 改成 `ss = 1` | 主角边缘明显锯齿（无抗锯齿） |
| `animation_pipeline.py` 把 `character` 的 z_depth 改成 1 | 主角跑到山后面去（被山遮） |
| `animation_pipeline.py` 把 `over` 公式改成 `a + dst`（漏写 `(1-a)`）| 画面瞬间过曝/颜色爆掉（过合成）|
| `ai_nodes.json` 删一个图层（如 `tree`） | 仍能跑通，但门槛③ 失败（5 层要求）|
| `encode()` 里把 `-crf 23` 改成 `-crf 5` | MP4 体积爆炸（~100 KB） |
