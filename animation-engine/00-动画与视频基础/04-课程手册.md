## 1. 整门课一句话

```
一段 2D 动画，在五个层面分别发生了什么：

  生理层   视觉暂留 + 似动现象 → 24fps 就够                课 1
  工业层   关键帧 + 中割 + 分层 → 用"画得少"降本            课 2-3
  数学层   矩阵 + 插值 + 缓动 + 贝塞尔 → 用"算"代替"画"      课 4-6
  渲染层   光栅化 + over 合成 + 深度排序 → 从公式到像素       课 7-8
  编码层   I/P/B 帧 + 码率 + 容器 → 从像素到文件             课 9-10
```

## 2. 全链路总图

```
AI 输出（需求文档数据）
  {matrix_data, z_depth, frame: 120}
        ↓
  ① 几何变换      3×3 齐次矩阵 · 缓动 · 贝塞尔路径        课 4-6
        ↓
  ② 光栅化        矢量 → RGBA 像素画布 + 超采样抗锯齿      课 7
        ↓
  ③ 合成          按 z_depth 排序 → 自底向上 over          课 8
        ↓
  ④ 编码          I/P/B 帧 + 码率预算 → H.264 码流         课 9
        ↓
  ⑤ 导出          ffmpeg → MP4 / GIF                      课 10
        ↓
  ⑥ 验收          ffprobe 核对帧数/分辨率/帧率/pix_fmt      课 10
        ↓
     视频文件 ✅
```

## 3. 核心速查（按阶段）

### 3.1 时间与帧（课 1-3）

| 项 | 公式 / 结论 |
|---|---|
| 帧号 ↔ 时间 | `t = frame / fps`，`frame = t × fps` |
| 一拍二 / 一拍三 | 一张画占 2 帧 / 3 帧（省画工）；动作片用一拍一 |
| 24fps 够用的原因 | 视觉暂留 + 似动现象，**不是**技术上限 |
| 间距 (spacing) | 相邻帧位置差；间距大 = 快，小 = 慢 |
| 档 | 帧号从 0 还是从 1 开始——**需求文档里凡是 `frame: N` 都要先问清** |

> ⚠ 课 1 强调过：`frame: 120` 是从 0 还是 1 数，是引擎里最常见的越界 bug 来源。

### 3.2 图形数学（课 4-6）

**矩阵**（3×3 齐次，课 5）：

```
平移 T(tx,ty) = [1 0 tx]      旋转 R(θ) = [cos -sin 0]     缩放 S(sx,sy) = [sx 0  0]
                [0 1 ty]                  [sin  cos 0]                    [0  sy 0]
                [0 0  1]                  [0    0   1]                    [0  0   1]

绕任意点 (px,py) 旋转  =  T(p) · R · T(-p)      ← 三步，顺序不可换
世界变换              =  T(pos) · R(angle) · S(scale)
```

| 项 | 结论 |
|---|---|
| 变换顺序 | **不可交换**，先旋转后平移 ≠ 先平移后旋转 |
| 齐次坐标 | 加一维把平移变成乘法，从而**用一个矩阵统一所有变换** |
| 屏幕坐标 | y 轴**向下**（与数学坐标相反）—— 所有"图上下颠倒"bug 的根源 |

**插值与缓动**（课 6）：

```
lerp(a, b, t) = a + (b - a) × t
ease_in_out_cubic(t) = 4t³  (t<0.5)  |  1 - (-2t+2)³/2  (t≥0.5)
三次贝塞尔 P(t) = (1-t)³P₀ + 3(1-t)²tP₁ + 3(1-t)t²P₂ + t³P₃
```

| 项 | 结论 |
|---|---|
| 弧长参数化 | 贝塞尔的 t **不等于**路程；要匀速必须按弧长重参数化 |
| 缓动 = 间距 | 十二原则的"间距"就是缓动函数，同一件事的两种说法 |

### 3.3 渲染与合成（课 7-8）

| 项 | 公式 / 结论 |
|---|---|
| **over 运算符** | `out = src·α + dst·(1-α)` —— **精确公式，不是"半透明效果"** |
| over 交换律 | **不满足**。`over(a,b) ≠ over(b,a)`，后画的层一定在上 |
| 边界 | α=0 → 完全 dst；α=1 → 完全 src |
| 预乘 alpha | 存储 `rgb×α` → 插值 → 反算 `rgb/α`。**解决缩放脏边** |
| 脏边根因 | 透明像素 RGB（常为 0,0,0）被插值算进去 |
| 光栅化 | 连续公式 → 离散像素网格，锯齿是**本质产物**不是 bug |
| 画家算法 | 整层一个 z，循环重叠时**必败**（实测画错 48.2%） |
| **z-buffer** | 逐像素比较，**永远正确**，代价是多一份 W×H 深度内存 |
| z-fighting | 三条件同时满足：几乎共面 + 深度精度有限 + 微小扰动 |
| 极端颜色标签 | `R=255,G=0,B=0` 机器零歧义判定（**不是因为红色好看**） |

**sRGB ↔ 线性**（课 8）：

```
sRGB → linear :  c ≤ 0.04045 ? c/12.92 : ((c+0.055)/1.055)^2.4
linear → sRGB :  c ≤ 0.0031308 ? c×12.92 : 1.055×c^(1/2.4) - 0.055
```

> ⚠ **凡"求平均"的操作都要在线性空间做**：alpha 合成、模糊、缩放插值、渐变。
> 经典证据：黑白 50/50 混合，sRGB 直接混 = **128**，线性混 = **188**（差 60 灰阶）。

### 3.4 编码与导出（课 9-10）

| 项 | 公式 / 结论 |
|---|---|
| 总帧数 | `fps × 时长(s)` |
| 原始字节 | `W × H × 4(RGBA) × 总帧数` |
| 文件大小 | `码率(bps) × 时长(s) ÷ 8` |
| 三角关系 | 分辨率 / 帧率 / 码率互相挤压；**码率是根本约束** |
| GOP | 两个 I 帧的间隔。大 → 小体积/拖拽慢；小 → 大体积/拖拽快 |
| I / P / B 帧 | I=完整图像；P=与前一帧残差；B=与前后两帧残差（最小） |
| 帧间压缩 | **奖励稳定、惩罚闪烁** |
| 容器 vs 编解码器 | `.mp4`=盒子，H.264=装法；**两者独立** |
| GIF 硬限制 | **256 色** + **1-bit 透明**（无半透明） |
| 真 alpha 视频 | 用 **WebM/VP9**；主流 H.264/HEVC 的 MP4 **不支持** |

## 4. 需求文档术语对照表

> **这是本手册最有价值的一节**——对应学习目标："能看懂并校验需求文档里的每一个术语"。
> 左列 = 需求文档里可能出现的写法；右列 = 它在本课程中的确切含义与出处。

| 需求文档术语 | 确切含义 | 出处 | 校验要点 |
|---|---|---|---|
| `frame: 120` | 帧号（律表的行号） | 课 1-2 | ⚠ **必须先确认从 0 还是从 1 开始数** |
| `matrix_data` | 变换矩阵（3×3 齐次） | 课 5 | 平移/旋转/缩放的复合，顺序不可交换 |
| `z_depth` | 深度值，决定合成顺序 | 课 8 | 数字越大越靠前；需按它排序后自底向上 over |
| `分层矩阵` | 多个独立 RGBA 图层 + 各自 z 值 | 课 2、课 8 | 赛璐珞分层的数据化版本 |
| `关键帧` / `中间帧` | 关键帧 = 原画；中间帧 = 中割/插值 | 课 2、课 6 | 能自动补的是**缓动+弧线+节奏**；**预备/挤压/夸张**不能完全自动 |
| `动画插值` | lerp + 缓动函数 | 课 6 | 位置可插值，艺术表现力不可 |
| `分部位独立生成` | 各部位独立图层 + group | 课 8 | group 可整组移动/显隐/改不透明度 |
| `按 Z 轴排序` | 渲染时按 z_depth 排序后合成 | 课 8 | 简单场景画家算法够用；**复杂场景必须 z-buffer** |
| `Z-Buffer` | 逐像素深度比较 | 课 8 | 解决"跨图层穿帮"；注意 z-fighting 规避 |
| `语义标签` / 极端颜色 | `R=255,G=0,B=0` 等零歧义通道约定 | 课 8 | 机器可判定，不含 AI 推理 |
| `帧间一致性` | 相邻帧画面稳定 | 课 9 | ⚠ **不只是好看，更是压缩率的前提**（闪烁 → 残差≈噪点 → 压不动） |
| `自动平滑` | 贝塞尔曲线拟合折线 | 课 6 | 把锯齿折线变成平滑线条 |

**需求文档第七节的原文引用**（课 1/2/7/8 一致引用）：

> "到了第 120 帧，软件瞬间从内存中抓取所有标记为 `frame: 120` 的矩阵，**按 Z 轴深度排序**，一次性渲染到屏幕上"

> ⚠ **待核对**：阶段 3 overview 里写的是"需求文档**第 3 节**"，与本表及课 1/2/7/8 的"**第七节**"不一致。已按多数证据（带原文的课 1/2）统一为第七节，overview 那处保留未改，**待你核对 docx 后确认**。

## 5. ffmpeg / ffprobe 参数速查

### 帧序列 → MP4（课 10 核心命令）

```bash
ffmpeg -y \
  -framerate 24 \            # 输入帧率（先于 -i）
  -i frames/frame_%04d.png \ # %04d 零补位，不补零会跳帧
  -c:v libx264 \             # H.264 编码
  -pix_fmt yuv420p \         # 不写→yuv444p，QuickTime 打不开
  -crf 23 \                  # 恒定质量，18~28 常用，23 是甜点
  -movflags +faststart \     # moov 头前移，网页边下边播
  output.mp4
```

### 帧序列 → GIF（两遍调色板法）

```bash
ffmpeg -y -framerate 12 -i frames/frame_%04d.png \
  -filter_complex "[0:v] split [a][b];[a] palettegen=max_colors=256 [p];[b][p] paletteuse=dither=bayer" \
  -loop 0 output.gif
```

### ffprobe 验收（一行核对完）

```bash
ffprobe -v error -select_streams v:0 -count_frames \
  -show_entries stream=width,height,r_frame_rate,nb_read_frames,codec_name,pix_fmt \
  -show_entries format=duration,size,bit_rate \
  -of default=noprint_wrappers=1 output.mp4
```

| 参数 | 坑 |
|---|---|
| `-framerate N` | 先于 `-i`，表示"按 N fps 读图" |
| `%04d` | **不补零 = 跳帧**（字典序：frame_10 在 frame_2 前）|
| `-pix_fmt yuv420p` | 不加则默认 yuv444p，**QuickTime / iOS / Safari 打不开** |
| `-movflags +faststart` | 不加则 moov 在尾部，**网页必须下完才播** |
| `-count_frames` | 真解码数帧，**准但慢**；不加则从容器元信息读，可能不符 |
| `-loop 0` | GIF 无限循环 |

## 6. 单位与换算

| 量 | 换算 |
|---|---|
| 1 MB（存储） | 1024² = 1,048,576 B |
| 1 MB（码率厂商） | 常按 1000² = 1,000,000 B 计 |
| bit ↔ byte | **1 byte = 8 bit**（最易错）|
| 1 Mbps × 10 s | = 10,000,000 bit ÷ 8 = 1.25 MB |
| RGB 每像素 | 3 B；**RGBA 每像素 4 B** |
| 1080p RGBA 单帧 | 1920×1080×4 = 8,294,400 B ≈ 7.9 MB |
