# 05 · 排障速查手册

> **定位**：本仓库脚本在本机跑通过程中真实踩到的坑，**每条都有一手证据**（报错原文 / 异常现象 / 修复方式）。
> 对应：Phase 5「实战经验 / 排障速查手册 / 场景解法库」的**排障**部分。
> 适用环境：Windows 11 + 中文 locale + PowerShell + uv 创建的 venv（Python 3.12）
>
> **用法**：按症状查表，不要从头读。每条格式统一为 `症状 → 根因 → 修复 → 证据`。

---

## 0. 两条元原则（比下面任何一条都重要）

### 元原则一：脚本能跑 ≠ 演示有效

本轮最隐蔽的几类问题，脚本**全部零报错跑通**，但演示完全没效果：

| 现象 | 脚本状态 | 实际 |
|---|---|---|
| 预乘 alpha 脏边对比图，左右两张**看起来一样** | 正常退出 | 硬边圆插值带只有 1 原像素宽，脏边肉眼不可辨 |
| 极端颜色标签的**反例**，命中数与正例完全相同（5420 = 5420）| 正常退出 | 场景里没有"接近红"的真实内容可供误伤 |
| 帧序列只生成了 `frame_000` 和 `layer_stack` | 无报错 | 进程被 PowerShell 提前杀掉了 |

> **检查习惯**：跑完脚本后，必须**打开产物图 / 数产物文件**，确认"效果真的出现了"，而不是只看退出码。

### 元原则二：报错先怀疑是"假象"

这个仓库路径含中文，而 PowerShell 与 git / Python 之间的编码不一致，会**凭空制造报错**：

| 假报错 | 真相 |
|---|---|
| `Test-Path` 说 10 个课文链接**全部 BROKEN** | 链接全部有效；PowerShell 把中文字面量按 GBK 传出去，路径被破坏 |
| `git: pathspec '...00-鍔ㄧ敾...' did not match` | 路径真实存在；同样是 GBK/UTF-8 不一致 |

> **验证习惯**：中文路径相关的报错，改用**不含中文的手段**复核（如文本比对、`git -c core.quotepath=false`）。

## A. 环境与工具链（最高频、最耗时）

### A1. `Select-Object -First N` 会杀掉未跑完的 Python 进程

- **症状**：脚本只产出一部分（如 24 帧里只有 `frame_000` + 1 张图），但**没有任何报错**
- **根因**：PowerShell 管道在收满 N 行后**关闭管道**，上游 Python 进程被终止
- **修复**：长脚本**不要**用 `Select-Object -First N` 截断输出。要么完整输出到文件再读，要么只对**已完成的输出**做截取：
  ```powershell
  # 错：会杀进程
  & python script.py | Select-Object -First 3

  # 对：先完整落盘
  & python script.py | Out-File -FilePath out.log -Encoding UTF8
  Get-Content out.log | Select-Object -First 3
  ```
- **证据**：课 8 第一批，产物时间戳显示仅 `frame_000` 与 `layer_stack` 更新，其余仍是上一轮时间

### A2. uv 创建的 venv **没有 pip**

- **症状**：`python -m pip install X` → `No module named pip`
- **根因**：venv 由 uv 0.11.11 创建（`pyvenv.cfg` 里 `uv = 0.11.11`），**不含 pip**
- **修复**：用 `uv pip install`：
  ```powershell
  uv pip install --python ".<venv>\Scripts\python.exe" <包名>
  ```
- **证据**：课 10 装 `static-ffmpeg` 时首次遇到

### A3. Windows 中文 locale 下 subprocess 的 GBK 解码崩溃

- **症状**（后台线程，不影响结果但满屏堆栈）：
  ```
  Exception in thread Thread-4 (_readerthread):
    File "...\subprocess.py", line 1599, in _readerthread
      buffer.append(fh.read())
  UnicodeDecodeError: 'gbk' codec can't decode byte 0xa7 in position 54
  ```
- **根因**：`subprocess.run(..., text=True)` **不指定 encoding** 时，按 `locale.getpreferredencoding()`（中文 Windows = cp936/GBK）解码；而 ffmpeg 输出含非 GBK 字节
  - 说明：我自己的调用都指定了 `encoding="utf-8", errors="replace"`，**不会**触发；本条来自第三方库 `static_ffmpeg` 的内部调用
- **修复（自己写的代码）**：永远显式指定
  ```python
  subprocess.run(cmd, capture_output=True, text=True,
                 encoding="utf-8", errors="replace")   # ← 关键
  ```
- **修复（第三方库触发时）**：绕开它的 API，直接 glob 二进制：
  ```python
  import static_ffmpeg
  base = Path(static_ffmpeg.__file__).parent / "bin"
  ffmpeg  = sorted(base.rglob("ffmpeg.exe"))[0]
  ffprobe = sorted(base.rglob("ffprobe.exe"))[0]
  ```
- **证据**：课 10，绕开 API 后 stderr 行数 5 → **0**

### A4. fd 级 stderr 重定向**无效**（异常在恢复之后才抛）

- **症状**：用 `os.dup2(devnull, 2)` 包住调用，异常堆栈**照样打印**
- **根因**：异常发生在**后台 reader 线程**，线程真正抛出时上下文管理器已经退出、fd 2 已恢复
- **修复**：不要试图压制线程异常，改为**从源头避免触发**（见 A3 的 glob 方案）
- **证据**：课 10 先试过 fd 重定向，确认无效后才改用 glob

### A5. PowerShell 中文路径传给 git 永远匹配不上

- **症状**：
  ```
  git add "animation-engine/00-动画与视频基础"
  → fatal: pathspec 'animation-engine/00-鍔ㄧ敾...' did not match any files
  ```
- **根因**：PowerShell 按 **GBK** 编码传参，git 按 **UTF-8** 解析
- **修复**：**cd 进目录后用 `.`**，不要在命令里写中文路径
  ```powershell
  $c = Get-ChildItem -Path "d:\projects\learning\animation-engine" -Directory | Select-Object -First 1
  Set-Location $c.FullName      # 中文部分由文件系统给出，不经手写
  git add --dry-run --all .
  ```
  读取时可用 `git -c core.quotepath=false` 让输出可读（**只解决显示，不解决传参**）
- **证据**：配置 .gitignore 时反复遇到

### A5b. git pathspec 里的通配符匹配不到中文目录名

- **症状**：同一目录，用全名能列出 52 项，用通配符却是 0 项
  ```
  git status --porcelain -- "animation-engine/"        → 52 行
  git status --porcelain -- "animation-engine/00-*/"   → 0 行   ← 静默返回空
  ```
- **根因**：pathspec 含 `*` 时，git 需拿它与磁盘上的中文目录名做匹配，在 GBK/UTF-8 不一致的环节失败
- **危害**：**静默返回空**，不报错——极易误判为"该目录没有未提交文件"，从而跳过整轮卫生检查
- **修复**：中文路径段**不要用通配符**，二选一
  1. 用不含中文的上级目录收窄：`git status --porcelain -- "animation-engine/"`
  2. cd 进该目录后用相对路径（路径段本身是 ASCII 时可行）：
     ```powershell
     $c = Get-ChildItem -Path "animation-engine" -Directory | Select-Object -First 1
     Set-Location $c.FullName
     git status --porcelain -- "playground/lesson-01/"   # 段名是 ASCII，可匹配
     ```
- **证据**：2026-09-02 卫生检查实测，`animation-engine/` 52 行 vs `animation-engine/00-*/` 0 行

### A6. 系统没有 ffmpeg / ffprobe 时的最小侵入装法

- **症状**：需要 ffmpeg 但系统未装
- **修复**（不污染系统、不改 PATH）：
  ```powershell
  uv pip install --python ".<venv>\Scripts\python.exe" static-ffmpeg
  ```
  首次运行会下载约 50 MB 静态二进制，落在 venv 内
  - `imageio-ffmpeg` **只含 ffmpeg，没有 ffprobe**——需要 ffprobe 时不能只装它
- **证据**：课 10；`static-ffmpeg` 提供 ffmpeg 8.0.1 + ffprobe，`imageio-ffmpeg` 提供 ffmpeg 7.1 但无 ffprobe

## B. PIL / Python / 图像生成

### B1. `repeat(3)` 把 3 通道数组变成 9 通道

- **症状**：`TypeError: Cannot handle this data type: (1, 1, 9), |u1`
- **根因**：数组**已经是** `(H, W, 3)`，却再 `np.repeat(x, 3, axis=2)` → `(H, W, 9)`
- **修复**：转图前先确认通道数；已经是 3 通道就直接 `Image.fromarray(arr)`
- **证据**：课 8 第二批 `srgb_vs_linear`

### B2. PIL 绘制宽度 / 坐标必须是整数

- **症状**：`TypeError` 或绘制结果异常（某些版本静默出错）
- **根因**：`width=`、`line()` 坐标传了 float
- **修复**：`int(round(...))`
- **证据**：课 5 首批发现，课 6 第二批**复发**

### B3. RGB 画布 `fill` 传了 4 元组

- **症状**：颜色异常 / TypeError
- **根因**：`Image.new("RGB", ...)` 的画布，`fill` 却给了 `(r,g,b,a)`
- **修复**：RGB 画布给 3 元组；需要 alpha 就用 `Image.new("RGBA", ...)`
- **证据**：课 5 第一批

### B4. 双引号字符串里嵌直角双引号 → SyntaxError

- **症状**：
  ```
  SyntaxError: invalid syntax. Perhaps you forgot a comma?
  ```
- **根因**：`"预乘 alpha：解决..."脏边"伪影"` —— 内层 `"` 提前闭合了字符串
- **修复**：内层改用中文引号 `「」` 或 `『』`
- **证据**：课 4（ASCII 引号）、课 8 第二批（中文引号）各一次

### B5. SVG 文本里出现 `</` 会被解析成结束标签

- **症状**：XML 校验失败：`名称不能以"<"字符(十六进制值 0x3C)开头`
- **根因**：我在 `<text>` 内容里写了 `P₀</`，`</` 被当作结束标签起始，与后面的 `</text>` 拼成非法的 `</</text>`
- **修复**：文本内容里**不要出现裸 `<`**；要显示就写 `&lt;`
- **证据**：课 7，5 处，用正则批量修复

### B6. emoji 在无 emoji 字体下渲染成 □

- **症状**：`✅ / ❌` 在 PIL 生成的图里显示成方框
- **根因**：当前字体（微软雅黑等）不含这些 emoji 字形
- **修复**：改用文本符号 `[✓] / [✗]` 或 `✓ / ✗`
- **证据**：结课实战验收报告

## C. 布局与渲染

### C1. 底部文字被裁（画布太矮）

- **症状**：最后一行只露出上半截
- **根因**：末行 `y` 坐标 + 字高 > 画布高度
- **修复**：算出末行实际占位后加高画布
  - `params_calculator.png`：430 → **460**（末行在 y=438）
  - `gif_palette.png`：340 → **360**（末行 y=332 + 字高）
  - `pipeline_report.png`：400 → **460**（③④ 节重叠）
- **证据**：课 9、课 10、结课实战各一次

### C2. 元素画到画布外（被静默裁剪）

- **症状**：图的一部分消失，**不报错**
- **根因**：`paste` / `rectangle` 的坐标超出画布；PIL 静默裁掉
- **修复**：画之前核对 `x + w ≤ 画布宽`、`y + h ≤ 画布高`
  - `resolution_ramp`：参照图 280+240=520 > 画布 400
  - `vector_scaling`：第四瓦片 500+150=650 > 画布 620
  - `painters_vs_zbuffer`：差异图 y=350 > 画布 330
- **证据**：课 7、课 8 第二批

### C3. 文字 / 图元重叠

- **症状**：两段文字叠在一起，或进度条压住标签
- **根因**：`y` 坐标没算上前一行的高度
- **修复**：后画的在前画之后（PIL 无 z 序），且手动留出行距（一般 ≥ 16px）
- **证据**：课 8 第一批两处（副标题压标签 / 进度条压 "over 结果"）

## D. 演示有效性（脚本零报错，但看不出效果）

### D1. 预乘 alpha 的"脏边"根本看不见

- **症状**：非预乘 vs 预乘两张图**看起来一样**
- **根因**：用了**硬边圆** + 3× 缩放。BILINEAR 的插值带只有 **1 个原像素宽**，放大后脏边极淡
- **修复**：必须用**软边圆**（边缘留 6px 的 alpha 渐变）+ 更大缩放（4×）
- **验证**：修复后取证——非预乘边缘 RGB=(218,39,39) vs 预乘 (232,39,39)，**暗 14**
- **证据**：课 8 第一批

### D2. 反例与正例的结果完全相同

- **症状**：严格阈值命中 5420，**放宽阈值也命中 5420**——反例形同虚设
- **根因**：测试场景里**没有**"接近红但非纯红"的真实内容可供误伤
- **修复**：补一个暗棕红 `(180,60,50)` 方块（严格阈值不命中、宽松阈值会误判）
- **验证**：修复后反例多命中 **1,978** 像素
- **证据**：课 8 第二批

## E. 内容准确性（不是 bug，但会误导）

### E1. 史实 / 术语错误（本轮 2 次，都已联网核查后修正）

| 错误写法 | 正确 |
|---|---|
| 「1原/2原」= 画几张关键帧 | 实为**原画工序的两个阶段**（1原草稿、2原清稿） |
| 多平面摄影机能机械拍出中间帧 | 它做**视差**，不能插值；中割靠人/算法 |

> **纪律**：凡是带人名、年份、专利、片名的陈述，**先查再写**。本轮已核查：Earl Hurd 1914 赛璐珞专利、1937《老磨坊》、Sutherland 1963 Sketchpad、Cayley 1858 矩阵论文、Johnston & Thomas 1981、H.264/AVC 2003、MPEG-1 1993。

### E2. 手算数值错误

- **症状**：Q1 答案写 3.6 MB
- **根因**：1280×720 RGBA = 3,686,400 B ÷ 1024² = **3.516 MB**，凑整应为 3.5 而非 3.6
- **修复**：重算选项与解析，并补上「bit 与 byte 差 8 倍」的提醒
- **证据**：课 7

### E3. `z_depth` 顺序写反

- **症状**：地面盖住了主角
- **根因**：初版把 `ground` 放在 z=5（最大）
- **修复**：重排为 `sky(0) → mountains(1) → ground(2) → tree(3) → character(4) → grass(5)`
- **证据**：结课实战

## F. 场景解法库（只收有真跑结果的）

### F1. 从 AI 矢量节点到可播放视频（端到端）

- **场景**：拿到一组 `{matrix_data, z_depth, frame}` 节点数据，要产出可双击播放的视频并验证
- **解法**：见 [03-结课实战项目.md](03-结课实战项目.md)，流水线为
  `数据解析 → 几何变换 → 光栅化 → z 排序合成 → ffmpeg 编码 → ffprobe 验收`
- **实测结果**：6 图层 × 72 帧 @24fps → MP4 79,698 B（h264/yuv420p/640×480/3.0s）+ GIF 1,092,584 B；四门槛全过
- **踩坑记录**：E3（z 序）、贝塞尔路径飞出画面、B6（emoji）
- **意外产出**：同场景 GIF 比 MP4 大 **13.7×** —— 课 9「GIF 无帧间压缩」的现实验证

> 其余"场景"未收录，因为 10 课正文的**第四幕**与 [04-课程手册.md](04-课程手册.md) 已覆盖；重复收录无价值。

## G. 关于「实战经验」为什么没写

Phase 5 原定三项：**实战经验 / 排障速查手册 / 场景解法库**。

**「实战经验」未编写，理由**：仓库中该词**没有任何定义与验收标准**。在无定义约束下撰写，产出大概率是"要注意细节""多动手"这类无法验证的泛泛之谈，对本课程是负资产。

Phase 5 要求「**证据纪律核查**」——主张必须有证据支撑。以此筛选：
- 排障速查手册 → 每条都有一手证据 → **做**（本文档）
- 场景解法库 → 只收有真跑结果的 → **做**（F1）
- 实战经验 → 无证据可依 → **不做**

若后续给出「实战经验」的明确定义与验收标准，可补写。
