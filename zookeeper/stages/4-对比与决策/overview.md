# 阶段 4 · 对比与决策（L9–L12）

> [课程目录](../../02-课程目录.md) · 上一阶段：[阶段 3 · 成本与风险](../3-成本与风险/overview.md)

## 阶段目标

前三阶段回答了"ZK 是什么、凭什么可靠、要付什么代价"。这一阶段把 ZK 放回真实的技术选型现场：**和竞品怎么比、生态往哪走、最终怎么选、怎么向团队汇报**。终点产物是一份能拿去开会的《协调服务选型决策》。

## 阶段主线

```text
L9  摆正四个候选的定位 → 同维度横拉对比表 → ZAB 与 Raft 的真实差异
     ↓（带着"ZK 的真实脾气"去比）
L10  看一个真实的用脚投票案例：Kafka 为什么去 ZK、KRaft 是什么、社区现状如何
     ↓（看清生态走向）
L11  落成一棵可复用的选型决策树 + 成本收益清单 + 汇报要点
     ↓
L12  在三个真实场景（注册中心 / 配置管理 / 分布式锁）里跑一遍决策树
     ↓
终点产物：《协调服务选型决策》
```

## 完成标志（阶段 4 结束时）

- 能说清 ZK / etcd / Consul / Redis 各自的定位与"人格"，不为"谁更强"争吵
- 能用关键维度对比表解释"为什么 K8s 选 etcd、为什么秒杀锁不选 ZK"
- 能讲清 ZAB 与 Raft 的异同，并知道**不要把协议差异当选型依据**
- 能说清 Kafka 去 ZK 的时间线与动机（KRaft），以及这对 ZK 生态位意味着什么
- 能用选型决策树为给定场景给出有依据的结论，并向团队讲清楚理由
