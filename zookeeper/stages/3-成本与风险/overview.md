# 阶段 3 · 成本与风险

> 用它要付出什么 · L7–L8 · 预计 1–2 小时

## 阶段目标

学完本阶段，你能用自己的话回答：

1. 服务端成本：几台机器、什么规格、磁盘怎么配——为什么"专用日志盘"是唯一值得花大钱的地方
2. 数据目录的生命周期：事务日志（WAL）与快照怎么配合、怎么清理、怎么备份恢复
3. 日常值守：盯哪些指标（fsync/latency/watch/连接/选举）、变更走什么规程（滚动重启/reconfig）
4. 客户端成本（L8）：Watch 风暴、Session 超时故障、常见反模式——服务端没错时，事故从哪来

## 故事位置

机制学完、配方跑通，公司正式立项生产集群。你从"它怎么工作"进入"养它要花什么"：先算服务端的账（机器、磁盘、值守），再复盘客户端的坑（Watch 风暴、Session 事故、反模式）——成本与风险看全，选型决策才有底。

## 完成标志

- 能独立审一份 ZK 采购/部署方案（台数、规格、磁盘布局、故障域）并指出问题
- 能说出生产必改的三个默认值（autopurge、4lw 白名单、reconfig）及其理由
- 能列出 ZK 的核心监控指标并各对应一句"出问题说明什么"
- 能说清 Watch 风暴与羊群效应的区别与联系，并给出各自的治法
- 能画出 Session 超时的四大诱因排查树，并区分 CONNECTION_LOSS 与 SessionExpired 的处置差异
- 能对照反模式清单自查客户端实现（当数据库 / 轮询 / 回调干重活 / 断连就重建 / 超时过小 / 不测故障）
