# 阶段 0 · 上手篇

> 先跑起来，再谈原理 · L0.1–L0.3 · 预计 90–120 分钟（含动手）

## 阶段目标

学完本阶段，你能**亲手**做到：

1. 在自己机器上从零装好并启动一个 ZooKeeper（单机模式），会用三种方式确认它活着
2. 用 zkCli 独立完成增删改查，亲手创建四种节点类型，亲手触发版本冲突与典型报错
3. 用 Python 的 kazoo 客户端写出带**连接状态监听**的程序，实现配置监听与服务注册发现

## 为什么有这个阶段

原有的 L1–L12 是**决策参考导向**的机制课：重在讲清"是什么、为什么、怎么选型"，实操环节以纸面推演为主。**它默认读者已经能把 ZK 跑起来、手上有基本手感。**

如果你是零基础，这个前提不成立——读完 L3 你知道 `create -e` 是临时节点，但**从没亲手建过一个**；读完 L5 你知道 Watch 是一次性的，但**从没收到过一条通知**。知识是飘着的。

本阶段就是把这个前提补齐：**先让手熟，再让脑通。** 三课只教"怎么做"和"看到什么"，把"为什么是这样"留给后面各课——带着亲手撞过的报错去学原理，记忆会牢得多。

> 📌 **已有基础？可以跳过。** 如果你已经装过 ZK、用过 zkCli 或任一客户端库，直接从 [L1](../1-问题与定位/lessons/lesson-01-为什么需要ZooKeeper.md) 开始即可，遇到想亲手验证的地方再回来查 [L0.3 的实验地图](lessons/lesson-0-3-Python客户端kazoo入门.md)。

## 故事位置

评审会上那句"这东西你自己跑过吗"问住了你。报告里写满了 ZAB、过半派、临时节点，但你一次都没装过。

于是你花一个下午：装好、连上、把增删改查走一遍、写下第一段能跑的 Python 代码。**当你在两个终端之间看着临时节点随进程退出而自动消失时，L1 那场双主故障突然变得具体了**——原来"不需要注销接口"是这个意思。

带着这份手感，你重新开始读那份报告。

## 完成标志

- 你的机器上有一个可以随时启动的 ZK，`zkServer.sh status` 能看到 `Mode: standalone`
- 你能不看文档敲出四种节点的 `create` 命令，并说清 `Node not empty` / `version No is not valid` 分别在防什么
- 你写过一段带 `add_listener` 的 kazoo 程序，并亲眼见过 `LOST` / `SUSPENDED` 状态
