# 阶段 1 · SQL 与关系基础

> 故事章节：「把业务装进结构」——主角一行订单，第一次有了"表"这个家

## 阶段目标

本阶段结束时，你能装好 PostgreSQL、建出规范的表、用标准 SQL 完成日常查询与基本的关联。**为后续建模、索引、并发、运维打地基**。

## 学习重点

1. **看清架构**：PG 的 cluster / database / schema / table 层级——很多人用了几年 PG 都没分清这四层
2. **建得规范**：选合适的数据类型与约束（NOT NULL / UNIQUE / CHECK / DEFAULT / 主键）
3. **写得正确**：SQL 语法准确，能写带过滤、排序、聚合的多表查询

## 必须掌握的知识点

| 课 | 知识点 |
|---|---|
| 课 1 认识 PostgreSQL | 1.1 PG 是什么 · 1.2 安装与工具链 · 1.3 数据库与模式层级 |
| 课 2 表与数据类型 | 2.1 常用数据类型 · 2.2 建表语法与约束 · 2.3 CRUD 基础 |
| 课 3 查询基础 | 3.1 WHERE/ORDER BY/LIMIT · 3.2 JOIN 家族 · 3.3 聚合与 GROUP BY |

## 本阶段在故事主线中的章节定位

阶段 1 是整个故事的「**起**」——主角（一条订单）出生、被插入第一行。读者（你）在这一章获得"能与 PG 对话"的能力。没有这个能力，后面的索引、事务、运维全是空中楼阁。

## 阶段内闭环

装库 → 建表 → 查数据。**学完课 3 后，你应该能独立用 Docker 起一个 PG 容器、建一张订单表，写 5 条不出错的查询**。

## 学习节奏

- 本阶段 9 知识点，建议 **3–5 天** 完成
- 每课配套实操，**实操 ≥ 50%**（本阶段以跑通命令为主，不深讲原理）

## 阶段产出物

学完本阶段后，你应有：

- 一台本机可用的 PG（Docker 容器即可）
- 一个 `order_service` 数据库
- 一张能正常 CRUD 的 `orders` 表
- 5+ 条不出错的常见查询（列表 / 详情 / 统计）
