# 阶段 3 · 索引与查询优化

> 故事章节：「让查询飞起来」——主角一行订单淹没在亿级表里，全表扫描 30 秒，故事进入性能章节

## 阶段目标

本阶段结束时，你能：

1. **说清**：B+Tree / Hash / GIN / BRIN 各索引的适用场景
2. **看穿**：读懂 EXPLAIN 输出，能定位慢 SQL 的瓶颈节点
3. **修好**：用重写 SQL + 调整索引 + 更新统计信息三件套修好一条慢查询

## 学习重点

1. **底层**：B+Tree 的页 / 分裂 / 顺序 IO 与组合索引的最左前缀
2. **EXPLAIN**：cost / rows / 计划树 + 常见算子语义
3. **优化实务**：慢查询日志 + 索引陷阱 + SQL 重写模式

## 必须掌握的知识点

| 课 | 知识点 |
|---|---|
| 课 8 索引原理 | 8.1 B+Tree 索引原理 · 8.2 Hash / GIN / BRIN 适用场景 · 8.3 组合索引与最左前缀 |
| 课 9 执行计划 | 9.1 EXPLAIN 读懂 · 9.2 常见算子 · 9.3 统计信息与 ANALYZE |
| 课 10 慢查询优化实战 | 10.1 慢查询日志 · 10.2 索引陷阱 · 10.3 重写 SQL 的常见模式 |

## 本阶段在故事主线中的章节定位

主角遇到"性能瓶颈"——数据量从万涨到亿，订单列表页从 100ms 涨到 30s。这是数据库领域最经典的"从能用走向用好"的分水岭。读者从此成为"写过性能优化"的人。

## 本阶段路径图

```
理解索引的数据结构（B+Tree / Hash / GIN / BRIN）
   │
   ├─→ 读懂 EXPLAIN（计划树 + cost + rows）
   │
   └─→ 上手实战
         ├─ 慢查询日志定位
         ├─ 索引陷阱诊断
         └─ SQL 重写模式
```

## 阶段内闭环

看懂原理 → 看懂计划 → 修好实例。**学完课 10 后，你应该能独立拿到一条慢 SQL，在 30 分钟内定位瓶颈并给出修复方案**。

## 学习节奏

- 本阶段 9 知识点，建议 **4–5 天** 完成
- 每课必有 EXPLAIN 实操，**实操 ≥ 50%**
- 阶段末有"慢 SQL 修复演练"

## 阶段产出物

学完本阶段后，你应有：

- 一张亿级模拟表（用 `generate_series` 灌 1000 万行）

- 1 份"慢查询修复报告"模板
