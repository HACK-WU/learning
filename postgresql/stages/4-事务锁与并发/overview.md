# 阶段 4 · 事务/锁与并发

> 故事章节：「多请求不打架」——订单系统一上线，库存超卖、超扣、双花，事故频发，故事进入并发章节

## 阶段目标

本阶段结束时，你能：

1. **说出**：ACID 是什么、PG 提供哪些隔离级别、各自会出什么并发问题
2. **画出来**：MVCC 的 `xmin` / `xmax` / 死元组 / autovacuum 是怎么工作的
3. **定位**：遇到锁等待 / 死锁，能用 `pg_stat_activity` / `pg_locks` 排查

## 学习重点

1. **隔离级别**：从脏读 / 不可重复读 / 幻读三个并发问题反推隔离级别的差异
2. **MVCC 原理**：`xmin/xmax` 隐藏列、可见性规则、autovacuum
3. **锁机制**：表锁 vs 行锁、显式锁、咨询锁、死锁排查

## 本阶段在故事主线中的章节定位

这是故事的"黑暗章节"——所有看似美好的功能在并发下都崩塌。读者通过这一章学到"并发正确性"的本质——这不是语法而是数学。

## 本阶段路径图

## 阶段内闭环

认识战场 → 看懂武器 → 救火。**学完课 13 后，你应该能用 psql 模拟一个超卖场景 + 给出修复（SELECT FOR UPDATE / SERIALIZABLE）**。

## 学习节奏

- 本阶段 12 知识点，建议 **5–6 天** 完成
- 每课设置"故意搞砸的小实验"（如两个终端同时 UPDATE）
- **实操 ≥ 50%**，概念 ≥ 50%——并发的真意只能动手体验

## 阶段产出物

学完本阶段后，你应有：

- 一个用两个 psql 会话复现的超卖场景
- 三种修复方案的对比（无并发控制 / SELECT FOR UPDATE / SERIALIZABLE）
- 一份"长事务排查清单"
