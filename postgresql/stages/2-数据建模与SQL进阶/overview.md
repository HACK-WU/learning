# 阶段 2 · 数据建模与 SQL 进阶

> 故事章节：「把表组织成系统」——一笔订单开始牵连出订单明细、用户、商品，故事从「一张表」变成「一群关系」

## 阶段目标

本阶段结束时，你能：

1. **设计**：为一个业务域（订单 / 用户 / 商品）设计表结构，**说清**为什么这种关系
2. **重用**：用视图、函数、触发器把常用逻辑固化
3. **写复杂查询**：CTE、递归、窗口函数全都会用，且能选对工具

## 学习重点

1. **关系建模的决策思维**：范式 / 反范式 / 冗余字段，哪些场景该上哪种
2. **SQL 抽象能力**：视图/函数/CTE 把临时 SQL 沉淀下来；用窗口函数做"分组内的排名"
3. **正确选工具**：CTE vs 子查询、相关子查询 vs JOIN、窗口函数 vs GROUP BY

## 本阶段在故事主线中的章节定位

订单开始牵连出订单明细（一对多）、用户（一对多）、商品（一对多）、收藏夹（多对多），故事的复杂度陡然上升。读者学会的不是"又多几个语法"，而是"识别关系 + 决策何时该规范化"。

## 阶段内闭环

设计表 → 用视图/函数固化 → 用 CTE / 窗口函数写复杂查询。**学完课 7 后，你应该能独立设计一个订单 + 用户 + 商品的三表关系，写出"每个用户最近一笔订单金额排行"这种带窗口函数的查询**。

## 学习节奏

- 本阶段 12 知识点，建议 **5–7 天** 完成
- 每课配套 5–10 条复合查询练习，**实操 ≥ 40%**

## 阶段产出物

学完本阶段后，你应有：

- 一个能跑的 `order_service` 库，含 users / orders / order_items / products 四张表
- 一个能跑存储过程的函数（自动维护某个聚合字段）
- 一张物化视图（统计每天 GMV 并定时刷新）
- 几条带 CTE 和窗口函数的复杂查询
