### 课 10 沉淀结论（2026-09-03）

1. **用户是一条记录**：`TYPE RECORD` 让终端用户变成表里一条记录，`WHERE owner = $auth.id` 这类判断可直接写进 schema。
2. **系统用户完全绕过 PERMISSIONS**：root 能读写 `PERMISSIONS NONE` 的表——用 root 跑应用则权限体系整体失效。
3. **表级与字段级默认值相反**：表级省略 = `NONE`（拒），字段级省略 = `FULL`（放）。表是主闸门，字段只能收窄。
4. **被拒一律静默**：表级返回 `[]`；字段级 select → 键消失（`SELECT *`）或变 `null`（显式列出）；**字段级 update → 该字段丢弃、其余照改、UPDATE 仍返回 200**（静默失败第十二次）。
5. **`$auth` 是实时读库的**，不是 token 快照（五轮决定性实验）。因此改用户记录即可即时吊销，但前提是权限表达式**引用了该字段**。
6. **吊销表达式必须写 `!= true`**：`= false` 在字段为 `null`（存量数据未回填）时求值为 false，会**误锁全员**（评审 P0，静默失败第十三次）。
7. **`WITH REFRESH` 改变返回体类型**：`token` 从字符串变成 `{access, refresh}`；refresh 必须放 body 的 `refresh` 字段；刷新即轮换。官方标注**实验特性，勿用于生产**。
8. **多租户方案 A 靠引擎划墙**（token 绑定 NS/DB，改 URL 参数切不走），**方案 B 靠表达式上锁**（`select FULL` 泄露、漏写动作、字段默认 FULL 三个陷阱）。工程上最常**混用**。
9. **`DEFINE ... OVERWRITE` 不清理子对象**：字段/索引/事件会保留，想真正重建须先 `REMOVE`。
10. **权限表达式的布尔判断优先用否定式**（`!= true`），别用肯定式（`= false`）。

### 课 11 沉淀结论（2026-09-03）

1. **路径参数就是能力清单**：`surreal start <PATH>` 的 scheme 同时决定持久化、版本化、横向扩展三件事，运行后不可改。
2. **三个后端在 3.2.4 已无法启动**：`file://`（报错明确提示改用 rocksdb/surrealkv）、`fdb://`、`indxdb://`、`memory://path`（后三者统一报 `Provide a valid database path parameter`，**不提「已移除」**）。
3. **`?versioned=true` 拼错完全静默**：非法值（`=1`/`=yes`）尚有一行 WARN，**拼错参数名连 WARN 都没有**。确认版本化是否开启只能看 `Versioning enabled:` 日志行。
4. **时间旅行的语义是「截至该时刻的状态」**：删除也是状态的一部分——记录删除后查任何更晚时刻都是 `[]`，**不是删除前的值**。能回到过去，不能从已删除的"未来"里捞数据。
5. **`[]` 与 ERR 是两个分支**：表在该时刻都不存在 → ERR；表存在、记录不存在 → `[]`。隐式建表（`CREATE` 不先 `DEFINE`）会让查历史时刻变成报错。
6. **时间旅行完整受 PERMISSIONS 约束**（阳性对照验证），被拒时静默返回空数组。
7. **历史版本跨重启存活**，`REMOVE TABLE` 后仍可查；rocksdb 与 surrealkv 在 SIGTERM 与 `kill -9` 后数据均完整。
8. **导出用 `INSERT`，非空库导入必整批回滚**（静默失败第十四次）：rc=1，只报一句含糊的失败，记录数完全不变（安全但难排查）。**恢复必须落到空库**。
9. **`import` 会自动创建不存在的 NS 和 DB**，与 `USE NS`（只建 NS 不建 DB）**行为相反**。写错库名不报错，而是静默建新库。
10. **导出文件补出 access 的 JWT 密钥**——备份文件即凭证，必须按密钥级别保管。
11. **单机后端有文件锁**：同目录第二个实例起不来；独立实例也不自动组网（nodes 里只有自己）。**"多进程 = 集群"不成立**，真分布式要上 TiKV 并接受其运维成本。
12. **可观测性家底很薄**：`/metrics` 仅 5 个进程级指标（无 QPS/延迟/慢查数/连接数）；`/health/ready`、`/health/live` 均 404；`/status` body 为空。
13. **`/health` 只证明端口活着，不证明是 SurrealDB**（静默失败第十六次）：本机 84xx 端口被其他服务占用也返回 200。就绪检查应用 `/version` 校验 `surrealdb-` 前缀。
14. **`--slow-log-threshold` 必须带单位**（`100ms`，写 `100` 启动失败），且日志含**完整 SQL**，需用 `--slow-log-param-deny` 脱敏。
15. **默认响应头暴露精确版本**（`server: SurrealDB` + `surreal-version`），生产建议加 `--no-identification-headers`。
16. **版本化的长期存储代价未测准**：短周期两组体积增长几乎相同（1.00x），只能说明 LSM 下旧版本仍在 WAL 未 compaction，**不可当"免费"结论**。

### 课 12 沉淀结论（2026-09-03）

1. **⚠️ 性能对比必须口径对齐**：SurrealDB 走 HTTP，空操作基线 **22.97ms**；Postgres/Mongo 驱动直连无这一层。拿客户端 wall time 直接比会得出「慢 40-160 倍」的错误结论，**真实差距约 10 倍常数级**（服务端自报 1.7-3.5ms）。
2. **⚠️ 扣除基线法在本场景失效**：HTTP 抖动 ±3ms > 查询耗时 1-3ms，实测扣除后出现**负值**（-2.128ms）。**噪声比信号还大时，要用服务端自报 time 字段，不要做减法**。
3. **两跳图遍历反直觉**：PostgreSQL 两次 JOIN 0.56ms < SurrealDB 1.68ms < Neo4j 3.98ms。**图数据库的优势在深度，不在两跳**——两跳太浅，B-tree + hash join 更快。
4. **⚠️ 深图遍历爆炸公式：结果条数 = 扇出^深度**。扇出 5 时：1 跳 5 条/1.96ms → 3 跳 125 条/3.09ms → **5 跳 3125 条/23.68ms**（第 5 跳陡增 5.7 倍）。推论：**扇出 10 的第 5 跳 = 10 万条，不可用**。边界判定：结果 ≤1000 条放心用；>10000 条必须换方案（LIMIT / 图算法 / 物化路径）。
5. **聚合是「全表扫描 + 内存聚合」**：5 千行 6.9ms → 8 万行 60.2ms（数据 16x、耗时 8.7x，**近线性**）。无列存、无预聚合。同期 PostgreSQL 8 万行 7.27ms。**OLAP / 报表场景请交给专用引擎**。
6. **写入路径反转**：灌 8 万行 SurrealDB 1.8s vs PostgreSQL 9.3s（LSM 顺序写 vs B-tree 随机写 + WAL）。**写多读少是 SurrealDB 的强项**。
7. **⚠️ 逐行写入差 940 倍**：2000 次单行 INSERT 48.89s（24.44 ms/次，几乎全是 HTTP 往返）vs 一次批量 INSERT 0.052s（0.026 ms/行）。**批量写是强制项，不是优化项**。
8. **索引有效但救不了 OLAP**：10 万行无索引 16.93ms → 建索引 7.15ms（加速 2.4x），而 PostgreSQL 同场景 0.36ms。
9. **⚠️【静默失败第十七次】`INSERT INTO edge [{in:…, out:…}]` 在 `TYPE RELATION` 表上不报错、返回 200，但一条都没写**。关系边**必须**用 `RELATE`。本课前四个图遍历实验因此全部返回 0 条而白跑——**也是「边即记录」的反例：它是记录，但不是普通记录**。
10. **⚠️【静默失败第十八次】`api::invoke()` 把端点的 500 伪装成 HTTP 200 返回**（错误藏在 body 里）。课 9「响应 body 支持 NONE」的错误结论正源于此。**端点必须走真实 HTTP 验证**。
11. **⚠️【更正课 9】端点必须 `RETURN { body: … }`**：`RETURN NONE` 与裸 `RETURN 'x'` 走真实 HTTP 均 **500**（Failed to convert public value to ApiResponse）；`{ body: '', status: 204 }` 可返回 204；`{ body: encoding::json::encode(obj) }` 可返回 JSON。课 9 另一条「对象走真实 HTTP 一律 500」仍然成立。
12. **`DEFINE API ... FOR GET` 回显成 `FOR any` 是误导**：行为验证显示非声明方法一律 404，**方法限制真实生效**。课 11 那句「配置生效后要用回显确认」在这里要打个补丁——**回显也可能不准，行为验证才是终点**。
13. **服务端 `time` 字段有多种单位**（`1.7ms` / `177.871µs` / `1.2s`）。**不能用 `.rstrip("ms")` 解析**（按字符集剔除，遇 µs 会剩 `177.871µ`）。这条是评审逐字执行讲义代码抓出来的。
14. **3.x 向量查询必须用 WHERE 谓语**：`ORDER BY emb <=> $q` 已报 Parse error（Missing order idiom），须写 `WHERE emb <|K,EF|> $q`，且查询向量先用 `LET` 定义。
15. **「不支持」是有效结论**：Q4 向量检索给 Mongo/Neo4j 标注「不支持原生向量索引」，而不是拿「扫全表 LIMIT 10」的假数字充数。**假数字比「不支持」有害得多**。
16. **能力清单可机检化**：12 课 40 知识点压缩为 **29 条断言**全部通过。**阴性断言必须配阳性对照**（3.3b / 4.3c）——`SELECT` 返回空可能是「被拦住」也可能是「表不存在」。
17. **选型结论**：选 SurrealDB 的条件是——痛点是**跨形状**而非单形状不够快、能接受每个单项慢一个常数级、数据量与图深度在崩点以内。三个必须写进决策文档的代价：**生态成熟度**（监控薄弱）、**图遍历规模**、**团队学习成本**。
