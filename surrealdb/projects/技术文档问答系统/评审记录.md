## 三、learner 视角（学习者）

### ① 场景吸引力

**"系统的检索对象就是关于检索的课程"** —— 自指设计是本项目的最大亮点。
学员问"索引怎么加速查询"，系统从他自己刚学过的讲义里找答案，
**对错一眼可辨，不需要额外领域知识**。这是降低验证成本的设计。

### ② 由浅入深

`demo.py` 五幕是完整阶梯：看得见的数据 → 四种模式的差异 → 权限的"三个世界"
→ 下推的价值 → 口径的区别。每幕末尾一句结论，收得住。

### ③ 认知阶梯

四种检索模式的并排对比（`demo.py 2`）是有效的认知冲突设计：
**同一个问题，四个不同答案**，学员自然会问"那该信哪个"，
接着看到互补性验证，自己得出"必须混合"的结论。

**扣分项**：`graph` 模式在演示里耗时 104ms，明显高于其它三者，
但文档没解释为什么。学员会误以为图扩展很慢。
已补：图扩展多了一跳邻居查询，是四次往返换来的背景信息。

### ④ 故事弧

主线清晰：一个应用要同时解决"检索不准、中文切不开、串租户、逻辑散落"四个问题。

### ⑤ 困惑点预判

| 学员可能困惑 | 文档是否回答 |
|---|---|
| 为什么要存 grams 冗余字段？ | 设计决策 1，有英文阳性对照实验 |
| 向量为什么只有 12 维？ | 设计决策 2，且说明了"弱向量路反而能演示互补性" |
| 库内函数为什么只接 3 个 term？ | 设计决策 5，有完整根因链 |
| root 为什么不受权限约束？ | demo 第三幕末尾显式说明"这是设计不是 bug" |
| 停用词为什么必须过滤？ | 设计决策 9，有 B7 失败的完整因果 |

**困惑点基本覆盖**。

### ⑥ 全局定位

README 的能力覆盖地图把每个文件对应到具体阶段与验收项，
学员能反查"这个知识点用在哪"。符合课程收尾的定位要求。

### 本轮评审的方法论收获

三条，都写进了 `验收清单.md` 的维护纪律：

1. **验收输入要刻意包含复杂输入**。"最小可过输入"是 bug 的天然庇护所。
2. **文档里的断言必须逐条跑过**。设计决策 5 是"从原理推的"，
   推出来的结论跟实测差了一个量级（"精度略低" vs "完全失效"）。
3. **跨层对照断言比单点断言强**。D1b 拿库内结果与应用层结果对照，
   比"库内返回 >0 条"这种自证式断言可靠得多。
