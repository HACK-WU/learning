# 验收清单

> 38 项自动验收 + 4 项人工复核。
> 自动部分一条命令跑完：`python3 verify.py`

设计原则：**不依赖"没报错"来判断成功**。
凡是验证"某事不该发生"的项，一律查副作用或配阳性对照。

---

## 一、怎么跑

```bash
# 前置：SurrealDB 已启动在 127.0.0.1:8000（root/root）

python3 init_db.py        # 建库 + 灌数 + 六项体检（幂等）
python3 deploy_logic.py   # 部署函数与端点
python3 verify.py         # 38 项验收
```

期望输出：

```
汇总：通过 38 / 38
全部通过。
```

退出码：全通过返回 0，有失败返回 1。

## 二、自动验收 38 项

### A. 数据层 —— 建模与写入（阶段 2）

| 编号 | 验收项 | 判据 | 常见失败原因 |
|---|---|---|---|
| A1 | 文档表行数正确 | `doc`=12 | 灌数被静默失败吃掉 |
| A2 | 切块表行数正确 | `chunk`=48 | 同 A1 |
| A3 | 关系边用 RELATE 建成 | `refs`=11 | 用了外键而非 RELATE |
| A4 | SCHEMAFULL 类型校验生效 | 错误类型被拒绝 | 表建成了 SCHEMALESS |
| A5 | 中文 bigram 字段已生成 | grams 含「索引」 | 分词函数没跑 |
| A6 | 向量维度与索引定义一致 | emb=12 维 | 改了 embed() 忘了改 DIMENSION |

### B. 检索层 —— 全文 / 向量 / 混合（阶段 3）

| 编号 | 验收项 | 判据 | 常见失败原因 |
|---|---|---|---|
| B1 | 关键词检索命中正确文档 | Top1=`chunk:l06_0` | 查了 text 而非 grams |
| B2 | 向量检索命中正确主题 | Top1=`chunk:l10_1` | 查询向量没 LET 就内联 |
| B3 | 混合检索召回图相关文档 | 含 l05 | rrf 参数顺序错 |
| B4 | 两路结果互补 | kw 独有 ≥1 且 vec 独有 ≥1 | 向量退化成常量 |
| B5 | 全文查询走索引 | EXPLAIN 含 FullTextScan | 索引没建在 grams 上 |
| B6 | 向量查询走索引 | EXPLAIN 含 KnnScan | KNN 算子漏写 `<` |
| B7 | 噪声可控 | 噪声 Top1 < 有效 Top1 × 0.5 | 停用词过滤被删 |
| B8 | 图扩展带出邻居背景 | 含邻居背景 ≥1 条 | `result()` 只取最后一条语句 |

### C. 权限层 —— 行级隔离与系统用户（阶段 4）

| 编号 | 验收项 | 判据 | 常见失败原因 |
|---|---|---|---|
| C1 | 记录用户可登录取 token | token 非空 | 鉴权头用成 Basic |
| C2 | alice 只见 acme | 租户集合=`['acme']` | PERMISSIONS 表达式错 |
| C3 | bob 只见 beta | 租户集合=`['beta']` | 同上 |
| C4 | root 不受约束（对照） | 见两个租户 | —— 这是设计不是 bug |
| C5 | 记录用户无法写入 | **副作用检查**：记录未产生 | 用"是否报错"判断会误判 |
| C6 | 审计表按租户隔离 | alice 条数 < 全库条数 | 审计表没加 PERMISSIONS |
| C7 | 错误密码被拒绝 | 拒错密码 **且** 对密码通过 | 只测拒绝会漏掉配置错误 |

### D. 逻辑下推 —— 函数与 HTTP 端点（阶段 3）

| 编号 | 验收项 | 判据 | 常见失败原因 |
|---|---|---|---|
| D1 | 检索函数对多 term 查询有召回 | 返回 >0 条（测三字查询） | 只测单字会放过零召回 bug |
| D1b | 库内函数与应用层 Top1 一致 | 两者 Top1 相同 | 库内链路与应用层走岔了 |
| D2 | 带租户过滤的函数生效 | 返回租户=`['beta']` | 过滤条件写死 |
| D3 | `/qa` 的 GET 与 POST 并存 | GET=200 且 POST=200 | 分两条 DEFINE 会互相覆盖 |
| D4 | POST `/qa` 返回正确结果 | q 回显正确且 count>0 | body 当对象用（字节数组） |
| D5 | 无匹配返回 count=0 | count=0 而非报错 | —— 验证降级路径 |
| D6 | 端点内可读到 `$auth.tenant` | tenant 非空 | 没用记录用户 token 调 |
| D7 | 审计记录命中条数 | n>0 | CREATE 在端点里没执行 |

### E. 可观测 —— 服务端自报耗时（阶段 4）

| 编号 | 验收项 | 判据 | 常见失败原因 |
|---|---|---|---|
| E1 | 响应含服务端 time 字段 | time 非空 | —— 基础能力 |
| E2 | time 解析支持 µs/ns/s | 5 种单位全对 | 用 rstrip 会删错字符 |
| E3 | 混合检索服务端耗时可测 | 中位数 >0 | —— |
| E4 | 墙钟显著大于服务端耗时 | 墙钟 > 服务端 | 口径搞反了会得出错误优化方向 |

### F. 工程性 —— 可重复执行与清理

| 编号 | 验收项 | 判据 | 常见失败原因 |
|---|---|---|---|
| F1 | schema 可重复执行 | 重复定义返回 OK | DEFINE 没加 IF NOT EXISTS |
| F2 | 连不上时有明确错误 | 返回 URLError 而非崩溃 | 吞掉异常 |
| F3 | 临时表已清理 | bench 临时表不存在 | 测试残留 |
| F4 | 用户数据完整 | `user`=2 | 灌数不全 |
| F5 | 所有切块都有租户标记 | 无租户的块=0 | seed 漏设 tenant |
| F6 | 倒排索引已建 | 倒排边=3198 | RELATE 没跑 |

## 三、人工复核 4 项

自动化测不出"对不对题"，这四项必须人眼看。

### H1. 召回的相关性

```bash
python3 query.py "索引怎么加速查询" --mode hybrid
```

逐条看返回的文本。**判据**：前 3 条里至少 2 条真的在讲索引。
自动验收只能保证"召回了一批结果"，不能保证这批结果对题。

### H2. 权限隔离的直觉验证

```bash
python3 demo.py 3
```

**判据**：三个身份看到三个不同的数字，且 alice + bob = root。
若 root 比两者之和小，说明有块的 tenant 字段为空（F5 会抓到，这里再确认一次）。

### H3. 端点对外的可用性

浏览器直接访问 `http://127.0.0.1:8000/qa`，应当看到提示语而非 404。

**判据**：能返回 `use POST /qa with {...}`。
这一项存在的意义是验证 GET/POST 合并定义真的生效 —— D3 已自动验收，
这里是从"另一个客户端"再确认一次。

### H4. 文档与代码是否一致

翻 `README.md` 的实测结论表，挑两条重新跑一遍：

```bash
python3 bench.py     # 核对规模敏感性的三个数字
python3 demo.py 5    # 核对墙钟 vs 服务端耗时
```

**判据**：文档里的数字与当前运行结果在同一量级。
数字会随机器波动，但量级不该变 —— 变了说明文档过期。

## 四、排障指引

验收失败时按这个顺序查：

| 症状 | 先跑这个 |
|---|---|
| A 组（数据层）失败 | `python3 init_db.py` 重跑，看六项体检 |
| B 组（检索）失败 | `python3 diag_recall.py`、`diag_score.py` |
| B7 噪声项失败 | `python3 diag_noise2.py`（会告诉你基线选对没） |
| C 组（权限）失败 | `python3 diag_verify.py` |
| D 组（端点）失败 | `python3 diag_body.py`（查 `$request.body` 形态）、`diag_method.py`（查 method 大小写） |
| E 组（可观测）失败 | `python3 bench.py` |
| 全组失败 | 先确认 SurrealDB 在跑：`curl http://127.0.0.1:8000/health` |

`diag_*.py` 系列刻意保留不删 —— 它们是"这个结论是怎么来的"的证据链。

## 五、验收清单本身的维护

新增验收项时遵守三条：

1. **验证"没发生"要查副作用**。参考 C5：不检查"是否报错"，检查"记录是否产生"
2. **配阳性对照**。参考 C7：拒绝了错密码还不够，要确认对密码能过
3. **判据本身先自证**。参考 B7：junk 查询必须真的不含语料里的词，
   否则测的是自己的判据而非被测对象

B7 这条最有教育意义 —— 它最初失败时，我改了三次断言，
前两次都是在修判据的错，第三次才发现是代码缺停用词过滤。
**先怀疑判据，再怀疑代码，但也别一直怀疑判据。**

4. **验收输入必须包含复杂输入**。D1 最初只测 `fn::qa_kw('索引', 3)` 这种
   单字调用，恰好绕过了"多字查询零召回"的缺陷，验收全绿但功能是坏的。
   现在 D1 测三字查询，D1b 再拿应用层结果做对照。
   **"最小可过输入"是 bug 的天然庇护所。**
