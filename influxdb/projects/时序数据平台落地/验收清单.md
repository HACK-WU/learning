# 验收清单 · 时序数据平台落地

> 逐项自测。**全部勾选才算真的做成了** —— 不是"跑起来就行"。
> 功能验收看"跑不跑得对"，非功能验收看"符不符合设计决策"，理解验收看"你有没有真的把 19 课串起来"。

## 功能验收

- [ ] `cd 实现/ && python3 main.py` 能跑通，无 traceback，退出码为 `1`（有 P0）
- [ ] 输出包含三个场景（IoT 设备遥测 / K8s 微服务监控 / 业务指标分析）
- [ ] 每个场景开头能看到**幸存 SKU 列表**，且它与后面的 P0 结论不矛盾
      （例：IoT 场景幸存 `enterprise / serverless / dedicated`，就不该再出现"Core 查不到数据"的 P0）
- [ ] `python3 main.py iot` 只跑一个场景，输出行数明显少于全量跑
- [ ] `python3 main.py nonexist` 输出"未知场景"提示并退出码 `3`
- [ ] 每条结论都带 `归属：阶段 X · LNN`，能回到讲义核对该数字
- [ ] 结论按 P0 → P1 → P2 → INFO 排序，同级别内保持稳定顺序
- [ ] 汇总段给出 `P0=N P1=N P2=N INFO=N` 并给出总结论

## 非功能验收

- [ ] **约束归属**：把 `config.py` 里 IoT 场景的 `want_managed` 改成 `False` 后重跑，
      Core 应重新回到幸存列表，且"432 文件超限"的 P0 重新出现
      （验证约束归属逻辑真的生效，不是写死的）
- [ ] **保留期命中检测**：把 IoT 场景的 `retention_period` 从 `0d` 改成 `90d` 后重跑，
      那条"立刻全删"的 P0 应消失（变成 INFO 或不再出现）
      （验证保留期检查真的在读配置，不是无条件告警）
- [ ] **合规翻转**：把业务指标场景的 `retention_period` 改成 `1mo` 重跑，
      因该场景 `compliance=True` 且 1mo 偏差 1.45% ≥ 0.3%，drift 应从 P1 升为 P0
- [ ] **单一数据源**：全局搜索 `432`、`0.012`、`240`，硬编码数字应只在 `config.py` 出现
- [ ] **AST 硬编码校验**（进阶）：用 `ast` 遍历各模块的 `BinOp` 子节点，
      确认 `432` / `240` / `0.012` 没有参与任何运算表达式
      （正则搜索会被 docstring 里的说明文字干扰，AST 才准 —— 本项目就是靠它抓出 `engine.py` 的一处漏网）
- [ ] **开闭原则**：在 `ops.py` 里新增一个检查函数并挂进 `run()`，**不改 `main.py`** 就能生效
- [ ] **退出码语义**：构造一个只有 P1 的场景（把 IoT 的 P0 项临时注释掉），退出码应为 `2` 而非 `1`
- [ ] **诚实标注**：全局搜索，`Enterprise` 授权费相关的结论必须带 ❓ 且不含具体金额
- [ ] **假设可替换**：改 `config.py` 的 `OPS_FTE_USD_MONTH` 为本地真实值，成本数字应同步变化

## 理解验收（把 19 课串起来）

> 这几条是本项目真正的目标 —— 代码只是载体。

- [ ] **能向同事讲清**：为什么"我们选了 InfluxDB"这句话没有信息量（选型是两次决策：产品 + SKU）
- [ ] **能向同事讲清**：432 文件上限是 **Core 的属性**，不是 InfluxDB 的属性。
      说出"把 A 的约束套到 B 上，和把 A 的优点算到 B 头上，是同一类错误"
- [ ] **能向同事讲清**：降采样层查不到，问题在**调度周期**不在精度。
      给出公式 `文件数 = 窗口天数 × 24 × 60 ÷ 调度周期(分钟)`，
      并算出 90 天窗口在 Core 上要求调度周期 ≥ 300 分钟（5 小时）
- [ ] **能向同事讲清**：迁移风险为什么按「失败时有没有声音」排序。
      举出 `0d`（reverse，静默删光）与 `3mo`（drift，少 1.3 天）两个例子
- [ ] **能向同事讲清**：为什么"最省"不等于"能选"。
      成本表必须排在排雷结果之后看
- [ ] **能回答收束问题**：我们公司该不该用 InfluxDB？用哪个 SKU？成本多少？迁移代价多大？
      —— 用自己的真实负载跑一遍 `main.py`，能逐条解释输出的每一条 P0
