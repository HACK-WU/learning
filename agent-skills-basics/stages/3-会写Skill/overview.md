# 阶段 3：会写 Skill

## 章节定位

**故事主线中的章节**：「把自己的规矩固化下来」

主角发现：别人的技能再好，也不如自己写的贴合。这一章是故事的收束——从"用别人的"到"产出自己的"。

## 阶段目标

学完本阶段，你能：

1. 把一件每周重复的事，写成一个 `SKILL.md`
2. 识别五种坏味道，判断一个技能写得好不好
3. 排查"装了但不触发"的问题
4. 拆分多文件、划定技能边界、与团队共享

## 学习重点

- **`description` 是第一优先级**：它决定了技能能不能被触发，比正文更重要。
- **让 AI 帮你写、你来审**：这是用户最实际的路径（用户无开发经验），但要讲清"AI 写的必须你检查什么"。
- **不触发是最高频故障**：必须给出可执行的四步排查，而不是泛泛而谈。

## 阶段状态

**进度**：3 课全部完成（9/9 知识点）。**✅ 阶段 3 收官**。

**已确立的核心结论**：

- **该不该做成技能**：三个信号——**说了 3 遍以上 / 每次都漏 / 又要改回来**（最后一个最强）。
- **六段式**：身份 / 触发 / 步骤 / 标准 / 反例 / 边界。**反例和边界最常被省、也最不该省**。
- **`description` 决定触发**：写 `"Use when ..." + 场景 + Examples: 用户会怎么说`。官方模板默认 `A brief description of what this skill does` 是**占位空话，照抄永不触发**。
- **静默失效（本课最硬的实测发现）**：`SKILL.md` 的 YAML 错一个字符（如 `name` 少冒号），**技能整个消失且不报任何错**。写完跑 `npx skills list -g` 自查在不在列表里。
- **`name` 与目录名不一致不影响识别**（实测：列表按 `name` 显示）——只影响你自己找它。
- **`npx skills init` 两个坑**：① `init --help` 不显示帮助，会真的创建名叫 `--help` 的技能；② 在**当前命令行目录**创建，不先 `cd` 会找不到。
- **让 AI 起草的分工**：你提供"规矩"和"用户会怎么说"（AI 猜不出）→ AI 出格式 → 你审 → **自己跑一遍才算数**。
- **必查三项**：description 是否具体 / 步骤是否可执行 / 有没有反例（**第一项专门抓"AI 原样保留占位文字"**）。

**课 6 新增结论**：

- **装了 ≠ 会被用**：`list -g` 只管"文件在不在"（工具层），**触发由 description 决定**（AI 层）。实测：description 是占位空话的技能**照样在列表里**。
- **五坏味道**：太泛（**最致命→不触发**）/ 太长 / 无反例 / 自相矛盾 / 该拆不拆。本机 7 个真实技能 48–122 行，可作"太长"的参考区间。
- **不触发四步排查**：① 在列表里吗 → ② description 对吗 → ③ **YAML/编码对吗** → ④ 点名能用吗（能用＝问题在 description）。
- **🔴 BOM 导致静默消失（Windows 专属）**：`Set-Content -Encoding UTF8` 会加 BOM（`239 187 191`），**文件看着完全正常，技能却凭空消失且不报错**。用 `[System.IO.File]::WriteAllText($p,$t,[Text.UTF8Encoding]::new($false))` 或 `npx skills init`。
- **🔴 `remove` 按文件夹名匹配**：列表显示 `name`，删除要用**文件夹名**。且**失效的技能 remove 也删不掉**（需先修好让它重新被识别）。→ **这才是"name 与目录名保持一致"的真正理由：不是怕识别不了，是怕你自己混乱。**
- **脚本技能会真实运行**：三条红线——不删库 / 不传数据 / 不需要时不高权限；**能执行 ≠ 该执行**。
- **删除用 `remove`**：实测扫描到 **66 个**已装技能（列表只显示 7 个 claude + 若干 codebuddy），手动删一个文件夹删不干净。**别用 `--all`。**

- **删除用 `remove`**：实测扫描到 **66 个**已装技能（列表只显示 7 个 claude + 若干 codebuddy），手动删一个文件夹删不干净。**别用 `--all`。**

**课 7 新增结论**：

- **多文件拆分实测成立**：三文件技能（`SKILL.md` + `reference.md` + `scripts/check.ps1`）复制进 skills 目录后**附件全部保留**，技能正常识别。**"附件会丢"不成立。**
- **渐进式披露在此落地**：附件**只在被点名时才加载**。→ **拆了却不在 `SKILL.md` 里点名 = 附件成摆设**（本课最容易踩的坑，已设为小测 Q1）。
- **太长 vs 太宽（核心辨析）**：**太长拆文件**（500 行硬上限，但本机实测多数技能 50–120 行，**500 是上限不是目标**）；**太宽拆技能**（一个技能一件事）。
- **git 天然能管技能**：技能是纯文本，实测 `3 files changed` + 三行 `create mode`，**附件全被管住**。
- **🔴 BOM vs CRLF（重要澄清）**：git 的 `LF will be replaced by CRLF` 是**正常提示**；**实测带 CRLF 的技能识别完全正常**。区别：**BOM = 开头多三个字节（致命）；CRLF = 换行符风格（无害）**。别混为一谈。
- **共享闭环**：课 6 的 BOM 坑 → 课 7 开场场景"发给室友他不理我"的答案正是它。**对策**：检查首三字节 / 用 `npx skills add` 安装 / **对方必跑 `list -g` 确认**。
