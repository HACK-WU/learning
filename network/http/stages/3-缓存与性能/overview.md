# 阶段 3 概览：缓存与性能

> 所属课程：HTTP 系统学习 ｜ 故事章节：让它快起来 ｜ 上一阶段：[阶段 2 · 连接与安全](../2-连接与安全/overview.md)

## 🎯 本阶段目标

- 能为静态资源配置正确的缓存策略：说清强缓存与协商缓存各省了什么，给"HTML + 带 hash 的静态资源"写出完整配置。
- 能把"页面慢"拆解成可测量的段落（连接 / TTFB / 下载等），会用 DevTools 瀑布图与 `curl -w` 读出每段耗时，并给出对应的优化方向。
- 能看清请求到达服务前站着哪些"中间人"（正向 / 反向代理、网关、CDN），说清真实 IP 如何经转发头传递、为什么会传错。

## 📍 学习重点

- 缓存是"让请求不出门"：强缓存（Cache-Control / max-age）连请求都省掉，协商缓存（ETag / Last-Modified）省正文不省请求——两者的分工是所有缓存配置的地基。
- "no-cache 不是不缓存"：no-cache、no-store、max-age=0 的语义差异，是缓存配置里最高频的混淆点。
- 性能优化先测量后动手：TTFB 与各阶段耗时的含义、gzip 与 brotli 的取舍、压缩的 CPU 代价——先拆段，再对症下药。
- 1.1 时代性能手段的兴衰：域名分片在 HTTP/1.1 是药方，在 HTTP/2 下反而有害——为阶段 4 埋伏笔。
- 代理家族与真实 IP：X-Forwarded-For 的追加语义与可伪造性、"只信最后一跳"；CDN 把缓存决策从"配给浏览器"扩展到"配给整条链路"（s-maxage 与共享缓存）。

| 协商缓存 | 课 7《HTTP 缓存：让请求不出门》 | 能说清 ETag 与 If-None-Match、Last-Modified 与 If-Modified-Since 的配合方式，解释"304 只省正文不省请求" |
| 缓存决策实战 | 课 7《HTTP 缓存：让请求不出门》 | 能为"HTML 不缓存 + 静态资源 hash 文件名长缓存"给出完整决策，说清浏览器刷新与强制刷新的行为差异，会画缓存决策树 |
| 响应压缩 | 课 8《性能测量与优化：把"慢"拆成段落》 | 能说清 Content-Encoding 与 Accept-Encoding 的协商过程，在 gzip 与 brotli 之间做取舍，知道压缩的 CPU 代价与不适用场景 |

| 代理家族 | 课 9《代理、网关与 CDN：请求的中间人》 | 能区分正向代理与反向代理、网关与负载均衡，会用 Via 头识别报文被哪些中间人改动过 |

| CDN 与边缘缓存 | 课 9《代理、网关与 CDN：请求的中间人》 | 能说清 CDN 命中与回源的机制，会用 s-maxage 区分共享缓存与浏览器私有缓存，让 Cache-Control 在 CDN 场景正确配合 |
