# 阶段 1 概览：报文与语义

> 所属课程：HTTP 系统学习 ｜ 故事章节：看得见请求 ｜ 上一阶段：无（课程起点，返回 [学习路径总览](../../01-学习路径总览.md)）

## 🎯 本阶段目标

- 能打开 DevTools（Network 面板）把一次网页加载产生的请求"看见"，并从头到尾读完整一条请求与响应报文。
- 能解剖 HTTP 报文的四段结构与高频头部，说清每个部分在整条对话里承担的角色。
- 能用方法（GET/POST/PUT/…）与状态码（1xx–5xx）的语义精确表达一次接口交互——联调群争论"该返 400 还是 401"时，你能给出有依据的答案。

## 📍 学习重点

- HTTP 的定位与请求-响应模型：它是建立在 TCP/TLS 之上的应用层协议，客户端-服务器一问一答、每个资源一个请求——这是后面所有内容的地基。
- 无状态设计与"状态"的由来：无状态的确切含义、为什么这样设计（简单、可扩展），以及状态由 Cookie 等机制补回（阶段 5 课 13 的伏笔）。
- URL 解剖与报文四段结构：scheme/host/port、path/query/fragment；起始行、头部区、空行分隔、正文区——这是"看见请求"的基本功。
- 高频头部与正文的表达：Host 与虚拟主机、Accept 系与内容协商、User-Agent 与 Referer；Content-Type 决定正文的解读方式（urlencoded / JSON / multipart）。
- 方法语义与状态码五大类：安全性与幂等性、高频状态码速查、重定向 3xx 的方法保持差异——接口对话的语言。
