## B. 病例一：慢请求与重定向

- [ ] `/api/redirect` 返回 302，并且 `Location` 指向 `/api/orders?source=redirect`。
- [ ] `/api/slow` 返回 200，响应有 `Server-Timing`，正文能够完整读完。
- [ ] 输出同时包含 connect、ttfb、body、total 四段时间；重复运行时数值可以变化，但阶段关系仍成立。
- [ ] 能解释：重定向是一次额外请求链路，TTFB 长不能直接推出“正文压缩有问题”。

## C. 病例二：认证状态

- [ ] 不带 `Authorization` 得到 401，并看到 `WWW-Authenticate: Bearer ...`。
- [ ] 带错误 Bearer 得到 403，而不是把错误伪装成 200。
- [ ] 带字面量占位符 `<DEMO_TOKEN>` 得到 200；没有真实密钥进入文件。
- [ ] 能解释：401 首先是认证材料缺失/无效，403 是身份已到达但授权不通过或被服务拒绝。

## D. 病例三：CORS 与缓存

- [ ] 允许来源 `http://localhost:5173` 的 OPTIONS 预检得到 204，并带允许来源、方法和请求头。
- [ ] `http://evil.example` 的同类预检得到 403。
- [ ] 第一次 GET `/api/orders` 得到 200 和 ETag；带 `If-None-Match` 再请求得到 304 且正文为空。
- [ ] `/static/app.abc123.js` 返回 `immutable`；能说明它依赖内容指纹不会被原地覆盖。
- [ ] 能区分“浏览器禁止页面读取响应”和“服务端根本没有返回响应”这两类问题。

## E. 病例四：协议决策

- [ ] 能指出本地实验的基线是 HTTP/1.1，而不是把它描述成 HTTP/2/3 实测。
- [ ] 在升级协议前能列出：实际协商版本、主要耗时段、客户端支持、服务端/CDN/代理支持、失败回退。
- [ ] 能说出至少一个“升级协议不会直接解决”的问题，例如应用处理慢或缓存未命中。

## 推荐手工复现

先进入项目目录：

```bash
cd network/http/projects/HTTP请求诊断实验场
python3 实现/server.py --port 8765
```

另开终端二：

```bash
cd network/http/projects/HTTP请求诊断实验场
curl -i http://127.0.0.1:8765/api/redirect
curl -sS -o /dev/null -w 'status=%{http_code} ttfb=%{time_starttransfer}s total=%{time_total}s\n' http://127.0.0.1:8765/api/slow
curl -i http://127.0.0.1:8765/api/auth
curl -i http://127.0.0.1:8765/api/auth -H 'Authorization: Bearer <DEMO_TOKEN>'
curl -i http://127.0.0.1:8765/api/orders
curl -i http://127.0.0.1:8765/api/orders -H 'If-None-Match: "orders-demo-v1"'
```

浏览器端：打开 DevTools → Network → Preserve log，访问 `http://127.0.0.1:8765/`，分别查看 Headers、Timing、Response；导出 HAR 前删除 Cookie、Authorization、查询参数中的秘密。
