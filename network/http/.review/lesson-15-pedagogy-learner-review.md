## 2. 教学法视角（pedagogy）

### 2.1 教学逻辑

- 15.1 先按证据目标区分 DevTools、curl 和中间代理，属于感知层→概念层。
- 15.2 用“接口慢”和“登录失效”把工具落到机制与定位层；先看请求是否存在、凭证是否存在、响应能否交给脚本，未跳过中间概念。
- 15.3 把定位结果收束为缓存、协议、认证、CORS 四类决策，并为每类保留验证与回滚，完成“定位→决策”闭环。
- 前置依赖均回指第 7–14 课；本课没有把 DNS、TLS 解密实现或认证协议内部细节扩写成超纲内容。

**结论：通过，无顺序断层、粒度失衡或前置缺口。**

### 2.2 内容准确性

- Chrome DevTools 的 Queueing、DNS Lookup、Initial connection、Proxy negotiation、Waiting (TTFB)、Content Download、Preserve log、HAR sanitized 和 Copy as cURL 已按官方 Network reference 核对，并在正文标注 `核查于 2026-09`。
- curl `-v` 的 `>` / `<` / `*` 行标记、`-w` 完成后输出格式变量、`--trace-ascii` 与 `-v` 互斥且可能暴露敏感数据，均按当前 curl 手册核对。
- mitmproxy 默认 regular proxy 的 `localhost:8080` 与 HTTPS 解密依赖客户端信任本地 CA，按官方 Getting Started / Certificates 核对；本机未安装，未把预期写成实测。
- 课程只把本地实验的 `connect-ms=0.09`、`ttfb-ms=85.07`、`body-drain-ms=44.26`、`total-ms=129.33`作为一次真实运行输出，并明确说明会抖动且不构成生产基线。
- 认证实验输出使用 `<DEMO_TOKEN>` / `<YOUR_ACCESS_TOKEN>` 占位符，没有真实凭据、内网地址或个人信息。

**结论：通过，无事实错误。**

## 4. 实验脚本静态正确性 review

- 只依赖 Python 标准库，无第三方安装、网络外连、系统代理修改或证书信任修改。
- 服务端固定提供 `/redirect`、`/slow`、`/auth`，路径分支与正文说明一致。
- `/slow` 先延迟再分两段写正文，客户端分别记录连接、首字节、读完正文和总耗时；时间值由 `perf_counter()` 真实产生，没有硬编码进程序。
- `/auth` 无凭证返回 401 + `WWW-Authenticate`，凭证匹配才返回 200；示例凭证是明确占位符，不是可用秘密。
- `try/finally` 确保测试服务器 shutdown / close，线程有 join 超时；默认访问日志关闭，输出稳定。
- 已通过 `py_compile` 和真实 `--section all` 运行；脚本没有生成课程目录内的运行残留。

**代码 review 结论：通过。**
