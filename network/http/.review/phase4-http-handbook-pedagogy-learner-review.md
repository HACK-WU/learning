## 3. Pedagogy 视角

### 3.1 通过项

- **第二入口定位清楚**：开篇说明“复习、排障、做决策”三种使用方式，避免手册退化为正文副本。
- **依赖顺序没有被打乱**：先报文与语义，再连接与安全，再缓存/性能/中间层，随后协议演进，最后回到认证联调与排障。
- **每课结构统一**：一句话本质 → 处境对照 → 全局图 → 知识点地图 → 速记/误区 → 命令卡 → 官方文档 → 三句话收束，降低查阅成本。
- **概念与行动保持连接**：每个知识点都改写成“能解释什么 / 能判断什么 / 能用什么证据验证”，符合用户“理解 + 实操 + 决策”三轨目标。
- **认知边界有保留**：明确 HTTP/2 仍受 TCP 队头阻塞、HTTP/3 需要回退、CORS 由浏览器执行、转发头依赖信任边界等关键边界。

## 4. Learner 视角

- **打开手册即可知道从哪里开始**：课程总图和五阶段表先回答“学什么、为什么按这个顺序学”。
- **遇到熟悉症状可反向查课**：现象路由表把“慢、401/403、CORS、旧数据、证书失败、协议升级”映射到具体章节。
- **不必记住所有头字段**：命令总卡与每课速查卡提供可复制的最小动作；细节仍可回原课。
- **图文比例合适**：阶段图看结构，课级图看机制，表格看决策；没有把复杂流程全部压成大段文字。
- **安全边界对初学者可见**：`--insecure`、mitmproxy、真实 Token、共享缓存等高风险动作都带有适用限制。
