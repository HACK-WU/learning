## 事实核查记录

| 事实 / 结论 | 核查来源 | 结果 |
|---|---|---|
| QUIC RFC 9000 为 2021-05，QUIC-TLS RFC 9001 为 2021-05，HTTP/3 RFC 9114 为 2022-06 | [RFC 9000](https://www.rfc-editor.org/rfc/rfc9000.html)、[RFC 9001](https://www.rfc-editor.org/rfc/rfc9001.html)、[RFC 9114](https://httpwg.org/specs/rfc9114.html) | PASS；正文统一标 `（核查于 2026-09）` |
| HTTP/3 将请求-响应映射到 QUIC stream；一条流受阻不必阻塞其他流 | RFC 9114 §2、§6 | PASS；正文以 12.1 与 12.2 的对照图和解释落地 |
| HTTP/2 的并发仍会受到 TCP 丢包后的共享有序交付影响 | RFC 9114 §1.1 | PASS；正文区分 HTTP 层 HoL 与 TCP 层 HoL |
| QUIC 提供流级可靠性、连接级拥塞控制和流量控制 | RFC 9114 §1.2、RFC 9000 | PASS；正文没有把 QUIC 写成“不会丢包” |
| QUIC 使用 TLS 1.3 握手；1-RTT 与 0-RTT 的数据阶段不同 | RFC 9001 §2.1、§3、§4.6 | PASS；正文同时说明加密、握手和早期数据边界 |
| 0-RTT 早期数据可能被重放，不适合未经防重放设计的副作用操作 | RFC 9001 §2.1、§9.2；RFC 8470 | PASS；正文未把 GET 直接等同于自动安全 |
| Connection ID 支持在地址变化时维持连接关联，新路径仍需验证 | RFC 9000 §9 | PASS；正文写成“让迁移成为可能”，没有承诺必然不断线 |
| HTTP/3 使用 QPACK 而非 HPACK | RFC 9114 §2、RFC 9204 | PASS；正文说明原因是 QUIC 没有 TCP 式全局顺序，且压缩不等于加密 |
| `h3` 是 HTTP/3 的 ALPN 标识；Alt-Svc 可用于发现备选 HTTP/3 endpoint | RFC 9114 §3.1、§3.2、§11.1；RFC 7838 | PASS；正文修正为正确锚点并区分发现与协商 |
| 当期浏览器支持度的定性表述 | [MDN HTTP/3](https://developer.mozilla.org/en-US/docs/Glossary/HTTP_3)、[MDN Evolution of HTTP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Evolution_of_HTTP) | PASS；仅写“多数主流浏览器具备支持”，并标 `（核查于 2026-09）`，没有编造百分比 |
| curl 的 `--http3-only`、`--http3`、Alt-Svc 方式与 QUIC 后端要求 | [curl HTTP/3 with curl](https://curl.se/docs/http3.html) | PASS；正文区分强制 h3、带回退和 Alt-Svc |
| 本机 curl 8.7.1 的 Features 与 HTTP/3-only 报错 | 本机 `curl -V` 与 `curl --http3-only -sS -o /dev/null https://example.com/`，实测于 2026-09-16 | PASS；真实输出已写入 12.2，结论限定为“本机这一份 curl” |
