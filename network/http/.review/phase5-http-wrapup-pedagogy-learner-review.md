## 三、learner 视角评审

### 角色与学习路径

代入角色是学习档案中的“小航”：入门水平、写过接口、会用浏览器/curl，但说不清报文、缓存、连接和协议细节。模拟路径为：先遇到线上症状 → 读 08 理解为什么 → 翻 09 在紧急状态下行动 → 打开场景文件先想 30 秒 → 展开三条路线做设计决策。

| 维度 | 具体观察 | 结论 |
|---|---|:---:|
| L1 场景吸引力 | 场景 1 从“浏览器 CORS 报错、curl 200”开始；场景 3 从“响应丢失后重复下单”开始；场景 5/6 用 500→5000、200 KB→2 MB 和 UDP 回退把规模压力具体化；没有用定义句开场 | 通过 |
| L2 由浅入深 | 08 先把症状翻译成责任层，09 只保留操作，场景再要求比较路线；场景 INDEX 明确先做信任/缓存/幂等，再做规模/弱网 | 通过 |
| L3 认知阶梯 | 术语首次出现处都给了人话：BFF、Idempotency-Key、mTLS、freshness、CORS safelisted；H1/H2/H3 属前置课程术语。预审发现的早引问题已修复 | 通过 |
| L4 故事弧 | 每个场景都是真实可观察处境 → 常显先想 → 分层提示 → 折叠多解法 → 推荐递进 → 边界与踩坑；不是直接公布唯一标准答案 | 通过 |
| L5 困惑与顿悟 | 可能的困惑点是“curl 200 为什么浏览器仍失败”“超时为什么不能直接重试”“H2/H3 到底解决哪一段”；这些都在场景描述/提示中给了入口，并由解法和故障编号回扣。顿悟点是“总耗时必须拆段”“CORS 不是授权”“转发头不是证明” | 通过 |
| L6 全局定位 | INDEX 说明三件套分工；每篇末尾回指课程、08 和边界；读者能知道何时读原理、何时照 QRH、何时做设计题 | 通过 |
| L7 入口可读性 | 08 有适用边界和反模式；09 首页是症状索引；场景文件在答案前保留先想锚点；SVG 下有读图指引；无需先读完整课程才能开始 | 通过 |

### Learner 正面发现

1. 场景 1 把“浏览器不让读”与“服务器能收到”分开，能纠正新手最常见的“curl 200 就说明 CORS 没问题”误解。
2. 场景 3 用“请求已执行但响应丢失”作为设计起点，比直接背幂等定义更容易理解为什么需要服务端记录。
3. 场景 5/6 把“协议升级”放在缓存、字节量和回退之后，能抑制“遇到慢就换 H3”的冲动。
4. 09 的每条第一步都是止血或回退，适合紧急状态下不必重新阅读原理的使用方式。

## 四、代码与配置静态正确性 review

| 范围 | 核查结论 |
|---|---|
| CORS/凭据 | `credentials: "include"` 与 Cookie 路线匹配；Bearer 路线显式发送 `Authorization`；文本明确禁止凭据与 `Allow-Origin: *` 组合 |
| 缓存 | `public, max-age=31536000, immutable` 只放在内容指纹资源；HTML/ETag/私有 API 的边界被分开说明 |
| 幂等 | PUT 使用稳定资源 ID；幂等键伪代码包含参数摘要、原子 claim、结果存储和冲突分支；客户端未知结果转查询，不把所有超时当成未执行 |
| 代理 | 示例要求入口清理外部转发头，并同时记录 peer 与解析地址；Forwarded 示例使用文档保留地址 |
| 协议/性能 | curl 只作协商与观测示例；H3 伪代码保留 H2/H1 回退；Timing 与响应字节被分开测量 |
| 安全 | 没有真实 token、密码、私钥；没有把 `-k` 作为修复；没有把 CORS 当作服务端授权 |

结论：代码/配置是设计级示例，静态 review 通过；本批没有声称这些片段已在真实生产环境运行。
