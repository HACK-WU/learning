# HTTP 学习路径总览

> 本文件是活文档，随学习进度动态调整。阶段依赖图统一用 SVG。

## 🎯 学习目标

- **目标类型**：都要——理解概念 + 动手实操 + 决策参考（三轨并重）
- **目标说明**：学完能对任意一次 HTTP 请求"解剖"——抓包看懂报文、把问题定位到具体一层，并对缓存 / HTTPS / 协议版本 / 认证方案给出有依据的决策
- **场景侧重**（四项全选，决定各阶段权重）：日常开发与调试 / 性能与优化 / 安全与 HTTPS / 体系化与原理纵深

> 学习目标是全局基准，决定各阶段/课的取舍与实操比重。目标变更时更新此处，并同步调整相关课。

## 故事主线

- **主角**：小航——入职三个月的全栈新人，负责公司 Web 项目的接口联调
- **冲突**：联调群天天"甩锅"——接口报错说不清是谁的锅、页面加载慢不知道慢在哪、上了 HTTPS 证书报错没人会看。看得见现象，看不见报文
- **收束**：能对任意一次 HTTP 请求做"解剖"，并输出团队可用的决策清单

> 整个课程是这条故事线的展开，每个阶段是故事的一个"章节"。

## 版本与事实基线

| 项 | 基线 | 说明 |
|----|------|------|
| HTTP 规范 | RFC 9110（语义）/ 9111（缓存）/ 9112（1.1）/ 9113（2）/ 9114（3），2022-06 发布 | ⏳ 稳定事实，课 10–12 仍按闸门复核 |
| TLS | TLS 1.3（现行规范 RFC 9846；原 RFC 8446）为主流，1.2 仍广泛 | ✅ 已核实（核查于 2026-09，RFC Editor） |
| 实操环境 | macOS arm64 + 系统自带 `curl` + Chrome DevTools | mkcert / mitmproxy 安装前先征询授权 |

## 阶段总览

### 阶段 1：报文与语义（预计 1–2 周）

- **目标**：把"看不见的请求"变成"看得见的报文"——能读完整一次请求/响应，能说清方法与状态码的语义
- **学习重点**：HTTP 在协议栈中的定位与请求-响应模型；报文四段结构与高频头部；方法语义与幂等性；状态码五大类与 3xx 重定向；URL 结构
- **必须掌握**：打开 DevTools Network 能逐段读出报文结构；能解释为什么接口"该返 400 还是 401"；能预测 301/302/307 对 POST 的影响
- **对应课**：课 1《一次网页加载的全旅程》、课 2《报文解剖》、课 3《方法与状态码》

### 阶段 2：连接与安全（预计 1–2 周）

- **目标**：说清一条连接从建立到加密的全过程；能本地配 HTTPS 并读懂证书报错
- **学习重点**：TCP 握手与连接成本；Keep-Alive 与队头阻塞；明文三大威胁；混合加密与 TLS 握手；证书链与信任体系；mkcert 实操
- **必须掌握**：能解释"HTTPS 到底防了什么、怎么防"；能从证书报错定位原因（过期/域名不匹配/自签）；能独立把本地开发环境升级为 HTTPS
- **对应课**：课 4《连接管理》、课 5《HTTPS 加密原理》、课 6《证书与信任》
- **提示**：本阶段（尤其 TLS 与证书）是全课程认知最陡的一段，节奏放慢

### 阶段 3：缓存与性能（预计 1–2 周）

- **目标**：能为静态资源配置正确的缓存策略；能把"慢"拆成可测量的段落并给出优化方向
- **学习重点**：强缓存与协商缓存的全套头字段；缓存决策树；压缩协商；TTFB 与瀑布图测量；代理/网关与真实 IP 转发头；CDN 与共享缓存
- **必须掌握**：能给"HTML + hash 静态资源"配出完整缓存方案；能用 DevTools/curl 把一次"慢"定位到 DNS/连接/TTFB/下载哪一段；能解释日志里 IP 全是网关的原因
- **对应课**：课 7《HTTP 缓存》、课 8《性能测量与优化》、课 9《代理、网关与 CDN》

### 阶段 4：协议演进（预计 1–2 周）

- **目标**：能说清 HTTP 各版本的演进动因与特性；能对"要不要升级协议"给出有依据的判断
- **学习重点**：0.9→1.0→1.1 的演进线与 1.1 关键特性；1.1 性能手段为何在 HTTP/2 下失效；二进制分帧与多路复用；HPACK 与服务器推送的兴衰；QUIC 的 0/1-RTT 与连接迁移；HTTP/3 部署现状
- **必须掌握**：能回答"HTTP/2 解决了什么、没解决什么"；能对"要不要上 HTTP/3"给出支持度清单与适用边界
- **对应课**：课 10《HTTP/1.1 与协议奠基》、课 11《HTTP/2 与多路复用》、课 12《HTTP/3 与 QUIC》

### 阶段 5：认证联调与决策（预计 1–2 周）

- **目标**：能处理 Cookie/Session/Token 与 CORS 的日常问题；能独立完成一次"从症状到定位"的完整排障；输出个人决策清单
- **学习重点**：Cookie 安全属性；Session vs JWT 权衡；Authorization 头与 401 机制；同源策略与 CORS 全链路；抓包方法论与综合排障推演；三类决策清单
- **必须掌握**：能给登录态方案选型并说清代价；能一眼定位 CORS 报错是谁的配置问题；能独立解剖"接口慢""登录失效"两类高频问题
- **对应课**：课 13《Cookie、Session 与 Token》、课 14《CORS 与同源策略》、课 15《抓包排障与决策清单》
- **叙事转折**：阶段 4 走完协议纵深后，本阶段**回到日常**——纵深是为了"收束成决策"，不是回退
