# HTTP 排障速查手册

> **怎么用**：出事了别从头读。按索引表找可观测症状，翻到对应条目照做。
> **想懂为什么**：每个条目末尾按编号回指 [08-实战经验](08-实战经验.md)。
> **查不到**：→ 转 `debug` skill 做现场取证；本手册不是当前故障的自动诊断器。

## 🔎 症状倒查索引

| 一眼看到的现象 / 报错关键字 | 紧急度 | 翻到 |
|---|:---:|---|
| `401`、`403`、`WWW-Authenticate`；应用日志没有请求 | 🔴 | **条目 1**：认证状态码错位 |
| 控制台 `blocked by CORS policy`；`OPTIONS` 是 401/403；curl 却 200 | 🔴 | **条目 2**：CORS 预检失败 |
| `Age`、`X-Cache: HIT`、304；发布后仍是旧内容或用户内容串了 | 🔴 | **条目 3**：缓存错配 |
| `time_total` 变大；瀑布图 Waiting 长，或接收阶段长 | 🟡 | **条目 4**：慢请求分段定位 |
| 客户端可伪造日志 IP；scheme、限流或白名单判断异常 | 🔴 | **条目 5**：代理链信任污染 |
| HTTP/3 失败后回落；部分网络失败；UDP/443 无到达 | 🟡 | **条目 6**：HTTP/3 发布回退 |
| `certificate verify failed`、名称不匹配、链不受信；`-k` 后表面恢复 | 🔴 | **条目 7**：证书校验失败 |
| keep-alive 超时、响应错位、`Content-Length`/chunked 异常 | 🔴 | **条目 8**：HTTP/1.1 报文边界 |

> **紧急度**：🔴 立即处理（业务已受损或信任边界可能被绕过）｜🟡 尽快处理（已有风险或部分用户受影响）｜⚪ 有时间再看（本批无纯优化项）。

## 🔴 条目 1：认证状态码错位

**一眼识别**：同一 URL 在无凭据、错误凭据、无权限和有权限请求间状态码异常；响应带 `WWW-Authenticate`，或网关返回 401/403 但应用没有同一请求 ID。

| 步骤 | 条件 / 动作 | 预期 |
|---|---|---|
| **止血** | 若刚发布认证/授权配置，回滚到上一版已验证配置；保留认证，不要关闭鉴权。 | 存量正常请求恢复到已知状态 |
| 定位 1 | 分别保存无凭据、格式错误、已认证无权限、正常权限四次请求的 method、状态码、`WWW-Authenticate`、请求 ID；凭据值脱敏。 | 四个分支可区分 |
| 定位 2 | 按请求 ID 查 CDN/网关与应用；边缘有、应用无 → 查代理策略；应用有 → 查认证/授权映射。 | 找到首次生成响应的层 |
| 修复 | 修正凭据传递、认证头格式和权限映射；401 保留挑战信息，403 保留拒绝语义。 | 各分支状态码稳定 |
| 若无效 | → 转“条目 5：代理链信任污染”检查 scheme/头部；仍不明 → 转 `debug`。 | — |

> **预防**：把四个认证分支纳入契约测试，并让每层日志共享请求 ID。
> **原理**：→ [08-实战经验](08-实战经验.md) 的故障模式 1。

## 🔴 条目 2：CORS 预检失败

**一眼识别**：Network 中有 `OPTIONS`；它的 `Origin`、`Access-Control-Request-Method` 或 `Access-Control-Request-Headers` 与响应允许项不匹配，实际请求没有发出或浏览器拒绝读取。

| 步骤 | 条件 / 动作 | 预期 |
|---|---|---|
| **止血** | 回滚最近的 CORS 配置；不要改成任意来源 `*`，不要关闭认证。 | 已知来源的联调恢复 |
| 定位 1 | 打开 `OPTIONS`，比较请求 Origin/method/headers 与 `Access-Control-Allow-Origin/Methods/Headers`。 | 找到缺失或不匹配的允许项 |
| 定位 2 | 若预检是 401/403，逐层确认 CDN/网关/应用是否放行 OPTIONS；若预检通过而实际失败，查实际响应头。 | 判断拦截层 |
| 定位 3 | 若响应按来源变化，检查 `Vary: Origin` 和 CDN 缓存键。 | 避免来源间复用 |
| 修复 | 精确配置来源、方法、头和 credentials；预检与实际响应都返回所需 CORS 头。 | 浏览器预检与实际读取均通过 |
| 若无效 | → 转“条目 1：认证状态码错位”检查凭据；仍不明 → 转 `debug`。 | — |

> **预防**：把浏览器预检、实际请求、凭据和错误响应作为一组回归用例。
> **原理**：→ [08-实战经验](08-实战经验.md) 的故障模式 2。

## 🔴 条目 3：缓存错配

**一眼识别**：发布后仍看到旧资源，响应出现 `Age`/`X-Cache: HIT`/304，或不同用户/来源收到相同个性化响应。

| 步骤 | 条件 / 动作 | 预期 |
|---|---|---|
| **止血** | 对受影响的个性化资源临时切到 `Cache-Control: private, no-store`（按变更流程执行），并 purge 错误对象；保留静态资源缓存。 | 先停止错误复用 |
| 定位 1 | 记录两种用户/来源的 `Cache-Control`、`ETag`、`Age`、`Vary`、`Date` 和缓存状态。 | 判断是否共享错配 |
| 定位 2 | 首次请求→带 `If-None-Match`→更换影响请求头，比较 200/304、响应体和命中状态。 | 分开 freshness 与验证问题 |
| 定位 3 | 沿 CDN→代理→源站核对缓存键、purge、版本化 URL；不要只用浏览器强刷判断。 | 找到错误缓存层 |
| 修复 | 私有响应禁止共享；hash 静态资源再长缓存；变化维度补 `Vary`/缓存键；需要验证时用 `no-cache`。 | 复用边界与发布策略一致 |
| 若无效 | → 转“条目 5：代理链信任污染”检查来源/用户维度；仍不明 → 转 `debug`。 | — |

> **预防**：为不同用户、不同来源、新发布、304 和 purge 保留回归样本。
> **原理**：→ [08-实战经验](08-实战经验.md) 的故障模式 3。

## 🟡 条目 4：慢请求分段定位

**一眼识别**：`time_total` 变大，但必须进一步确认是连接、首字节等待还是内容下载；浏览器 Timing 的某一段明显拉长。

| 步骤 | 条件 / 动作 | 预期 |
|---|---|---|
| **止血** | 回滚刚上线且已证明增加耗时的变更，或把关键流量切到已知正常实例；不要盲目切协议。 | 先恢复已知基线 |
| 定位 1 | 用浏览器 Timing 或 curl `-w` 采集重定向、连接、TLS、TTFB、总耗时与字节数；按协议判断不适用字段。 | 获得分段基线 |
| 定位 2 | TTFB 高 → 按请求 ID 查网关/应用/上游；下载高 → 查响应大小、编码、带宽和复用。 | 进入正确责任层 |
| 定位 3 | 对比冷连接/复用、缓存命中/未命中、不同协议和响应大小；每次只改一个变量。 | 排除混杂变量 |
| 修复 | 对证据所在阶段处理：复用、减少重定向、压缩/缩小、缓存；业务/数据库慢则转应用层。 | 对应分段下降 |
| 若无效 | → 转 `debug` 做网络、系统或应用 profiling；不要把 DNS/数据库问题继续留在 HTTP 手册里。 | — |

> **预防**：分别监控 TTFB、下载耗时、总耗时和响应大小，保留 HAR/trace。
> **原理**：→ [08-实战经验](08-实战经验.md) 的故障模式 4。

## 🔴 条目 5：代理链信任污染

**一眼识别**：客户端自带一个转发头就能改变日志 IP、限流键、白名单或生成的 scheme；多代理后转发链长度与拓扑不符。

| 步骤 | 条件 / 动作 | 预期 |
|---|---|---|
| **止血** | 在可信入口覆盖/清理外部提交的转发头；暂时停用依赖该字段的高风险白名单规则。 | 不再让用户输入直接影响信任判断 |
| 定位 1 | 受控地测试无头、单头、多头，记录边缘/网关/应用各自看到的值；只用文档保留地址。 | 看出哪一跳错误追加或透传 |
| 定位 2 | 对照部署拓扑列出每跳的覆盖、追加、删除契约；同时记录连接对端地址。 | 明确可信代理边界 |
| 修复 | 由可信代理生成规范链；应用只信任已知代理连接和约定位置，不把头部当认证因子。 | 伪造头不再改变授权/审计结果 |
| 若无效 | → 转“条目 1：认证状态码错位”检查由错误 scheme 触发的认证分支；仍不明 → 转 `debug`。 | — |

> **预防**：把直连、单代理、多代理、伪造头加入部署回归测试。
> **原理**：→ [08-实战经验](08-实战经验.md) 的故障模式 5。

## 🟡 条目 6：HTTP/3 发布回退

**一眼识别**：客户端尝试 H3 后失败并回落 H2/H1；问题集中在部分网络；服务端看不到 UDP/443 或 QUIC 握手。

| 步骤 | 条件 / 动作 | 预期 |
|---|---|---|
| **止血** | 撤回/暂停 H3 广告或灰度开关，确保 H2/H1 入口保持可用；不要强制所有客户端只走 H3。 | 回到可用回退路径 |
| 定位 1 | 记录最终协商协议、回落次数、网络类型和区域；分别测 H1/H2/H3。 | 判断是 H3 单层还是共同入口故障 |
| 定位 2 | 检查 UDP/443、防火墙、负载均衡、QUIC 终止和证书是否在同一入口生效。 | 找到路径或终止点问题 |
| 修复 | 修正 UDP/443/QUIC 配置后按区域灰度；保留可靠 H2/H1 回退。 | H3 成功且失败可回落 |
| 若无效 | → 转“条目 4：慢请求分段定位”确认收益/问题是否其实在 TTFB 或下载；仍不明 → 转 `debug`。 | — |

> **预防**：监控最终协议和回落率，按真实网络分组做验收。
> **原理**：→ [08-实战经验](08-实战经验.md) 的故障模式 6。

## 🔴 条目 7：证书校验失败

**一眼识别**：`certificate verify failed`、主机名不匹配、过期或链不受信；`curl -k` 能通但正常校验失败。

| 步骤 | 条件 / 动作 | 预期 |
|---|---|---|
| **止血** | 回滚到上一张已验证证书/入口配置，或切换到已知正常入口；生产禁止用 `-k` 作为长期路径。 | 恢复可信 HTTPS |
| 定位 1 | 保存主机名、客户端版本、原始错误和证书链摘要；用 `openssl s_client` 带正确 SNI 查看实际送出的链。 | 确认实际证书而非文件名 |
| 定位 2 | 逐项核对 SAN、有效期、链顺序、用途和客户端信任库；比较不同入口/客户端。 | 定位校验项或环境差异 |
| 修复 | 部署覆盖实际主机名的证书和完整链，修正 SNI/路由，或更新受控本地开发信任根。 | 浏览器、curl、SDK 正常校验 |
| 若无效 | → 转 `debug` 做 TLS/代理层现场取证；不要复制生产私钥或永久绕过校验。 | — |

> **预防**：做续期、链完整性和多客户端回归监控。
> **原理**：→ [08-实战经验](08-实战经验.md) 的故障模式 7。

## 🔴 条目 8：HTTP/1.1 报文边界或持久连接错误

**一眼识别**：keep-alive 下请求挂住或响应错位；关闭复用后减轻；trace 中 `Content-Length`、chunked 终止或连接关闭位置异常。

| 步骤 | 条件 / 动作 | 预期 |
|---|---|---|
| **止血** | 回滚最近的 framing/代理变更；无法立刻修复时临时关闭受影响路径的连接复用，并记录性能代价。 | 先停止跨请求污染 |
| 定位 1 | 保存 `curl --trace-ascii` 或原始报文，核对头部终止、Content-Length、chunked 终止和连接关闭。 | 找到消息边界证据 |
| 定位 2 | 同一请求分别用新连接和 keep-alive；复用才失败 → 查前一响应是否被完整消费。 | 区分边界错误与业务错误 |
| 定位 3 | 沿应用→代理→CDN 比较 framing 头是否重复、冲突或被改写。 | 找到首次破坏边界的层 |
| 修复 | 让一个责任层生成合法消息边界；消除冲突 framing 头，修正 chunked/长度处理后恢复复用。 | 同连接多请求稳定 |
| 若无效 | → 转 `debug` 做原始字节级取证；若仅某代理版本触发，保留最小复现并回滚。 | — |

> **预防**：协议回归覆盖固定长度、分块、空正文、keep-alive 和异常断开。
> **原理**：→ [08-实战经验](08-实战经验.md) 的故障模式 8。

## 通用升级出口

1. 记录时间窗口、请求 ID、客户端/协议、原始状态行与关键响应头；敏感值脱敏。
2. 先确定“请求是否到达下一层”，再讨论下一层为什么慢或拒绝。
3. 每次只改变一个变量，保留变更前后样本和回滚点。
4. 仍无匹配或证据互相矛盾 → 转 `debug`；涉及 DNS/TCP/系统/数据库/业务代码时，把取证范围交给对应领域。
