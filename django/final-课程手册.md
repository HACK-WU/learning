## 1 这门课在讲什么

### 一句话

**一个「什么都能干」的 Django 视图函数，怎么把职责一步步交出去，最后瘦成「一份契约」。**

### 故事主线

| 阶段 | 章节 | 主角交出了什么 |
|------|------|--------------|
| 1 | 决定分家 | 交出渲染权，视图开始返回 JSON，模板与 Forms 退场 |
| 2 | 立规矩 | 交出校验（序列化器）、路由（router）、业务逻辑（service） |
| 3 | 守门 | 交出安全（认证 / 权限 / 限流），视图彻底变瘦 |
| 4 | 纵深 | 交出计算（推给数据库），多库与变更有章法 |
| 5 | 扛住真实世界 | 让它快、让它稳，但**别加错东西** |
| 6 | 收尾 | 能验证、能追溯、能上线 |

### 一个贯穿全课的暗线：**「不报错的错误」**

这是全套课程真正的主角。22 课里反复出现的不是"这个 API 怎么用"，而是**同一类事故**——

> 配置写错了、代码漏了、顺序排错了，**但程序不报错、不告警、退出码还是 0**。
> 你以为它在工作，它其实什么都没做。

**全课累计记录了 12 处**，以下是最典型的 7 处：

| 不报错的错误 | 出处 |
|-------------|------|
| `pool={}` 连接池**静默失效** | 课 12 |
| `ready()` 不注册信号 → **全程静默，一条都不报** | 课 17 |
| check 不注册 → **退出码 0，一个报错都没有** | 课 21 |
| 缺 `SECRET_KEY` 时 `check` **退出码 0** | 课 22 |
| 追踪中间件排在认证前 → **日志全是 `anonymous`**，视图却看到 `alice` | 课 18 |
| `patch` 打错位置 → **测试依然绿，但命令真的去调了外部服务** | 课 20、21 |
| `static()` 生产环境 **静默返回 `[]`** | 课 22 |

> 这条暗线在 [08-实战经验.md](./08-实战经验.md) 第二节被提炼成"高频故障模式"，在 [09-排障速查手册.md](./09-排障速查手册.md) 里被组织成可倒查的症状表。
>
> 其余 5 处散落在课 2（CORS 白名单配 `*` 却带凭证）、课 11（`select_for_update` 在 SQLite 上直接抛错，换库才暴露）、课 13（`allow_migrate` 返回 `None` 等于一律放行）、课 14（`atomic=False` 留下半成品迁移）、课 19（删数据库记录后磁盘文件 100% 残留成孤儿文件）。

### 范围边界（先读这个）

本主题是 **Django 进阶**，「前后端分离」是**范围裁剪条件，不是学习目标**。

**不在本范围**（依附服务端渲染，由前端接管）：模板系统与 DTL、Forms 的渲染职责、`render()`/TemplateResponse、Messages 框架、模板语境下的 `{% csrf_token %}`。

**保留但限定边界**：Admin（课 19，只讲定制与安全）、Forms 校验思想（课 3，仅与 Serializer 对照）、staticfiles（课 19，只讲对 Admin 的意义）、CSRF（课 10，压缩为一节）、Session vs Token（课 8，作为选型对比项）。

### 我要设计 API / 划分职责

| 我要做什么 | 看哪课 | 本项目落点 | 最坑的地方 |

### 我要做安全

| 我要做什么 | 看哪课 | 本项目落点 | 最坑的地方 |
|-----------|-------|-----------|-----------|
| 选认证机制 | 课 8 | Session + Token 双认证 | 登出困境——JWT 无状态，**签发后收不回** |
| 做行级权限 | 课 9 | `permissions.py` + `OrderQuerysetMixin`（两个方向） | 只做 queryset 过滤 → **详情接口仍可越权** |
| 配限流 | 课 9 | `OrderCreateThrottle` 显式声明 `scope` | 视图写 `scope` 却配 `UserRateThrottle` → **静默失效** |
| 防越权与批量分配 | 课 10 | `Order.order_no` 用 UUID，不暴露自增 ID | 自增 ID 让**遍历攻击**成本降到零 |

### 我要处理数据

| 我要做什么 | 看哪课 | 本项目落点 | 最坑的地方 |
|-----------|-------|-----------|-----------|
| 原子更新、避免竞态 | 课 11 | `filter(stock__gte=qty).update(stock=F("stock")-qty)` | `select_for_update()` 在 SQLite 上**直接抛错**，换库才暴露 |
| 加索引、加约束 | 课 12 | `CheckConstraint` + `UniqueConstraint` + 两处复合索引 | `pool={}` **连接池静默失效** |
| 多库、主从 | 课 13 | ⚠️ 单库 SQLite，**未演示** | `allow_migrate` 返回 `None` = **一律放行，所有库都建表** |
| 写迁移、改线上表 | 课 14 | `bulk_create` / `bulk_update` 的规模意识 | 大表回填用 `objects.all()` + 逐条 `save()` |

### 我要优化性能

| 我要做什么 | 看哪课 | 本项目落点 | 最坑的地方 |
|-----------|-------|-----------|-----------|
| 治 N+1 | 课 15 | `prefetch_related("items")`，有测试锁 SQL 条数 | `select_related` **不去重实例**；`FETCH_PEERS` 在 `.iterator()` 下失效 |
| 加缓存 | 课 16 | `get_product_cached` + 响应头 `X-Cache` | 缓存键只认 `Authorization`，**自定义身份头会串号** |
| 判断要不要上 async | 课 16 | 本项目链路同步，未用 | async 里调同步阻塞 → **慢 4.2x** |
| 决定用不用 signal | 课 17 | **`ready()` 保持空实现**，改用 `_write_audit` 显式调用 | `ready()` 不注册 → **全程静默，一条都不报** |

### 我要上生产

| 我要做什么 | 看哪课 | 本项目落点 | 最坑的地方 |
|-----------|-------|-----------|-----------|
| 加链路追踪 | 课 18 | `middleware.py`（contextvars）+ `logfmt.py`（JSON） | 中间件排在认证前 → **日志全是 `anonymous`**，视图却看到 `alice` |
| 处理文件上传 | 课 19 | `obj.image.url`，不手工拼 `/media/` | `django.conf.urls.static()` 只在 `DEBUG=True` 挂载 → **上线即 404** |
| 提速测试、生成文档 | 课 20 | `factories.py` + `testhealth` + `exportdocs --check` | `patch` 打错位置 → **测试依然绿，但真调外部服务** |
| 把脚本变成命令、把约定变成检查 | 课 21 | 三个命令 + 六条 check | check 不注册 → **退出码 0，一个报错都没有** |
| 配密钥、部署、上线 | 课 22 | `settings_prod.py` + `deploy.sh` + `ci_check.sh` | 缺 `SECRET_KEY` 时 `check` **退出码 0**；`bool(os.getenv("DEBUG"))` **恒为 True** |

### 一次下单经过了什么

🔬 **本图为运行时抓取**（probe_13，2026-09-04）：在 service / `_write_audit` / `invalidate_product_cache` 三处打点，实际发一次 `POST /api/v1/orders/`，抓到的真实顺序如下。

```
POST /api/v1/orders/  -> HTTP 201
  ├─ 中间件：RequestContextMiddleware（contextvars 存 trace_id）
  ├─ 认证：Session / Token
  ├─ 限流：OrderCreateThrottle（显式声明 scope）
  ├─ 序列化器：校验字段（显式 fields，不用 __all__）
  ├─ service：create_order          ← 抓到
  │    ├─ 幂等键检查（UniqueConstraint 兜底）
  │    ├─ F() 条件更新扣库存         ← 实测 SQL：SET stock = (stock - 3)
  │    ├─ bulk_create 明细           ← 实测 1 次下单 3 条 INSERT
  │    └─ _write_audit 写审计        ← 抓到（显式调用，非 signal）
  └─ 事务提交后：invalidate_product_cache  ← 抓到
```

**三项实测断言**（均为运行时抓取，非源码推断）：

| 断言 | 实测结果 |
|------|---------|
| 扣库存是 `F()` 原子更新 | ✅ `UPDATE shop_product SET stock = (stock - 3) WHERE id=1 AND stock >= 3` |
| 明细走 `bulk_create` | ✅ 一次下单 3 条 INSERT（订单 + 明细 + 幂等记录） |
| 审计真的写入 | ✅ `AuditLog` 条数 = 3（显式调用生效，非 signal） |

> ⚠️ **纠正一个容易想当然的点**：trace_id **只在错误响应里返回**，成功响应（201）**不含** trace_id——实测已确认。它主要用于串联日志，不是给成功路径用的。

### 六条 check 与四个命令

**六条 check**（团队约定 → 可执行的检查）：

| 约定 | 级别 | 判据 |
|------|------|------|
| 手写路径必须在 router 之前 | **Error** | 会静默 405 |
| check 模块必须被 `ready()` import | **Error** | 不注册时全不执行（最典型的静默失败） |
| 生产配置缺安全开关 | **Error** | 直接导致安全事故 |
| schema 必须与代码同步 | Warning | 文档错了不影响运行 |
| 序列化器不得用 `__all__` | Warning | 会泄漏新字段 |
| 字段应有 `help_text` | Warning | 文档缺说明 |

> **Error 还是 Warning 的判据**（课 21）：**会不会直接导致测试失败或线上事故**。会 → Error，CI 必须拦；不会 → Warning，应当修。

**四个命令**：`testhealth`（三段计时体检）、`exportdocs`（schema 导出 + `--check` CI 模式）、`seed_demo`（造演示数据）、`payorders`（批量支付）。

## 8 学完之后

### 自检清单

按这 12 项自查，能全部答上来说明这套东西真正落地了：

1. 能不能说清分离后 Django 退场了哪些能力，替代方案是什么（课 1）
2. 每个 ModelSerializer 是否都显式列了 `fields`（课 3）
3. 业务逻辑是否还在 view 里（有 `if 业务规则` 就是还在）（课 7）
4. 所有写操作是否用 `F()` 或显式事务，避免"先读后写"（课 11）
5. receiver 是否都用 `on_commit` 包住外部副作用（课 17）
6. 批量路径（`bulk_create` / `update`）是否自己补了信号该做的事（课 17）
7. 追踪中间件是否排在 `AuthenticationMiddleware` **之后**（课 18）
8. 慢查询日志是否有「只记最慢 N 条 + SQL 截断」两道防线（课 18）
9. 团队约定是否都进了 System checks（且 check 模块被 `ready()` import）（课 21）
10. 敏感配置是否走 `raise` 而非默认值——缺 `SECRET_KEY` 时 check 是**不报错**的（课 22）
11. `patch` 是否打在**使用处**而非定义处（课 20、21）
12. 提速结论是否在**目标环境**重新量过（课 20）

### 三句话带走

1. **Django 提供的是扩展点，不是默认行为**——把代码删掉不报错、只是"少了一点效果"，那就是扩展点。check 不注册、signal 不注册，都属于这一类。
2. **先量后改**——执行只占测试耗时的 4%，一上来优化"用例怎么写"最多省 4%。
3. **让静默失败变成显式失败**——能写成 check 的写 check，check 查不到的用 `raise` 让进程起不来。
