## 阶段 1：为什么要前后端分离（课 1-2）

| 课 | 知识点 | 在本项目的落点 |
|----|--------|---------------|
| 课 1《从模板渲染到 API 契约》 | 渲染权移交后退场的能力；契约先行 | `serializers.py` 全部——API 的输入输出边界由序列化器定义，而非模板 |

## 阶段 2：DRF 核心三件套（课 3-7）

| 课 | 知识点 | 落点 |
|----|--------|------|
| 课 3《序列化器：API 的边界守门人》 | 显式 `fields`，不用 `__all__`/`exclude` | `serializers.py` 每个 Meta 都显式列字段；`checks.py` W002 自动检查这条约定 |
| 课 4《序列化器进阶》 | 可写嵌套、动态字段、快照明细 | `models.py` 的 `OrderItem.product_name` / `unit_price` 是**快照**（商品改名不影响历史订单），不是冗余 |
| 课 5《视图层：从 APIView 到 ViewSet》 | view 变胖会泄漏不一致的错误结构；路由遮蔽 | `apps/common/exceptions.py` 统一错误结构（含 `trace_id`）；`config/urls.py` 手写路径排在 router 之前 |
| 课 6《API 版本控制》 | 版本策略 | 本项目用 URL 前缀 `/api/v1/`（`config/urls.py`） |
| 课 7《业务逻辑该放哪》 | 业务逻辑放 service，view 只做三件事 | `services.py` 是全部业务规则的归集处；`views.py` 里没有任何 `if 业务规则` |

**课 5 的路由遮蔽坑**：`checks.py` 的 `check_route_order`（E001）会问 URL 解析器"这条路径到底落到了哪个视图"，被吃掉就报 Error。

## 三个"脚本"是怎么变成"命令"的

课 21 的核心动作之一。三个原本是临时脚本的东西，现在都是正式命令：

| 原来的临时脚本 | 现在的命令 | 新增了什么 |
|---------------|-----------|-----------|
| 体检脚本（实验 41 三段计时） | `manage.py testhealth` | 参数可配（`--cases`/`--seed`）、`--verbosity` 进度、`--json` 结构化输出、退出码 |
| schema 导出（实验 33） | `manage.py exportdocs --file schema.yaml` | `--check` 模式供 CI 用、`--fail-on-warn`、路径处理 |
| 多版本文档导出（实验 30） | 同上（本项目单版本，用 URL 前缀 `/api/v1/` 区分） | — |

**"脚本"变"命令"才有的四样东西**（`testhealth.py` 的模块注释里写了）：
参数可配置、进度输出、退出码、结构化输出。缺任何一样，CI 都拦不住。

## 四条"约定"是怎么变成 System checks 的

| 团队约定 | 级别 | 判据 | 落点 |
|---------|------|------|------|
| 手写路径必须在 `include(router.urls)` 之前 | **Error** | 会静默 405，测试直接失败 | `checks.py` E001 |
| check 模块必须被 `AppConfig.ready()` import | **Error** | 不注册时检查全不执行，是最典型的静默失败 | `checks.py` E002 |
| 生产配置缺安全开关 | **Error** | 会直接导致安全事故 | `checks.py` E003 |
| schema 文件必须与代码同步 | **Warning** | 文档错了不影响运行，但迟早出问题 | `checks.py` W001 |
| 序列化器不得用 `__all__`/`exclude` | **Warning** | 现在能跑，但会泄漏新字段 | `checks.py` W002 |
| 字段应有 `help_text` | **Warning** | 文档里会缺字段说明 | `checks.py` W003 |

**Error 还是 Warning 的判据**（课 21 反复强调）：会不会直接导致测试失败或线上事故。会 → Error，CI 必须拦；不会 → Warning，应当修。

⚠️ 一个踩过的坑（值得记住）：E003 最初写成 `if settings.DEBUG: return []`，结果**一跑测试就报 3 条错误**——因为 Django 测试运行器会强制把 `DEBUG` 设为 `False`，于是"不是 DEBUG"被误判成"是生产"。现已改为检查显式哨兵 `IS_PRODUCTION_DEPLOY`。
