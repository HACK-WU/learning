## P1 问题清单

### P1-① 缺术语表（与课 16 体例不一致）

**问题描述**

课 16 在开场有一张「先对齐几个术语」表，本课初稿**没有**。

本课密集出现的术语：`receiver`、`sender`、`dispatch_uid`、`on_commit`、`fast_delete`、`隐式调用链`。其中 `fast_delete` 是 Django 内部概念，学员大概率没听过；`dispatch_uid` 的"uid"容易被理解成"唯一 ID"（确实是，但它的**去重语义**需要解释）。

**这是体例不一致**——课 15、课 16 都有术语表，本课缺了会让学员觉得"这课讲得没那么细"。

**修改建议（已采纳）**

在开场补一张术语表，7 条：`receiver` / 信号 / `sender` / `dispatch_uid` / `on_commit` / `fast_delete` / 隐式调用链。

### P1-② 2.3 节的反直觉点没有"点破"

**问题描述**

2.3 节给了一张批量操作的信号矩阵，数据完整，但**最关键的那个反直觉点被埋在表格里**：

| 操作 | `pre_save` | `post_save` | `pre_delete` | `post_delete` |
|------|-----------|-------------|--------------|---------------|
| `queryset.update()` | **0** | **0** | 0 | 0 |
| `bulk_create()` | **0** | **0** | 0 | 0 |
| `queryset.delete()` | 0 | 0 | **3** | **3** |

学员看完这张表的第一反应会是"哦，批量操作不发信号"——**然后就会记错**。因为 `queryset.delete()` 那一行的 3 摆在那儿，但表格的视觉重心在前面两个"0"上。

初稿只在表格后写了一句「不发信号的是 `update` 家族」，力度不够。

**修改建议（已采纳）**

1. 在表格下方用**加粗 + 独立段落**强调这个反直觉点
2. 写进「高频误区」表
3. 做成自检题第 2 题（"下列操作哪些发信号"），让学员主动回忆

### P1-③ 3.4 节迁移路径缺"双触发"这个真实陷阱

**问题描述**

3.4 节讲了迁移三步法，但初稿的第三步只说「正解是用一个开关让两条路径互斥」，**没说清楚会发生什么**。

学员读完会以为"shim + service 双写"只是"有点冗余"，不知道它的实际后果是**通知发两遍、邮件发两封**。

而且这个陷阱**在真实迁移中几乎必然发生**——你把 service 写好了、老代码还没改完，两条路径同时生效是过渡期的常态。

**修改建议（已采纳）**

1. 先给出**不加开关时的实测数据**（新路径 2 封 vs 老路径 1 封），让学员看到后果
2. 再给 `by_service` 开关的解法
3. 补一句"等所有调用点都改成显式调用，再把 shim 整个删掉"

### P1-④ 缺"怎么确认生产环境挂了哪些 receiver"的自检手段

**问题描述**

1.2 节讲了"`ready()` 忘了 import 会静默失效"，并说了一句「自查手段（实验 33 给出了完整脚本）」——但**脚本内容在第四幕，第一幕看到这句话时拿不到**。

这是必查项 #11（关键结论须有可验证的自检手段）的典型场景：讲义说"你要检查 X"，但没给"怎么检查 X"。

**修改建议（已采纳）**

1. 在 1.2 节**就地给出**最小可跑的检查片段（而不是只说"见实验 33"）
2. 在 4.4 节给出完整版体检脚本
3. 在自检题第 12 题专门问这个
