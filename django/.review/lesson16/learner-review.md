## 二、问题 1：缓存

### ✅ 答到了，且有量化

| 我的疑问 | 讲义给的 | 出处 |
|----------|----------|------|
| 加了缓存能快多少 | 1 条 SQL → 0 条；200 次 108.5ms → 74.4ms | 实验 1 |
| 加哪一层 | 四层对照表 + 前后端分离只用中间两层 | 1.2 节 |
| 粒度怎么选 | 整列表 1 条 vs 对象级 50 条冷启动对照 | 实验 4 |
| 什么时候清 | `on_commit` 删，**不要用 set 更新** | 实验 7 |

**特别是 2.2 节**——"事务回滚了缓存却留着新值"，这个坑我以前根本没想过。讲义给了三种场景对照（白清 / 留脏 / on_commit 正确），还标了"不一致会持续到 TTL 且无任何报错"，说服力强。

### ⚠️ L1-① 2.5 节版本化方案没说清"多花的那条查询值不值"

**问题**：方案 A（版本化）每次读都要先 `aggregate(Max("updated_at"))` 花 1 条 SQL。讲义只说"版本化要多花 1 条聚合查询"，但没回答**学员真正想问的**：我为了不手工清缓存，反而每次读都多花一条查询，这笔账划算吗？

**判定**：这是"给了事实没给权衡"，属于 L1。

**修复**：已补一段权衡说明——版本化的那条聚合是**走索引的 count 级查询**（`updated_at` 上有索引时接近零成本），而手工失效的成本是**人的记忆**（漏一处就是脏数据，且脏数据不报错）。所以写路径分散时，多花一条查询换"不可能漏"是划算的。同时补了 `updated_at` 必须建索引的前提，否则那条聚合会变成全表扫描。

### ✅ 2.3 节穿透：推翻了流行说法，很有价值

"把空值缓存起来防穿透"我以前就是这么写的。讲义实测出：None 确实存进去了（`has_key=True`），但 `cache.get` 对"无键"和"值为 None"都返回 None，所以**每次都当成 miss 去查库**——形同虚设。

而且顺带验证 `cache.get(key, sentinel)` **也区分不了**，这才堵死了我"那我改用哨兵值"的念头。给的答案（`has_key`）是唯一可靠的。

## 三、问题 2：async

### ✅ 答到了，且有反直觉证据

| 我的疑问 | 讲义给的 | 出处 |
|----------|----------|------|
| async 能快多少 | 5 次 50ms IO：252ms → 58ms（4.37x） | 实验 12 |
| 写了 async 就并发吗 | **不是**——一处 `time.sleep` 就卡死整个循环 | 实验 13 |
| ORM 在 async 里会变快吗 | 不会，5 次查询跑在同一个线程 | 实验 15 |
| 那什么时候值得用 | 四场景表 + IO 次数量化表 | 3.7 节 |

**3.3 节是本课对我最有用的一节**。"async 不是写了 async def 就并发，loop 里任何一处同步 IO 都会卡死整个事件循环"——这解释了我们项目里"上了 async 反而更慢"的怪现象。

### ⚠️ L1-② 3.3 节没给"怎么发现自己踩了这个坑"的手段

**问题**：讲义告诉我"同步阻塞会卡死循环"，但我怎么知道**我的 async 视图里有没有同步阻塞**？靠读代码一个个看吗？

**判定**：给了"是什么"没给"怎么查"，属于 L1。

**修复**：已补两个可操作的自检手段——

```python
# ① 用 asgiref 的探测：同步上下文里调用会抛错
from asgiref.sync import async_to_sync
# 在 async 视图里，任何 Django ORM 调用都会抛 SynchronousOnlyOperation
# 反过来：如果它没抛错，说明你那段代码其实跑在线程里，不是在事件循环里

# ② 最直接的办法：看 IO 期间事件循环还能不能动
async def probe():
    async def tick():
        for _ in range(10):
            await asyncio.sleep(0.01)
    t0 = time.perf_counter()
    await asyncio.gather(your_view_logic(), tick())
    # 如果 tick 的 10 次 tick 没有均匀铺开，而是挤在某一段 → 有阻塞
```

### ✅ 3.7 节的量化表很实用

"1 次外部 IO 省 0%，3 次省 66%，5 次省 79%"——这张表让我能直接算自己项目的收益，而不是记一句"IO 多的时候用 async"。

## 四、问题 3：任务框架

### ✅ 答到了，且三条硬约束都是实测

| 我的疑问 | 讲义给的 | 出处 |
|----------|----------|------|
| 内置框架怎么用 | `@task` + `enqueue` 最小形态 | 实验 19 |
| 有什么限制 | 模块级函数 / 参数须 JSON 兼容 / **默认后端同步执行** | 4.1 节 |
| 缺什么 | **无 Beat、无重试、无编排**（三条全部实测） | 实验 24、25 |
| 怎么选 | 六场景表 + 四步判断顺序 | 4.6 节 |

**4.1 节的第三条（默认后端同步执行）是我最需要的一条**。我以前以为 `enqueue()` 就是"丢出去"，本地测试秒返回还挺高兴——讲义直接指出"本地快所以秒返回，上线后邮件服务慢，enqueue 就跟着慢"。

### 🚨 L1-③ 4.2 节"任务异常被吞"缺一条可直接抄的检查代码

**问题**：讲义说了"异常塞进 `result.errors`，`enqueue` 不抛"，也说了"不检查 status 等于静默失败"。但**没给一段可以直接抄的检查代码**。学员看完知道要检查，但不知道怎么写。

**判定**：这是"知道要做但不知道怎么做"，属于 L1 但优先级高。

**修复**：已补一段可直接复制的检查封装：

```python
def enqueue_checked(task, *args, **kwargs):
    """enqueue 的带检查版本：失败时立刻记日志，不让任务静默失败。"""
    result = task.enqueue(*args, **kwargs)
    if str(result.status) == "FAILED":
        err = result.errors[0] if result.errors else None
        logger.error(
            "任务 %s 失败：%s",
            task.module_path,
            err.exception_class_path if err else "未知错误",
            exc_info=None,
            extra={"traceback": err.traceback if err else ""},
        )
    return result
```

并说明为什么需要它：`enqueue()` 不抛异常，所以 `try/except` 包 `enqueue` **完全拦不住**任务内部的错误。

### ✅ 4.4 节 DummyBackend 的"读返回值抛 ValueError"很及时

我原本以为配了 dummy 后端就能 `assert result.return_value is None`。讲义实测出会抛 `ValueError: Task has not finished yet`（因为状态停在 READY），并给了源码位置 `tasks/base.py:240`。省了我一次调试。

### ⚠️ L1-④ 缺术语直白解释表

**问题**：课 15 有"术语直白解释表"（实例去重 / savepoint / 隔离级别 / fetch mode 传播），本课出现了同样密度的新术语——**Vary**、**事件循环**、**thread_sensitive**、**ImmediateBackend**、**穿透/雪崩**、**ASGI/WSGI**——但没有集中解释。

**判定**：前后体例不一致，属于 L1。

**修复**：已在第一幕开头补一张术语表（见下表）。

| 术语 | 直白解释 |
|------|----------|
| Vary | 响应头里的一句话，告诉缓存"我的内容还跟这些请求头有关"，决定缓存键里要不要带上它们 |
| 事件循环 | 单线程里轮流执行所有协程的那个调度器；一个人卡住，所有人都得等 |
| thread_sensitive | `sync_to_async` 的开关，打开表示"同一段 async 代码里的同步部分共用一个线程"（为了保护数据库连接） |
| ImmediateBackend | 内置任务框架的默认后端，`enqueue` 时**当场同步执行**，不是丢给后台 |
| 缓存穿透 | 查一个根本不存在的数据，缓存里永远没有，每次都打到数据库 |
| 缓存雪崩 | 大批缓存同一时刻集体过期，那一瞬间数据库被全部流量命中 |
| ASGI / WSGI | 两种服务器接口协议；WSGI 同步（一请求一线程），ASGI 异步（事件循环，支持长连接） |
