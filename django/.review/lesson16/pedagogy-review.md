## 六、问题清单

### P1-① 2.4 节雪崩示例：TTL 采样与写入脱节（已修）

**问题**：原稿写成

```python
for i in range(100):
    cache.set(f"jitter:{i}", value, 60 + random.randint(0, 30))   # 写入时现算
ttls = [60 + random.randint(0, 30) for _ in range(100)]            # 又算了一遍
```

写入用的 TTL 和记录用的 TTL 是**两批随机数**，日志里的分布并不反映实际写入。这是"演示代码自己就不自洽"。

**修复**：改为先采样、再复用同一个值写入（与自检题 12 的答案保持一致）。这处已在实验 5 中同步修正，实测输出 `最小 60s，最大 90s`。

**为什么是 P1 不是 P0**：不影响结论正确性（抖动确实有效），但属于"讲义里给出的代码与它声称的结论对不上"，是必查项 #27 的范畴。

### P1-② 1.4 节缺少"怎么确认你的缓存键里有什么"的自检手段

**问题**：讲完 Vary 机制后，读者知道了原理，但不知道**怎么在自己的项目里确认**。这是 learner 视角最容易卡住的地方。

**修复**：已补一段：

```python
from django.utils.cache import _generate_cache_header_key, get_cache_key
# 先看当前 URL 的 headerlist 键里存了什么
header_key = _generate_cache_header_key("", request)
print(cache.get(header_key))        # 比如 ['HTTP_AUTHORIZATION'] 或 []
```

配合实验 34 的 A/B 对照，读者能自己验证。

### P1-③ 第四幕缺"从异步到任务"的过渡

**问题**：第三幕讲完 async 边界后直接跳到内置任务框架，两幕之间缺衔接——读者会疑惑"既然 async 能并发等待，为什么还要任务队列"。

**修复**：已补 4.0 过渡段，点明 async 解决"请求内的等待"、任务解决"要挪出请求的慢活"，二者的分界是**用户愿不愿意等这 30 秒**。

### P1-④ 3.5 节异步 ORM 的"价值"表述不准确

**问题**：原稿写"异步 ORM 的价值在于不占线程，不是更快"——这句对，但没说清楚**什么时候这有价值**。

**修复**：补一句上下文：在**高并发长连接**场景（WebSocket/SSE）下，不占线程 = 能撑更多连接；在普通短请求场景下，收益接近零。避免读者误以为异步 ORM 是普适优化。

## 七、本课教学价值评估

### 最有价值的三个发现

1. **缓存键 = URL + Vary，且只有 `Authorization` 有自动兜底**（实验 34）
   备课预设"缓存键不含请求头"被实测推翻，查源码才看清三步生成流程。对多租户系统是**数据泄露级**风险，且完全不报错。

2. **存 None 挡不住穿透**（实验 6、9）
   流行说法"把空值缓存起来防穿透"只对了一半——None 确实存进去了（`has_key=True`），但 `cache.get` 对"无键"和"值为 None"都返回 None，调用方区分不了。`get(key, sentinel)` 也区分不了。这是**又一个"看起来正确实则无效"的流行做法**。

3. **`enqueue()` 默认同步执行 + 异常不抛**（实验 20、23）
   两个坑叠在一起：本地快所以"秒返回"的假象，上线后异常被吞进 `result.errors`。这是本课第二处"不报错的错误"。

### 与前序课程的串联

| 串联点 | 出处 |
|--------|------|
| 缓存与 N+1 是叠加关系（先治 N+1 再加缓存） | 1.1 节回指课 15 |
| `on_commit` 清缓存的必要性 | 2.2 节坐实课 15 的结论 |
| `thread_sensitive` 与数据库连接数 | 3.4 节回指课 12 公式 |
| 限流的缓存依赖 + 多进程配额翻倍 | 2.6 节闭环课 10 |
| `.iterator()` 与 `bulk_*` 的放大检验 | 1.2 节回指课 14、课 15 + 必查项 #28 |
| 任务信号不跨事务 | 4.5 节预告课 17 |
