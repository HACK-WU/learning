## L1（应修复）

### L1-1　3.1.1 的骨架代码没有"完整可跑"的上下文

**问题**：给了 `Command` 类的完整代码，但没说**这个文件该放在哪、文件名叫什么**。读者知道要放 `management/commands/`，但 3.1.2 才讲这个——顺序上倒挂了。

**影响**：照着 3.1.1 敲完不知道存成什么文件名，跑 `manage.py hello` 会报 Unknown command。

**修复建议**：在 3.1.1 的代码块前加一行注释或说明："保存为 `apps/shop/management/commands/hello.py`"，或者把 3.1.2 的"在哪儿被发现"提前到 3.1.1 之前。

### L1-2　3.3.2 的 patch 对照表，缺"我怎么知道该 patch 哪个"

**问题**：四组对照（实验 35-39）讲清楚了"早绑定要 patch 使用处"，也说了"看命令模块顶部写了什么 from 语句"。但**如果读者面对的是一个陌生的命令**，怎么快速定位？

**对比**：课 16 的 L1-③ 补了"怎么发现 async 里有同步阻塞"的探针。本课缺同类手段。

**修复建议**：补一个可执行的定位方法，比如：
```python
import apps.shop.management.commands.payorders as m
print(m.pay.__globals__.keys())  # 看 pay 函数从哪个命名空间取 charge
```
或者更简单：打印 `pay.__module__` 确认它在哪个模块里被定义。

### L1-3　3.2.3 的 check 注册代码没说 `app_configs` 参数是什么

**问题**：`def check_route_order(app_configs, **kwargs)` —— 这个 `app_configs` 从哪来、什么时候有值、什么时候是 None？正文完全没提。

**影响**：读者写自己的 check 时会照抄这个签名，但不知道 **Django 只在 `manage.py check <app_label>` 时才传具体值**，平时是 None。这会导致"想只对某个 app 做检查"时写错。

**修复建议**：补一句说明 + 一个判断示例（`if app_configs is None: 检查全部`）。

### L1-4　4.1 的运行方式依赖一个写死的 Python 路径

**问题**：
```powershell
& "C:\Users\v_wypgwu\.workbuddy\binaries\python\envs\dj-course\Scripts\python.exe" count_assertions.py
```
这是**本课作者的本机路径**，读者照抄必然失败。

**对比**：课 20 的 L1-④ 补了 Windows PowerShell 等价写法。本课应该先给通用形式。

**修复建议**：改成 `python count_assertions.py`，然后在下方注明"本课实测用的是 dj-course venv 的 Python 3.13.14"，把绝对路径放到括号里当注释而非命令主体。

## L2（建议修复）

### L2-1　1.1 的三句对话可以再"狠"一点

现在的抱怨比较温和。真实场景里更痛的是：运维把脚本挂在 cron 上，脚本崩了但退出码是 0，监控一片绿，三天后才发现数据没同步。建议把第三句改得更具体。

### L2-2　5.5 高频误区表缺"命令名与文件名"这一条

新手常问：为什么我把文件叫 `myCommand.py` 就不能用 `--myCommand`？建议补一条：
| "命令名可以和文件名不一样" | **命令名 = 文件名**，想改命令名就改文件名 |

### L2-3　5.6 自检题 C-2 的"列出三种可能"没给答案

C-1 和 C-2 都是开放题。C-1 给了提示（退出码 / `--no-input` / stdout 缓冲），C-2 只给了提示（settings 差异 / 文件存在性 / `--fail-level`）但没展开。建议至少给一个方向性答案。

### L2-4　4.3 实验清单可以给"时间预算"

52 个实验全跑要多久？建议标注"全量回归约 X 秒"，让读者知道值不值得跑。
