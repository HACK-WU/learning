## P1-① 第一幕的工单没有给出"如何确认"的路径

**问题**：第一幕讲「四个环节全对，结果是错的」，很有代入感。但读完后学员知道"现象是什么、根因在 4.3 节"，中间缺少一个**可执行的排查路径**。

课 18 的做法值得对齐——它在 3.4 节给了「三分钟自检」（curl + grep + 三个排查方向）。本课第一幕提出问题后，要到第四幕 4.5 节才有检查点，跨度太大。

**建议**：在第一幕 1.2 节的三行表格之后，补一个「五分钟定位」小节，给出最小排查序列：

1. `ls` 确认文件在不在 `MEDIA_ROOT`
2. `python manage.py shell -c "from django.conf import settings; print(settings.DEBUG)"` 确认 DEBUG
3. 检查 `urls.py` 里 `static()` 是否被 `if settings.DEBUG:` 包着
4. `curl -I` 实际访问一次

这样第一幕就能自洽，不必等到第四幕。

## P1-② 2.12 节孤儿文件只给了对策，没给「怎么发现」

**问题**：实验 18 证明了"删光记录磁盘不降"，很有冲击力。但讲义只说了"生产上这就是磁盘莫名满了的原因"，没给学员**怎么发现孤儿文件**的手段。

这是必查项 #11 的典型场景——关键结论须有可验证的自检手段。

**建议**：补一个扫描脚本，把「数据库有的」与「磁盘有的」做差集：

```python
import os
from pathlib import Path
from django.conf import settings
from apps.core.models import Attachment

# 数据库里引用的文件（注意：用 values_list 取全量，
# 10 万条时不要把所有对象读进内存 —— 必查项 #28）
db_names = set(Attachment.objects.values_list("file", flat=True))

# 磁盘上真实存在的文件
disk_names = {
    str(p.relative_to(settings.MEDIA_ROOT)).replace("\\", "/")
    for p in Path(settings.MEDIA_ROOT).rglob("*")
    if p.is_file()
}

orphans = disk_names - db_names
print(f"数据库引用 {len(db_names)} 个，磁盘 {len(disk_names)} 个，孤儿 {len(orphans)} 个")
```

⚠️ 注意这里必须用 `values_list(flat=True)`，不能 `for obj in Attachment.objects.all()` 再取 `obj.file.name` —— 后者在 10 万条时会把全表读进内存，正是必查项 #28 要防的。这本身就是个好教学点。

## P1-③ 3.3 节的 update() vs save() 取舍讲得不够透

**问题**：3.3 节正确指出 `queryset.update()` 是 1 条 SQL，也提了一句"`update()` 不触发 signal"，但只是轻描淡写。

这恰恰是本课与课 17 的**强连接点**，也是学员最容易踩的坑：运营在 Admin 点了"批量通过"，结果依赖 `post_save` 的审计日志**一条都没记**，而界面显示"已通过 30 条"。

**建议**：把这段升级成一个明确的决策对照：

| 场景 | 选哪个 | 代价 |
|------|--------|------|
| 纯状态流转，无副作用 | `update()` | 快，但 signal 不触发 |
| 有审计/通知/缓存失效 | 逐条 `save()` 或 `update()` + 显式调用 | 慢，但副作用不丢 |
| 数据量大到 save() 跑不动 | `update()` + 显式补做副作用 | 需自己保证一致性 |

并明确一句：**"Admin 的 action 里选 `update()`，等于默认这批操作不需要 signal"** —— 这个决定必须由写代码的人明确做出，而不是默认发生。
