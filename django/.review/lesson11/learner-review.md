## 三、认可点

1. **第一幕的三个场景把三个知识点串得很好**：阅读数不准 → 库存超卖 → 列表很慢，最后点出"根因是同一个：把本该数据库做的算术搬到了 Python 里"。这个收束让我一眼就明白这一课要干什么。

2. **"困惑二"解答了我真正的疑问**。我看到竞态的第一反应就是"加个事务不就行了"，讲义直接说"默认隔离级别下两个事务都能读到同一个旧值"——把我脑子里的错误方案提前堵住了。

3. **`select_for_update` 在 SQLite 上静默失效**这个太有用了。我一直用 SQLite 做本地开发，从来没想过锁相关的代码根本没被测试过。讲义还给了 `compiler.py:840` 的行号，我可以自己去验证。

4. **`update()` 返回值的用法是真正的收获**。以前我只把它当"执行成功了"，没想到 `rows == 0` 可以直接用来判断库存不足，省掉一次 SELECT。实验 5c 那个 `1 1 0 0` 的输出特别直观。

5. **多值关系的 AND 陷阱纠正了我的想当然**。我一直以为 `Q(a) & Q(b)` 和链式 filter 是一回事，看到"前者 0 件、后者 1 件"的实测才反应过来 JOIN 次数不一样。讲义还解释了"两次 JOIN vs 一次 JOIN"，让我能理解而不只是记住。

6. **6.1 新函数给了"本机能跑吗"的对照表**，而不是罗列一堆 API。`UUID7` 那行标了 ❌ 并说明要 Python 3.14，我立刻就知道自己现在用不了，不用去试错。

7. **UUID7 的隐私提醒很有价值**。只说"性能好"的教程很多，但提醒"它会泄露毫秒级创建时间、用户可见 URL 要用 v4"的很少。

8. **`fetch_mode` 的顺带发现**。虽然讲义说这属于阶段 5，但提前告诉我"6.1 有个框架级 N+1 解法"让我对后面的课有预期。

9. **误区速查表 14 条**，几乎每条都是我可能会犯的，尤其"F() 可以引用别的行的字段"这种想当然。

10. **结尾一句话把"静默错误"三条并列**（Subquery 漏分组、SQLite 的 FOR UPDATE、Q()&Q() 多值关系），形成了很强的记忆点——它们都不报错，只给你错的结果。
