## 🎯 本课目标

- 装好 `deepagents` 并确认版本 >= 0.7（后面 `delete` 工具与 opt-in 行为都依赖它）
- 配好一个支持 tool calling 的模型 provider
- 跑通一个最小 deep agent，看到它真的调用了文件工具

---

## 装什么（最小集）

只装后续 12 课真的会用到的四样东西。**不预装**向量库、LangSmith SDK、部署工具——那些到对应课再按需加。

| 项 | 版本 / 要求 | 为什么是它 |
|----|------------|-----------|
| Python | `>=3.11,<4.0` | `deepagents` 的硬性 `Requires-Python`，不是建议值 |
| `deepagents` | `>=0.7`（本文实测 `0.7.28`） | 课程主体；`<0.7` 没有 `delete` 工具，任务规划也还是默认开启 |
| 一个 provider 集成包 | 至少一个 | 光装 `deepagents` 不能调模型，见下方"坑 2" |
| 一个模型 API key | 支持 tool calling | 硬要求，不支持 tool calling 的模型直接跑不起来 |

`deepagents` 会自动带上这些依赖（实测装完即有的版本）：

| 包 | 实测版本 | 说明 |
|----|---------|------|
| `langchain` | 1.4.6 | 核心构件层，`create_deep_agent` 的返回值就是它的 agent |
| `langchain-core` | 1.6.12 | messages / tools / runnable 基类 |
| `langgraph` | 1.2.16 | 运行时（durable execution / streaming / interrupt） |
| `langchain-anthropic` / `langchain-google-genai` | 自动带上 | 这两个被列为**核心依赖**，所以开箱就能用 Claude 与 Gemini |

> ⚠️ 注意最后一行带来的错觉：**`langchain-openai` 不在核心依赖里**。很多人以为"装了 deepagents 就什么模型都能用"，实际用 OpenAI 会当场报 `Initializing ChatOpenAI requires the langchain-openai package`（见"坑 2"）。

---

## 装什么（TypeScript 侧）

Python 侧那套依赖在 TS 世界换成 npm 包，**版本号独立演进**——不要拿 `deepagents 0.7.28` 去 npm 找，TS 版现在是 `1.15.1`。

| 项 | 版本 / 要求 | 为什么是它 |
|----|------------|-----------|
| Node.js | `>=20`（本文实测 `22.22.2`） | LangGraph JS 的运行时要求 |
| `deepagents` | `^1.15.1` | 课程主体，TS 版入口 `createDeepAgent` |
| `@langchain/core` | `^1.2.20` | 与 `deepagents` 的 peer 要求一致 |
| `@langchain/langgraph` | `^1.5.1` | 运行时 |
| `@langchain/openai` | `^1.6.2` | 走 OpenAI 兼容端点时必需 |
| 一个模型 API key | 支持 tool calling | 同 Python 侧 |

一条命令装齐：

```bash
npm i deepagents@^1.15.1 @langchain/core@^1.2.20 @langchain/langgraph@^1.5.1 @langchain/openai@^1.6.2
```

TypeScript 侧的 peer 依赖比 Python 侧宽松，但**装错版本会直接 `ERESOLVE` 失败**。本课程把实测通过的组合固定在 `playground-ts/package.json` 里，直接 `npm i` 即可。

> 💡 与 Python 侧最大的不同：TS 的 `deepagents` 把 Anthropic 也列为 peer（不是核心依赖自动带上），所以**开箱不会自动获得任何模型集成**。你必须显式装 `@langchain/openai` 或 `@langchain/anthropic`。

## 怎么装

### 主路径：uv（推荐，隔离干净）

```bash
uv init
uv add deepagents
uv sync
```

官方 quickstart 给的正是这四行。如果你想单独开一个练习目录而不污染现有项目：

```bash
mkdir -p ~/da-playground && cd ~/da-playground
uv venv .venv
uv pip install --python .venv/bin/python deepagents
```

> 📌 实测提醒：`uv venv` 建出来的环境**不带 `pip`**。所以后续装包要么继续用 `uv pip install --python .venv/bin/python xxx`，要么先 `uv pip install --python .venv/bin/python pip`——直接敲 `.venv/bin/pip` 会得到 `No such file or directory`（见"坑 1"）。

### 备选 A：pip（已有虚拟环境的老项目）

```bash
pip install deepagents
```

差异就一句话：不帮你锁依赖树，版本冲突时得自己解。

### 备选 B：装在已有 LangChain 项目里

如果你已经有 `../langchain/langchain/playground/` 这类环境，直接 `pip install deepagents` 即可——它会把自己需要的 `langchain>=1.4.6` 一并拉齐。差异是：**不要**为了跑本教程去降级已有的 `langchain`，`deepagents 0.7.28` 要求 `langchain>=1.4.6`，降级反而会装不上。

### 再装一个 provider 包（按你用的模型选）

前面说过只有 Anthropic 与 Google 是核心依赖。用其他家的，补一行：

| 你的模型 | 补装 |
|---------|------|
| OpenAI / Azure OpenAI | `uv pip install --python .venv/bin/python langchain-openai` |
| 通义 / 火山 / 其他 OpenAI 兼容端点 | 同上，走 `base_url` 覆盖 |
| Ollama 本地 | `uv pip install --python .venv/bin/python langchain-ollama` |

### 配 key

```bash
export OPENAI_API_KEY="..."        # 或 ANTHROPIC_API_KEY / GOOGLE_API_KEY / ...
export TAVILY_API_KEY="..."        # 仅当你不用 provider 内置搜索、要自己接 Tavily 时才需要
```

官方 quickstart 明确说明：Google / OpenAI / Anthropic **都自带服务端网页搜索工具**，不需要额外装包也不需要 Tavily key。只有用 OpenRouter、Fireworks、Baseten、Ollama 这类 provider 时，官方示例才要求额外配 `TAVILY_API_KEY`。

> 🔐 key 只进环境变量或 `.env`，不要写进代码、不要提交。这是后面课 5 讲权限时的同一条纪律。

## 验证：装好了吗

三步，逐条过。前两步不需要任何 key，第三步才要。

### 第 1 步：包在不在、版本够不够

::: code-group

```bash [Python]
python -c "import deepagents, sys; print('deepagents', deepagents.__version__); print('python', sys.version.split()[0])"
```

```bash [TypeScript]
node -e "const p=require('./node_modules/deepagents/package.json'); console.log('deepagents', p.version); console.log('node', process.version)"
```

:::

实测输出：

::: code-group

```text [Python]
deepagents 0.7.28
python 3.12.13
```

```text [TypeScript]
deepagents 1.15.1
node v22.22.2
```

:::

版本号卡一条硬线——`>=0.7`：

::: code-group

```python [Python]
import deepagents
from packaging.version import Version

v = Version(deepagents.__version__)
print("OK" if v >= Version("0.7") else f"版本过低：{v}，需要 >= 0.7")
```

```typescript [TypeScript]
import { createRequire } from "node:module";

const require = createRequire(import.meta.url);
const v: string = require("deepagents/package.json").version;
// TS 版没有内置版本比较工具，这里按 major.minor 手工拆
const [major, minor] = v.split(".").map(Number);
const ok = major > 1 || (major === 1 && minor >= 15);
console.log(ok ? "OK" : `版本过低：${v}，需要 >= 1.15`);
```

:::

> 为什么 Python 非要 0.7：① `delete` 工具是 0.7 才加的，课 4 要用；② 任务规划的默认行为在 0.7 变了（转 opt-in），课 10 要用。版本不对，这两课的现象会和文档对不上——这正是最容易让人误判"文档写错了"的地方。
>
> 为什么 TS 卡 1.15：`createDeepAgent` 的参数对象形态在 1.15 稳定下来（`systemPrompt` / `interruptOn` 等驼峰命名已固定），更早的版本参数名与本文不一致。

### 第 2 步：装配能不能建起来（不花一分钱、不联网）

这一步是本课最实用的检查：**只构造 agent、不调模型**，就能看到 harness 到底替你装了什么。

::: code-group

```python [Python]
# check_assembly.py
from deepagents import create_deep_agent

agent = create_deep_agent(model="openai:gpt-5.4", tools=[])
tool_names = sorted(agent.nodes["tools"].bound.tools_by_name)

print("工具数：", len(tool_names))
print(tool_names)
print("图节点：", list(agent.nodes))
```

```typescript [TypeScript]
// l01-setup.ts 的核心片段
import { createDeepAgent } from "deepagents";

const agent = await createDeepAgent({ model: "openai:gpt-4o-mini", tools: [] });

// 工具从各中间件的 tools 字段汇总，不是从 options.tools 读
const collected: string[] = [];
for (const mw of agent.options.middleware ?? []) {
  const t = (mw as { tools?: unknown }).tools;
  if (!t) continue;
  const arr = typeof t === "function" ? (t as () => unknown[])() : (t as unknown[]);
  for (const x of arr ?? []) {
    const n = (x as { name?: string }).name;
    if (n) collected.push(n);
  }
}
const toolNames = [...new Set(collected)].sort();
console.log("工具数：", toolNames.length, toolNames);
console.log("中间件层数：", (agent.options.middleware ?? []).length);
```

:::

实测输出：

::: code-group

```text [Python]
工具数： 9
['delete', 'edit_file', 'execute', 'glob', 'grep', 'ls', 'read_file', 'task', 'write_file']
图节点： ['__start__', 'model', 'tools', '_ParentNotifierMiddleware.after_agent', 'PatchToolCallsMiddleware.before_agent']
```

```text [TypeScript]
FilesystemMiddleware -> ls,read_file,write_file,edit_file,delete,glob,grep,execute
subAgentMiddleware -> task
工具数： 9
中间件层数： 5
中间件清单： FilesystemMiddleware, subAgentMiddleware, SummarizationMiddleware, patchToolCallsMiddleware, UnsupportedContentMiddleware
```

:::

三个值得现在记住的观察：

- **两侧工具清单完全一致：9 个**——8 个文件工具 + 1 个 `task`（派子代理用）。注意 `execute` 也在这份**静态清单**里：工具构造时就注册好，真正发给模型前还会按后端能力再裁一遍（后端不支持的会被摘掉，而不是让模型调用失败）。所以"清单里有"不等于"模型一定能用"——课 6 会把这条讲透。
- **装配成员两侧不同**：Python 裸栈实测 7 条中间件（比 TS 多 `_ParentNotifierMiddleware` 与 `AnthropicPromptCachingMiddleware`），TypeScript 默认 5 条。**图节点数不等于中间件条数**——`_ParentNotifierMiddleware` 与缓存中间件不在节点名里。**这是行为差异**：TS 版默认不带提示缓存，需要时自己挂。
- **读法也不同**：Python 从 `agent.nodes["tools"].bound` 读，TS 从 `agent.options.middleware` 里各中间件的 `tools` 字段汇总。两侧都不是公开 API，只适合做环境自检，别写进业务代码。

> 💡 第 2 步在 Python 侧需要一个能**构造**的模型对象，所以得先有 provider 包，但**不需要真实 key**（构造过程不发网络请求）：
>
> ```bash
> OPENAI_API_KEY=sk-placeholder python check_assembly.py
> ```
>
> 若跳过假 key，会得到 `openai.OpenAIError: Missing credentials...`——不是装错了，只是没给它一个字符串。
>
> TypeScript 侧更宽松：`createDeepAgent({ model: "openai:gpt-4o-mini" })` 传字符串即可，连假 key 都不用设，因为字符串模型在 `invoke` 时才真正初始化。

### 第 3 步：真的跑一次

::: code-group

```python [Python]
# hello_deep_agent.py
from deepagents import create_deep_agent

agent = create_deep_agent(
    model="openai:gpt-5.4",          # 换成你实际可用的 provider:model
    tools=[],
    system_prompt="你是一个严谨的助手。需要暂存中间结论时，先写进文件再继续。",
)

result = agent.invoke({"messages": [{"role": "user", "content": "把 1 到 5 的平方算出来，写进 squares.md，然后读回来确认。"}]})
print(result["messages"][-1].content)
```

```typescript [TypeScript]
// hello_deep_agent.ts
import { createDeepAgent } from "deepagents";

const agent = await createDeepAgent({
  model: "openai:gpt-5.4",          // 换成你实际可用的 provider:model
  tools: [],
  systemPrompt: "你是一个严谨的助手。需要暂存中间结论时，先写进文件再继续。",
});

const result = await agent.invoke({
  messages: [{ role: "user", content: "把 1 到 5 的平方算出来，写进 squares.md，然后读回来确认。" }],
});
const last = result.messages.at(-1);
console.log(typeof last?.content === "string" ? last.content : last?.content);
```

:::

> ⚠️ **未实测（本机无 provider key）**：输出为参考示例。预期你能看到模型先调 `write_file` 再调 `read_file`，最后一句自然语言回答；文件落在**内存态**里（默认 `StateBackend`，会话结束即消失——课 5 会讲这件事）。
>
> 想看见完整调用过程，Python 侧把 `agent.invoke(...)` 换成 `for chunk in agent.stream(..., stream_mode="updates")`；TypeScript 侧把 `invoke` 换成 `streamEvents(..., { version: "v3" })`（课 13 详解）。或在环境里设 `LANGSMITH_TRACING=true` + `LANGSMITH_API_KEY` 到 LangSmith 看面板。

三条全绿 = 环境就绪。

## 常见安装坑

| 症状（报错关键字） | 原因 | 解法 |
|-------------------|------|------|
| `timeout: failed to run command '.venv/bin/pip': No such file or directory` | `uv venv` 默认不装 pip | 用 `uv pip install --python .venv/bin/python <包>`，别直接敲 `.venv/bin/pip` |
| `Initializing ChatOpenAI requires the langchain-openai package` | OpenAI 集成不在 `deepagents` 核心依赖里（只有 Anthropic / Google 在） | `uv pip install --python .venv/bin/python langchain-openai` |
| `openai.OpenAIError: Missing credentials. Please pass an api_key ...` | 模型对象构造时就要一个 key 字符串，哪怕不联网 | 临时检查用 `OPENAI_API_KEY=sk-placeholder`；真跑换成真 key |
| `LangChainDeprecationWarning: Passing model=None to create_deep_agent is deprecated and will be removed in deepagents==1.0.0` | 不传 `model` 时走的是即将删除的兼容路径 | **永远显式传 `model`**。别依赖默认值——1.0 起 `model` 会变成必填 |
| 版本 `0.6.x` 上找不到 `delete` 工具、`write_todos` 却默认出现 | 装到了 0.7 之前的版本 | `uv pip install --python .venv/bin/python -U "deepagents>=0.7"` |
| 模型能对话但从不碰文件工具 | 模型不支持 tool calling，或 provider 前缀写错导致降级 | 先确认是 `provider:model` 格式（前缀决定用哪个 LangChain 集成）；再换官方推荐模型（`gemini-3.6-flash` / `gpt-5.5` / `claude-opus-4-8` 一类） |

> 上表第 2、3、4 条是实测撞到的原始报错；第 1 条也是实测（`uv venv` 后直接调 `.venv/bin/pip`）；第 5、6 条来自文档与版本对照，未复现。
