## 功能验收

- [x] `uv sync` 后 `uv run python demo.py` 一键跑通全部 7 个场景（实测：7 场景全部输出正常）
- [x] **政策咨询**：问"七天无理由退货"→ 回答引用《退换货政策》来源（实测：检索相关度 0.652，回答含版本号 v2.1）
- [x] **订单查询**：问订单 A1003 → 调用 `query_order` + `query_logistics`（实测：物流轨迹"预计 09-18 送达"正确）
- [x] **大额退款审批**：399 元退款 → 出现「审批请求 → 批准 → 执行」流程（实测：审批参数 `{"order_id": "A1001", "amount": 399}`，批准后工具执行、账本记录）
- [x] **小额退款直通**：29 元退款 → 无审批直接执行（实测：未触发中断，`process_refund` 直通）
- [x] **PII 脱敏**：发手机号 → 对话状态中存储 `****5678`（实测：完整号码不出现在状态与后续任何环节）
- [x] **多轮记忆**：同会话两轮，第二轮"它发货了吗"命中第一轮的订单（实测：消息数 7 条累积，回答引用 A1003）
- [x] **转人工**：投诉场景 → `escalate_to_human` 生成工单号（实测：工单 T-20260916-01；模型自动携带用户 ID 与会员等级作为背景）
- [x] `uv run python -m app.cli`：交互式对话可用，流式输出 + 审批交互（实测：流式打字机输出；输入 y 批准后完成退款）

## 非功能验收

- [x] **安全（PII）**：手机号 / 邮箱在进入模型前打码（实测见功能验收第 7 条；单元测试 `test_phone_detector_matches_cn_mobile` 覆盖正则边界）
- [x] **错误处理（金额校验）**：退款金额与订单实付不符时拒绝执行（实测：单元测试 `test_refund_amount_mismatch_rejected` 通过，返回"校验不通过"说明）
- [x] **护栏（分级审批）**：≥ 50 元中断、< 50 元直通（实测：单元测试两条分支分别通过）
- [x] **成本护栏（限额）**：模型调用上限 / 退款次数上限均实测生效——退款工具连续请求 3 次时：执行 2 次、第 3 次被拦（tool 消息 "Tool call limit exceeded. Do not call 'process_refund' again."）；模型调用上限 15 次时：恰好 15 次调用后优雅收尾（实测探针，离线剧本驱动）
- [x] **可维护性（测试套件）**：`uv run pytest tests/` 快速层 7 项通过（0.73 秒）；`-m integration` 集成层 2 项通过（70.57 秒）
- [x] **可观测（审计）**：demo 实测输出 11 条审计轨迹（工具名 / 参数 / 耗时 / 结果摘要），业务账本记录 2 笔退款 + 1 次转人工
