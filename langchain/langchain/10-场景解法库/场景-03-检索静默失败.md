# 场景 3：知识库答不准，还悄悄"静默失败"（经典设计题）

**场景描述**：知识库上线后抽查 20 个问题："答非所问"3 个、"资料未涵盖"4 个，但监控上**零报错**——全链路静默失败。

**🔒 先自己想 30 秒**：是检索坏了，还是模型坏了？先修哪一半？

<details><summary>💡 提示（分层 / 分维度想）</summary>

把链路拆开验证：文档**在不在库里**（切分后还在吗）？命中的**是哪一块、分数多少、排第几**？换个**措辞**会怎样？——"检索"和"生成"的锅要分开定。

<details><summary>📖 展开解法</summary>

### 解法一览（效果按"召回命中 / 实现成本"对比）

| 解法 | 效果（召回改善 / 成本） | 代价 | 适用边界 |
|------|----------------------|------|---------|
| A · 调切分参数（chunk_size / overlap） | 治"答案被切碎 / 块内杂质多" | 要评估对照（课 11 三档切分实测方法） | 文档结构规整 |
| B · 调 k 值 / 手动阈值过滤 | 治"差一名被截断"（k=3→k=4 让答案块进场） | k 大引入杂质、挤占 prompt | 块级检索 |
| C · 查询改写（Agentic RAG 多步检索） | 去掉高相似度噪声词，命中答案块 | 多一次模型调用 | 长查询 / 带无关词 |
| D · 强制引用 + "不知道"兜底话术 | 防编造、可追溯（不改善召回） | 需在提示词与验收中坚持 | 所有场景都该有 |

### 各解法详解（含关键代码）

#### 解法 B：k 值探针——先看清"答案块排第几"

把"命中了哪一块、排第几"打出来——这是区分"检索没送到"与"模型没用好"的关键证据（课 11 完整案例：k=3 时答案块排第 4 名、分数 0.5615，被一刀切在门外）。

```python
# 检索质量探针：k 值扫描（课 11 定位"k 截断"用的方法）
query = "员工年假天数 政策"
for k in (1, 2, 3, 4, 5):
    retriever = vector_store.as_retriever(
        search_type="similarity",
        search_kwargs={"k": k},
    )
    docs = retriever.invoke(query)
    hit = any("年假" in d.page_content for d in docs)   # 期望答案块是否进入窗口
    print(f"k={k}: 期望块命中={hit}（共 {len(docs)} 条）")
```

> 为什么这么写：**k 是调出来的，不是猜出来的**——k 小可能截断答案，k 大召回全但杂质多（还挤占 prompt）。先跑扫描找到"命中窗口"，再定 k。

#### 解法 A：切分参数对照（评估方法）

切分粒度直接决定"答案会不会被切碎"。课 11 的评估方法：**同一份文档跑三档切分**，把目标问题的命中块打印出来对照——块太大，杂质多；块太小，答案被切开。

```python
# 对照要点（完整脚本见 playground/lesson-11-*-lab.py，三档切分实测）
# 1) 每档切分后统计：块数 / 平均块长
# 2) 对固定问题集跑检索：期望块是否完整落在某个块内
# 3) 对照标准：答案块完整率 + 命中排名，而不是"感觉"
```

> 为什么这么写：切分没有万能参数——**参数要配着评估调**（课 11 结论）。先建问题集，再动参数。

#### 解法 C：查询改写——把检索变成工具，让模型自己"换个说法再查"

```python
@tool
def search_policy(query: str) -> str:
    """检索员工政策知识库。输入应包含关键实体与意图。"""
    docs = vector_store.similarity_search(query, k=4)
    return "\n\n".join(d.page_content for d in docs)
```

> 为什么这么写：课 11 实测——用户原话里的"高相似度噪声词"（公司名等）把无关块顶到前面；agent 改写后的查询（保留"员工年假天数 政策"）直接命中答案块。把检索包成工具交给 agent，改写就发生在它发现"没查到"之后。

#### 解法 D：强制引用 + 兜底话术（提示词片段）

```text
只依据【检索资料】回答问题。
资料未涵盖时，明确回答"资料未涵盖，建议咨询人工"，不要推测。
每个结论标注来源：[来源: 文档名]。
```

> 为什么这么写：检索质量短期修不好时，**诚实兜底**是最后的防线——"资料未涵盖"比"自信编造"安全（对照 Air Canada 判例：编造政策由公司担责）。

### 替代路线（非本课程技术栈）

| 替代方案 | 思路 | 与本课程解法的差异 |
|---------|------|------------------|
| 混合检索（关键词 BM25 + 向量 + 重排） | 双路召回后精排 | 召回更稳（专有名词、编号类查询尤其）；引入检索组件与调优成本 |
| 全文检索系统（ES / 站内搜索） | 换非向量路线，词项精确匹配 | 精确词命中强、结果可解释；语义泛化弱（换个说法就找不到） |

### 推荐路径（递进，不是一次全上）

1. 先建**质量基线**（问题集 → 期望命中块），把"感觉不准"变成"可量化"
2. A / B 调参（便宜、当天可验证）——课 11 完整案例：k=3 截断的答案块在 k=4 起进入
3. 仍不准 → C（查询改写）；D 始终开启（诚实 > 编造）

### 什么情况下此方案不适用

- 知识库里**根本没有答案**：先补数据，调参救不了"无源之答"
- 高精度专业检索（法律 / 医疗条款）：语义相似度不够用，需混合检索 / 重排（见替代路线）
