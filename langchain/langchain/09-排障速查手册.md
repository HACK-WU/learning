## 🔴 症状 1：循环停不下来 / 成本失控

**一眼识别**：任务简单但"模型 → 工具 → 模型"多轮不收敛；抛出 `GraphRecursionError`（报错含 "You can increase the limit by setting the `recursion_limit` config key."）；调用次数异常增长

| 步骤 | 动作 | 预期 |
|------|------|------|
| **止血** | 停掉当前进程；把 `recursion_limit` 调小（`config={"recursion_limit": N}`） | 循环立刻中止在设计范围内 |
| 定位 1 | 打印消息序列，找"重复出现的同一个工具调用" | 找到反复调用的工具 = 它的返回值让模型不收敛 |
| 定位 2 | 检查是否配置 `ModelCallLimit` / `ToolCallLimit` | 没有 = 无兜底防线，确认是"无预算"问题 |
| 修复 | 配限额中间件 + 显式 `recursion_limit` + 修问题工具的返回设计 | 重跑：调用数落在预期内、任务正常收尾 |
| 若无效 | → 转「症状 2 / 症状 3」；仍不收敛转 `debug` 现场排查 | — |

> **预防**：每个工具上线前验证"失败返回是否让模型收敛"
> **原理**：→ [08-实战经验.md](08-实战经验.md) · 故障模式 2

## 🔴 症状 2：工具异常打停 agent

**一眼识别**：工具抛业务异常后 agent 运行**直接中断**——控制台是原始异常栈、没有最终回复；同输入可复现

| 步骤 | 动作 | 预期 |
|------|------|------|
| **止血** | 用固定输入复现；把该工具临时替换为"返回错误字符串"版本 | 对话恢复可用，先保住其他功能 |
| 定位 1 | 看异常栈归属 | 定位到具体工具（业务异常，非模型问题） |
| 定位 2 | 检查该工具：有 try/except 吗？配了 handle_errors 吗？ | 都没有 = 默认冒泡，确认根因 |
| 修复 | 工具内兜底返回结构化错误说明；或配 handle_errors；要"模型自修正"用 `wrap_tool_call` 转 ToolMessage | 异常场景下模型能拿到错误并继续 |
| 若无效 | → 转 `debug` 现场排查 | — |

> **预防**：每个工具明确"失败契约"并写进测试
> **原理**：→ [08-实战经验.md](08-实战经验.md) · 故障模式 1

## 🟡 症状 3：限额拦下了调用

**一眼识别**：tool 消息 `Tool call limit exceeded. Do not call 'xxx' again.`；或 `Model call limits exceeded: run limit (2/2)`

| 步骤 | 动作 | 预期 |
|------|------|------|
| **止血** | 先判定"拦对了还是拦错了"：防滥用场景拦对（无需动作）；正常业务被拦 → 调限额 | 业务恢复正常 |
| 定位 1 | 查限额配置：`thread_limit` / `run_limit` / `exit_behavior` | 明确是哪道闸门、阈值多少 |
| 定位 2 | 看被拦后模型行为（工具限额默认 `continue`：模型继续跑、可能如实说明；"优雅收尾"需显式配 `end`） | 判断是"静默降级"还是"硬中断" |
| 修复 | 调整限额数值或 `exit_behavior`；被拦场景补"先说明、后降级"的产品逻辑 | 重跑：不再误伤，防滥用仍有效 |
| 若无效 | → 转「症状 1」（可能是无预算循环的次生现象） | — |

> **预防**：限额值与业务量校准；监控"被拦次数"（被拦本身是信号）
> **原理**：→ [08-实战经验.md](08-实战经验.md) · 故障模式 2

## 🟡 症状 4：中断恢复失败（HITL）

**一眼识别**：能拿到中断提案（`__interrupt__`），但 `Command(resume=...)` 报 `RuntimeError`；或恢复后模型又发起一次原始请求（二次中断）

| 步骤 | 动作 | 预期 |
|------|------|------|
| **止血** | 暂缓恢复；把本轮对话换新 `thread_id` 隔离，避免反复失败污染现场 | 会话可继续（重新走一遍交互） |
| 定位 1 | 检查 create_agent 是否挂 checkpointer | 没挂 = 命中根因（中断"存不下来"） |
| 定位 2 | 挂了仍报错 → 检查恢复时 `thread_id` 与中断时是否一致；二次中断看 edit 幅度 | 对齐 thread_id；判断是否属"重大修改" |
| 修复 | 挂 `InMemorySaver`（生产用持久化后端）；edit 只做小修，大改走「reject + 新指令」 | 中断 → 决策 → 恢复全流程走通 |
| 若无效 | → 转 `debug` 现场排查 | — |

> **预防**：中断恢复路径进集成测试
> **原理**：→ [08-实战经验.md](08-实战经验.md) · 故障模式 6

## 🟡 症状 5：结构化输出被拒 / 拿不到

**一眼识别**：请求结构化输出被服务端拒绝（多与思考模式相关）；中间件里切 `response_format` 报错；或 `OUTPUT_PARSING_FAILURE`

| 步骤 | 动作 | 预期 |
|------|------|------|
| **止血** | 临时降级为文本输出，先保证对话可用 | 功能不阻塞交付 |
| 定位 1 | 是否开启思考模式？关掉重试 | 通过 = 服务端对该模式有限制（确认根因） |
| 定位 2 | `response_format` 候选是否**创建时**用 `ToolStrategy(A \| B)` 声明？ | 未声明 = 违反本版本要求（官方示例亦有此坑） |
| 修复 | 关思考 / 创建时声明候选、中间件只收窄 / 解析失败改工具调用式结构化输出 + 更明确格式指令（官方建议） | 结构化输出稳定拿到 |
| 若无效 | → 转 `debug` 现场排查（附模型原始输出） | — |

> **预防**：动手前小脚本先验证（课 4 起立下的规矩）
> **原理**：→ [08-实战经验.md](08-实战经验.md) · 故障模式 9

## 🟡 症状 6：检索静默失败（答不上 / 答偏但不报错）

**一眼识别**：回答"资料未涵盖"或答偏，**全链路零报错**；k 值一动结果就变；使用 `similarity_score_threshold` 时抛 `NotImplementedError`（InMemoryVectorStore 未实现 relevance scores 方法）

| 步骤 | 动作 | 预期 |
|------|------|------|
| **止血** | 无线上"急救"——先划清影响面（哪些问题答不上），必要时开人工兜底渠道 | 用户侧损失可控 |
| 定位 1 | 打印命中块 + 分数 + 排名 | 答案块是否被 k 截断（排第 k+1 名） |
| 定位 2 | k 值扫描（k=1~5）+ 措辞改写对照 | 找到"命中窗口"与措辞敏感性 |
| 定位 3 | 是否用了未实现的 search_type（阈值） | `NotImplementedError` = 接口承诺 ≠ 实现可用 |
| 修复 | 调 k / 切分参数；查询改写（Agentic RAG）；手动阈值过滤替代 | 抽查问题集命中率回升 |
| 若无效 | → 转 `debug`；评估切分链路与嵌入链路 | — |

> **预防**：建检索质量基线（问题集 + 期望命中块）
> **原理**：→ [08-实战经验.md](08-实战经验.md) · 故障模式 5

## 🟡 症状 7：中间件同名判重（AssertionError）

**一眼识别**：启动报 `AssertionError: Please remove duplicate middleware instances.`

| 步骤 | 动作 | 预期 |
|------|------|------|
| **止血** | 启动期错误——先跑通最小组装（移除其一） | 服务可启动 |
| 定位 | 找出两个同类中间件实例 | 确认是"同类默认同名"被判重 |
| 修复 | 给其中一个起唯一 `name="..."`（或合并 / 换不同类） | 组装通过、两件都生效 |
| 若无效 | → 转「症状 8」/ `debug` | — |

> **预防**：中间件清单一处维护（含 name 字段）
> **原理**：→ [08-实战经验.md](08-实战经验.md) · 故障模式 4

## 🟡 症状 8：测试假信号（green ≠ good）

**一眼识别**：A) 单测里 fake 模型传给 create_agent 抛 `NotImplementedError`（bind_tools 未实现）；B) 回放测试报 `OpenAIConnectionError: Connection error.`（网络明明正常）

| 分支 | 动作 | 预期 |
|------|------|------|
| **止血** | 标记失败测试为"待修"，禁止"改断言让它变绿" | 假绿被拦住 |
| 若 A（fake 模型） | 子类化补 `bind_tools`（约 3 行：`def bind_tools(self, tools, *, tool_choice=None, **kwargs): return self`） | 组装通过，单测可跑 |
| 若 B（回放） | 断网对照——断网仍报 = 本地失配（非网络）；比对测试输入与 cassette 是否一致 | 定位到"输入变了没录到" |
| 修复 | B：更新输入后重录 cassette | 回放稳定通过 |
| 若无效 | → 转 `debug` 现场排查 | — |

> **预防**：测试策略三层（单元 / 集成 / Evals）；录制文件纳入版本管理
> **原理**：→ [08-实战经验.md](08-实战经验.md) · 故障模式 8

## ⚪ 症状 9：依赖缺失

**一眼识别**：`ImportError: cosine_similarity requires numpy to be installed`（内存向量库相似度计算）；或 `ModuleNotFoundError: No module named 'xxx'`

| 步骤 | 动作 | 预期 |
|------|------|------|
| **止血** | 局部功能不可用——记录并绕行，别全局瞎装 | 影响面明确 |
| 定位 | 看报错模块名 → 对照项目依赖声明 | 确认是"隐式依赖"还是"漏装" |
| 修复 | 用包管理器加依赖（如 `uv add numpy`，注意先确认） | 功能恢复 |
| 若无效 | → 转 `debug`；检查 Python 环境是否用错 | — |

> **预防**：锁依赖（lockfile）+ 新环境"冒烟跑一遍"全功能
> **原理**：→ [08-实战经验.md](08-实战经验.md) · 落地 Checklist（依赖与版本）

## ⚪ 症状 10：PII 覆盖盲区（未脱敏）

**一眼识别**：安全自查（回显验证）发现手机号等类型在消息原文里未被 mask；或输入侧处理了、输出侧没管

| 步骤 | 动作 | 预期 |
|------|------|------|
| **止血** | 收紧涉及敏感信息的放量；先补 detector 再全量开 | 敏感面停止扩大 |
| 定位 | 对照内建五类（`email / credit_card / ip / mac_address / url`） | 业务类型（如手机号）不在其中 = 需自定义 |
| 修复 | 自定义 detector（正则 / 函数）+ 输入 / 输出两侧都开；密钥类用 block | 回显验证两处都 mask |
| 若无效 | → 转 `debug`；核对中间件顺序 | — |

> **预防**：PII 覆盖清单进安全自查 / CI
> **原理**：→ [08-实战经验.md](08-实战经验.md) · 故障模式 7

## ⚪ 症状 11：tracing 静默失效（收不到数据）

**一眼识别**：接入后 trace 面板空白；无 key 时有 warning（`LangSmithMissingAPIKeyWarning`）+ 后台 401 静默降级；进程中途设置环境变量无效

| 步骤 | 动作 | 预期 |
|------|------|------|
| **止血** | 业务不受影响（追踪与功能解耦），记录"观测缺口" | 知悉盲区 |
| 定位 1 | 环境变量是否**进程启动前**配好（"固化"行为：首次调用时确定，中途改不生效） | 找到未生效环节 |
| 定位 2 | key 是否有效（无 key 静默降级 + 后台 401） | 排除凭据问题 |
| 修复 | 改好环境变量后**重启进程**；更换有效 key | 面板收到 trace |
| 若无效 | → 转 `debug` 现场排查 | — |

> **预防**：接入后"跑一次、看一眼"再宣布完成
> **原理**：→ [08-实战经验.md](08-实战经验.md) · 故障模式 8（测试与观测的假信号）

## 🚑 通用止血动作（不确定是哪类问题时，先把损失停下）

| 场景 | 止血动作 | 代价 |
|------|----------|------|
| 刚改完提示词 / 中间件就出问题 | 回滚到上一版本 | 丢失新功能 |
| 循环 / 成本失控 | 停进程 + 调小限额 | 当前任务中断 |
| 疑似密钥泄露 | 轮换 API key；检查环境变量暴露面 | 需重新配置 |
| 高风险动作疑似误执行 | 人工介入核对（HITL reject / 台账比对） | 人工成本 |

## 附录 A · 官方错误码速查（7 条）

> 来源：LangChain 官方 errors 文档（核查于 2026-09）。⚠️ 其中 4 条文档标注 "Currently only used in `langchainjs`"（JavaScript/TypeScript）——**Python 侧遇到同类问题时表现为供应商 SDK 的原始异常**（401 / 404 / 429 等），处置思路一致。

| 错误码 | 触发 | 处置 | 文档 |
|--------|------|------|------|
| `MODEL_AUTHENTICATION` | 认证失败 / 密钥无效（401） | 核对 key 与端点；检查环境变量拼写、dotenv 是否干扰；可显式传参绕过环境变量 | [MODEL_AUTHENTICATION](https://docs.langchain.com/oss/python/langchain/errors/MODEL_AUTHENTICATION.md) |
| `MODEL_NOT_FOUND` | 模型名不被识别（404） | 核对拼写与格式；代理 / 网关可能限制模型名 | [MODEL_NOT_FOUND](https://docs.langchain.com/oss/python/langchain/errors/MODEL_NOT_FOUND.md) |
| `MODEL_RATE_LIMIT` | 触发供应商限流（429） | 客户端限流 / 响应缓存 / 多供应商分流 / 申请提额 | [MODEL_RATE_LIMIT](https://docs.langchain.com/oss/python/langchain/errors/MODEL_RATE_LIMIT.md) |
| `INVALID_PROMPT_INPUT` | 提示模板缺 / 错变量 | 检查 f-string 花括号转义（`{{ }}`）；`MessagesPlaceholder` 传消息数组；打印实际输入 | [INVALID_PROMPT_INPUT](https://docs.langchain.com/oss/python/langchain/errors/INVALID_PROMPT_INPUT.md) |
| `INVALID_TOOL_RESULTS` | 工具消息与调用不匹配 | 一个 `tool_call_id` 对应一条 ToolMessage；查"缺 / 重 / 孤儿"三类 | [INVALID_TOOL_RESULTS](https://docs.langchain.com/oss/python/langchain/errors/INVALID_TOOL_RESULTS.md) |
| `MESSAGE_COERCION_FAILURE` | 消息格式不合法 | 用标准消息类或 `{role, content}` 字典；示例报错 `ValueError: Message dict must contain 'role' and 'content' keys` | [MESSAGE_COERCION_FAILURE](https://docs.langchain.com/oss/python/langchain/errors/MESSAGE_COERCION_FAILURE.md) |
| `OUTPUT_PARSING_FAILURE` | 输出解析失败 | 改用工具调用 / 结构化输出；更精确格式指令；换更强模型 | [OUTPUT_PARSING_FAILURE](https://docs.langchain.com/oss/python/langchain/errors/OUTPUT_PARSING_FAILURE.md) |
