# 事故初判手册

当有 P1 告警时，按这个顺序做初判，不要跳步。

## 第一步：确认影响面

问三个问题，缺一个就先补齐：

- 谁受影响：全部用户 / 某个区域 / 某个租户
- 什么时候开始：看告警起始时间，不要用"刚才"
- 是否还在扩大：对比 5 分钟前后的错误率

## 第二步：判断是否已知模式

常见模式与对应动作：

| 现象 | 先看哪里 | 第一个动作 |
|---|---|---|
| 5xx 突增但下游健康 | 本服务发布记录 | 回滚最近一次发布 |
| 5xx 突增且下游超时 | 下游依赖健康页 | 摘流 + 通知下游值班 |
| 连接池打满 | 慢查询与连接泄漏 | 重启实例止血，再查泄漏 |
| 磁盘涨满 | 日志与临时文件 | 清日志，别急着扩容 |

## 第三步：定级

- P1：核心链路不可用，或错误率超过 5%
- P2：非核心链路异常，或核心链路降级但可用
- P3：只影响内部效率

定级只写一次，不要在后续对话里来回改。

## 不要做的事

- 不要在没确认影响面前就升级
- 不要同时给出"回滚"和"摘流"两个方案让人选——选一个，说清为什么
- 不要把"已通知"当成"已解决"
