## 课程故事主线

- **主角**：**小谷** —— 一个写了几年 Python 的后端工程师，被安排把一个"一压测就崩"的下单接口用 Go 重写
- **冲突**：Go 的语法三天就能翻完，但写出来的服务**要么数据错乱（并发竞争）、要么内存一路涨（goroutine 泄漏）、要么上线后什么都查不到（没有可观测）**
- **收束**：能独立交付一个带并发控制、可观测、可回滚的 Go 服务，并说清「**该不该用 Go、用到哪一步**」

> 每个阶段是故事的一个"章节"，每课是章节中的一个"情节"。

| 阶段 | 故事章节 | 情节一句话 |
|------|---------|-----------|
| 1 · 语言地基 | 写出第一行，看懂每一行 | 语法比想象中少得多——"少"本身是设计，但代价是处处要显式 |
| 2 · 组合与抽象 | 没有 class，怎么组织代码 | 没有继承、没有异常，靠组合、接口与"错误是值"拼出结构 |
| 3 · 并发模型 | goroutine 不是免费的 | 起一个 goroutine 只要一个关键字，收住它却要一整套机制 |
| 4 · 标准库与网络编程 | 让它对外提供服务 | 标准库几乎够用，但它的默认值不都是生产级的 |
| 5 · 工程化与生产落地 | 从能跑到能交付 | 会写不等于能交付：要能测、能查、能构建、能回滚，还要知道该不该用 |

| **【课 12·`Timer.Stop()` 返回值的准确判据（本课纠错的核心事实）】** 官方 `Stop` 的**首句**是 *"It returns true if the call stops the timer, false if the timer has already expired or been stopped"*，但**同一段紧接着的新句**是 *"For a chan-based timer created with NewTimer(d), **as of Go 1.23**, … **if the program has not received from t.C already and the timer is running, Stop is guaranteed to return true**."* → **按首句写会错**。本课新建探针 `p18_timerstop` 实测 8 种情形：`NewTimer` —— ①未到期 `Stop` → `true`；②已 `Stop` 过再 `Stop` → **`false`**；③**已到期但值从未被接收 → `true`**（老文档说 `false`）；④已到期且值已被接收 → **`false`**；⑤已到期、值未接收时 `Reset(1h)` → **`true`**；⑥`Reset` 后 `Stop` → `true`。**`AfterFunc` 则不同**：②已到期、回调已跑 → **`false`**（**这一格才是老文档说的"没拦住"**）；③立刻 `Stop` 拦回调 → `true`。**结论：`NewTimer` 的 `false` ⟺ 值已被接收过 / 已被 `Stop` 过，"已到期"本身不算。** 另实测 `AfterFunc(...).C == nil` 为 **true**、`NewTimer(...).C == nil` 为 **false**。**方法论教训：文档里"为兼容而保留的老句子"，要拿它后面的新段落一起读。** | 已核实（本机实测 8 格 + 源码） | 高 | 本机 `p18_timerstop` + `$GOROOT/src/time/sleep.go`（核查于 2026-09） |
