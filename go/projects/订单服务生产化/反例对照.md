# 生产反例对照

| 反例 | 短期看起来能跑 | 真实代价 | 本项目的收口 |
|---|---|---|---|
| 每次请求新建 `http.Client` | 单次请求成功 | 连接池和超时策略无法复用，外部服务慢时容易拖垮请求 | `HTTPPaymentClient` 持有一个复用的 `http.Client`，请求再叠加 context timeout |
| 订单写入后直接同步调用支付 | 代码路径短 | 支付抖动直接放大为下单延迟，客户端重试可能重复扣款 | 先落 `pending`，worker 负责有限次数调用，幂等键守住重复提交 |
| goroutine 里忽略 `ctx.Done()` | 正常流量下无感 | 停机时 worker 不能收束，超时请求仍占资源 | worker、支付请求、重试 timer 都受可取消 context 控制 |
| 使用无界队列 | 高峰期暂时不丢请求 | 内存上界消失，延迟和积压不可见 | 有界 channel；满时显式失败并记录指标 |
| 只返回 HTTP 500，不记录订单失败状态 | 客户端知道失败 | 运营无法查询订单最终状态，重试语义不清 | `failed` 状态、`last_error`、`attempts` 同时落库 |
| 把 pprof 挂到公网业务端口 | 排障很方便 | profile 端点暴露运行时信息和高开销操作 | pprof 只在 admin 端口注册，公共端 `/debug/pprof/` 为 404 |
| 只在本机 `go run` | 开发反馈快 | 目标平台、版本、调试信息和容器入口都未验证 | ldflags、`CGO_ENABLED=0`、linux/amd64、Docker 多阶段和 demo 全验收 |
| Docker 默认用 root + 可写根文件系统 | 容器里改文件方便 | 权限边界和篡改面扩大 | scratch、非 root、运行时用内存 DSN 或显式挂载数据卷 |
