# 阶段 4：分布式与生产实践

> 所属课程：Redis 系统学习 ｜ 故事章节：「单机不够用了」——数据量超内存、缓存雪崩、Redis 到底该不该上 ｜ 上一阶段：[阶段 3](../3-持久化与高可用/overview.md)

## 🎯 本阶段目标

- 能设计一套完整的缓存方案并说清每个参数为什么这样定
- 能定位大 key、热 key 与慢查询
- 能判断"这个业务该不该用 Redis"，以及不用 Redis 时该用什么

## 📍 学习重点

- **哈希槽而非一致性哈希**：Redis Cluster 用 16384 个固定槽做分配，这个设计选择决定了伸缩、重定向与多 key 操作的全部行为。
- **三种缓存故障不是一回事**：穿透（查不存在的数据）、击穿（单个热点 key 过期）、雪崩（大批 key 同时过期）成因不同，解法也不同，混为一谈就会用错药。
- **一致性的真相**：Cache Aside 是事实标准，但"先更新数据库还是先删缓存"没有完美答案——**延迟双删也不保证一致**。要理解的是"能接受多久的不一致"。
- **淘汰策略要按业务选**：`allkeys-lru` 不是万能答案，当 Redis 一部分 key 不能丢时，它就错了。
- **生态已分裂**：2024 年许可证变更、Valkey 分叉、2025 年 AGPL 三许可。选型前必须先知道"你说的 Redis 是哪个 Redis"。

## 本阶段产出

- [x] `lessons/lesson-07-分片与集群.md` — 2026-09-01 完成（P0=0）。核心实测：手写 CRC16-XMODEM 与 `CLUSTER KEYSLOT` 20/20 吻合；迁移中间态捕获 `ASK`、完成后捕获 `MOVED`；Lua `numkeys=0` 硬编码 key 连不同节点结果不同；分组 `--pipe` 比逐条 `-c` 快 531 倍。
- [x] `lessons/lesson-08-缓存设计.md` — 2026-09-01 完成（P0=0）。核心实测：布隆过滤器误判率 0.056%（声明 0.1%）、假阴性 0%、每 id 仅 2.24 字节；缓存空值挡不住随机 id（1999/2000 仍穿透）而布隆只穿透 3 次；击穿时无防护 DB 查询 114 次/瞬时并发 106，互斥锁与逻辑过期均降到 1；雪崩时统一 TTL 的 DB 峰值 189 次/秒、随机 TTL 降到 27 次/秒（7 倍）；一致性实测复现"旧值回填不自愈"与"更新缓存乱序"；volatile-* 无 TTL 时退化为 noeviction 致写请求 OOM。
- [x] `lessons/lesson-09-生产实践与选型.md` — 2026-09-01 完成（P0=0）。核心实测：SLOWLOG 记 37ms 而客户端实测 1501ms（差 40 倍，证明慢日志不含网络传输）；大 key 删除阻塞 113.66ms vs 拆分后 0.61ms（185.7 倍），UNLINK 降到 0.45ms；ACL `+@read` 默认包含 `KEYS`（真实连接实测可返回全部键名，须显式 `-keys`）；io-threads 用 Python 客户端测出"越大越慢"是客户端瓶颈假象，换官方 redis-benchmark 后 =4 比 =1 快 3.5 倍（CPU 用量 44.5→78.1）；FT.CREATE 返回 OK 时索引仍在异步构建（立刻查仅命中 10 条，真值 9990）；Hash 分桶比独立 String 省 20.2% 内存；索引查询比全量扫描快 177 倍但额外占 195.7% 内存。
