# 验收清单 · 服务注册发现与配置中心

> 逐项自测。**全部勾选才算真的做成了**——不是"跑起来就行"。

## 功能验收

- [ ] **注册生效**：跑 `python main.py` 后，第 1 步输出两个实例 ID（`demo-svc-1`、`demo-svc-2`）
- [ ] **Consul 侧确认注册**：另开终端执行 `consul catalog services`，能看到 `demo-svc`
- [ ] **发现与调用**：第 2 步能选中实例（注：实例未真实监听端口时调用会失败，属预期；需跑 `demo_service.py` 才能验证真实调用）
- [ ] **真实端到端**：启动 `demo_service.py` 后访问 `http://127.0.0.1:18081/`，响应里 `greeting` 字段等于 KV 中 `demo/greeting` 的值
- [ ] **故障自动收敛**：第 3 步注销一个实例后，剩余健康实例只剩 1 个（消费方代码零改动）
- [ ] **配置热更新**：第 4 步显示"阻塞查询在 XXXXms 内检测到变更"，且新配置包含新写入的值
- [ ] **热更新无需重启**：`demo_service.py` 运行期间改 KV，不重启服务，接口返回值随之变化
- [ ] **领导者选举**：第 5 步第一个 worker 抢锁 True、第二个 False，前者释放后后者抢到 True
- [ ] **集群观测**：第 6 步能打印出 leader 地址

## 非功能验收（三条工程约束）

- [ ] **错误处理**：把 Consul 停掉（`consul leave`）后再跑 `main.py`，应打印友好提示并退出（*而不是抛一长串 traceback*）
- [ ] **降级可用性**：`demo_service.py` 运行中断开 Consul，服务仍能响应请求（用快照中的旧配置）
- [ ] **可维护性**：项目目录下生成了 `config-snapshot.json`；Consul 恢复后服务自动重新同步配置

## 理解验收（能说清才算会）

- [ ] 能说清**为什么用 TTL 检查而不是 HTTP 检查**，以及什么情况下该改用 HTTP 检查
- [ ] 能说清**阻塞查询的 index 为什么必须用响应头 `X-Consul-Index`**，用 body 里的 `ModifyIndex` 会怎样
- [ ] 能说清**为什么客户端超时必须大于 wait 参数**（本项目实测踩过的坑）
- [ ] 能说清**同值重写会不会触发阻塞查询**，以及背后的 index 行为
- [ ] 能说清**Consul 的锁为什么叫"建议性锁"**，以及怎么防止被绕过
- [ ] 能说清**leader 崩溃后新 leader 要等多久才能抢到锁**，以及这个等待期叫什么（LockDelay）
- [ ] 能说清**反例版配置监听的 4 个坑**分别在哪，以及为什么它"能跑通"
