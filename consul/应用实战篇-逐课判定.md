## 一、判定标准

不是每课都必须配实战篇。判定采用两条硬标准：

1. **可实操性**：该课知识点能否在单机（Windows + Consul dev/单机多实例）上跑出可观测结果。纯认知型、纯决策型的课不配。
2. **未被现有项目覆盖**：已被现有实战项目焊进去的知识点，不再重复配套。

按这两条，出现三种结论：

- **配套实战篇**：知识点可实操 + 现有项目未覆盖 → 需要写
- **并入现有项目**：知识点可实操 + 现有项目已覆盖 → 不另写，回指项目
- **不配**：决策/认知型，或受环境限制无法单机实测 → 说明原因

## 四、三份待写实战篇的立项说明

### 实战篇 A：一致性读模式实测（配课 5）✅ **2026-09-17 已完成**

- **干了什么**：起三节点集群，对同一 KV 键分别用三种模式读，并强杀 leader 观测无 leader 窗口内三者表现。
- **实测结论**：
  - 写后立即读，`stale` **10/10 次稳定落后一个版本**（不是偶发）
  - `X-Consul-LastContact` 可量化新旧：default/consistent 恒为 0，stale 为 15/30/45ms
  - **强杀 leader 后约 9.5 秒窗口内，`default` 与 `consistent` 全部返回 500，只有 `stale` 持续返回旧值**
  - **quorum 丢失时（三节点挂两个）stale 也不可用**（返回 404）——stale 换的是"选举期间可用"，不是灾备能力
- **过程中的自我纠错**：初版脚本一直访问 8500，而被杀的正是 node1（8500），导致三种模式全失败——那是"连不上 agent"而非读模式差异。修正为从存活节点读后才得到上面这组数据，该教训已写入正文 4.5 节。

### 实战篇 B：Connect 服务网格最小闭环（配课 7）✅ **2026-09-17 已完成，风险已解除**

- **环境可行性结论（重要）**：原判定为「⚠️ 中低，需先验证 Envoy」。实测确认本机**无 Envoy、无 consul-dataplane**，但 **Consul 2.0.2 自带内置代理 `consul connect proxy`，可跑通完整 mTLS 数据面**——**不需要 Envoy**。降级预案未启用。
- **干了什么**：注册两个带 sidecar 的服务，用内置代理跑通 mTLS 调用，用 intention 控制放行/拒绝，并读取证书与 SPIFFE 身份。
- **实测结论**：
  - 通过 upstream 端口访问 → HTTP 200，mTLS 数据面打通
  - 不带客户端证书连 sidecar → TLS 握手即失败（`TLSV13_ALERT_CERTIFICATE_REQUIRED`）
  - **绕过 sidecar 直连应用端口 → 明文 200**（sidecar 与应用之间是 localhost 明文，应用监听 `0.0.0.0` 时网格可被绕过）
  - intention deny 立即生效，日志含 `Matched L4 intention ... Action: DENY`；改回 allow 后 **82ms 恢复**
  - 证书：根证书 10 年、叶子证书 3 天；身份为 SPIFFE ID
- **与课 7 记录的差异**：课 7 曾记录"删除 intention 后长时间仍生效"，本次**未复现**（2.0.2 + `consul config write` 配置条目方式下秒级生效）。已在正文显式说明差异来源，未重复断言。
- **未覆盖**：七层能力（路径级授权、灰度、流量拆分）需 Envoy，本次未实测。

### 实战篇 C：ACL 生产权限模型落地（配课 8）✅ **2026-09-17 已完成**

- **干了什么**：起 `default_policy = deny` 的 agent，为 web/api/ops 三个角色设计最小权限策略，用 21 项权限矩阵逐条验证越权确实被拒。
- **实测结论**：
  - web 写 `api/` → 403；ops 写 `web/` → 403；web 注册名为 api 的服务 → 403 —— 最小权限生效
  - **递归读（`?recurse=true`）越权返回 404，不是 403** —— 客户端会当成"配置不存在"，导致配置热更新静默失效
  - 匿名列目录/列 keys/查健康实例均返回 **200 空结果**（`{}` / `[]`），看起来像"没数据"实为"没权限"
  - **`operator` 资源不带 label**，正确写法是 `operator = "read"`；写成 `operator_prefix "" { policy = "read" }` 不报错但**权限静默不生效**
  - 策略缺 `session_prefix` 时建 session 直接 403 —— 分布式锁用不了，是 ACL 上线最易漏的一项
