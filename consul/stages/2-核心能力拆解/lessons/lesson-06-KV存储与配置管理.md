# 课 6：KV 存储与配置管理

> ⏳ 本课为骨架，正文将在 Phase 2 展开填充。

## 本课目标

掌握 Consul KV 的核心操作与工程用法，重点评估"KV 当配置中心"的真实成色：能用在哪、和 Nacos/Apollo 这类专业选手差在哪——这是选型中"二合一 vs 专职工具"的关键判断。

## 情节定位

引擎第三站：小林发现 Consul 还带一个 KV 存储，团队里有人说"配置也放它那儿，少养一个组件"。他要验证这个说法的成色。

## 知识点清单

### 知识点 1：KV API 与核心操作

- 关键点：CRUD 与前缀查询（层级 key 的"目录"错觉）
- 关键点：CAS（compare-and-swap）：并发写安全的基石
- 关键点：lock 接口：基于 KV 的分布式锁（及它的边界）

### 知识点 2：KV 当配置中心——用法与局限

- 关键点：标准用法：watch 前缀 + 应用侧热更新
- 关键点：局限清单：无环境模型、无灰度/回滚、无推送审计、无版本 diff
- 关键点：适用判断：简单配置 vs 专业配置管理需求的分界线

### 知识点 3：Consul Template 与集成生态

- 关键点：consul-template：KV → 配置文件 → reload 的自动化链路
- 关键点：envconsul 与应用直连两种姿势
- 关键点：与 Nomad / Kubernetes 的集成形态（注册来源自动化）
