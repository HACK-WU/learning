# 课 1：为什么需要服务注册与发现

> ⏳ 本课为骨架，正文将在 Phase 2 第一批展开。

## 本课目标

理解"服务寻址"这个问题本身：它是怎么随着架构演化被一步步放大的，注册中心为什么是标准答案。这是全课程的问题原点，也是一切选型讨论的前提。

## 情节定位

故事开篇：小林接手微服务化改造，第一个深夜故障电话让他意识到"服务找不到服务"才是最原始的痛。

## 知识点清单

### 知识点 1：服务寻址难题——从硬编码 IP 到动态世界

- 关键点：硬编码 IP / 配置文件维护的崩坏过程
- 关键点：扩缩容与故障漂移：实例列表永远是旧的
- 关键点：容器与云时代：IP 用完即弃，动态性成为常态

### 知识点 2：服务发现的两种模式——客户端发现 vs 服务端发现

- 关键点：客户端发现：调用方自己查注册表、自己负载均衡
- 关键点：服务端发现：中间层（LB/网关）代查代转发
- 关键点：DNS 与 API 两种查询接口的取舍

### 知识点 3：注册中心的核心职责与 CAP 初印象

- 关键点：四大职责：注册/注销、健康检查、查询、变更通知
- 关键点：一致性 vs 可用性：注册表短暂不准 vs 完全不可用
- 关键点：CAP 初印象（为阶段 2 课 5 与阶段 3 对比埋伏笔）
