# 课 2：Consul 是什么与能力全景

> ⏳ 本课为骨架，正文将在 Phase 2 展开填充。

## 本课目标

建立 Consul 的完整心智模型：它从哪来、能干哪六件事、架构上由什么角色组成，以及 2026 年当下的版本与许可证现状（决策关键输入）。

## 情节定位

第一位候选人登场：小林翻 Consul 的履历——HashiCorp 出身、十年演化、以及 2023 年那场许可证风波。

## 知识点清单

### 知识点 1：诞生与定位

- 关键点：HashiCorp 与 2014 年诞生背景（微服务浪潮下的服务发现刚需）
- 关键点：定位演化：服务发现工具 → 服务网络平台（service networking）
- 关键点：单二进制 + Go 实现：部署形态对运维成本的先天影响

### 知识点 2：能力全景图——六大能力

- 关键点：服务发现（DNS + HTTP 双接口）
- 关键点：健康检查（应用级、多类型）
- 关键点：KV 存储；多数据中心支持；Connect 服务网格；（加分项）分层命名空间/分区

### 知识点 3：架构角色——Server / Client / 数据中心

- 关键点：agent 模型：每节点一个 agent 的意义
- 关键点：Server（Raft 仲裁）与 Client（轻量转发）分工
- 关键点：数据中心（DC）边界与 gossip 初印象（为课 5 埋伏笔）

### 知识点 4：版本与许可证现状（2026）

- 关键点：2.x 时代：v2.0.0（2026-05）与维护中的三条版本线（核查于 2026-08）
- 关键点：BUSL 1.1 事件始末：1.16.4（最后 MPL 版）→ 1.17.0 起 BUSL；API/SDK 仍 MPL 2.0
- 关键点：对选型的直接影响预告（深入拆解读在课 10）
