# 课 10：许可证成本与风险

> ⏳ 本课为骨架，正文将在 Phase 2 展开填充。

## 本课目标

算清选型前的三本账：许可证账（BUSL 1.1 到底限不限我）、运维账（养它要花多少）、退出账（想走能不能走掉）。三本账算完，决策的风险面就收敛了。

## 情节定位

技术对比结束，小林进入尽调：法务问许可证、老板问运维预算、架构评审问"将来想换怎么办"。

## 知识点清单

### 知识点 1：BUSL 许可证深度解读

- 关键点：条款拆解：允许复制/修改/再分发，限制"与 HashiCorp 竞争的托管服务"
- 关键点：每个版本发布 4 年后自动转 GPL；API/SDK 保持 MPL 2.0
- 关键点：结论边界：公司内部使用不受限；云厂商转售托管服务才受限（核查于 2026-08）

### 知识点 2：运维成本评估

- 关键点：最小生产拓扑：3 或 5 server + 每节点 client agent
- 关键点：升级成本：版本线跟随（2.0.x / 1.22.x）、Envoy 兼容矩阵（若用网格）
- 关键点：监控与人力：quorum 健康、leader 切换、证书轮换的日常负担

### 知识点 3：迁移与退出成本

- 关键点：耦合面：注册 API、DNS、KV、watch 的使用深度决定迁移难度
- 关键点：双跑方案：抽象层设计（Spring Cloud Commons / 多注册适配）
- 关键点：社区 fork 现状：BUSL 后有无成熟开源分支可退（课内联网核实，避免过时表述）
