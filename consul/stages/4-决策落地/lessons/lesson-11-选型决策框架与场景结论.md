# 课 11：选型决策框架与场景结论

> ⏳ 本课为骨架，正文将在 Phase 2 展开填充。

## 本课目标

收束全课程：把前三个阶段的认知压缩成一套决策框架 + 决策清单 + 典型场景结论，能直接回答"我的场景该不该用 Consul、用它的哪部分、不用换什么"。

## 情节定位

签字时刻：小林把四个阶段的结论装订成三页决策材料，走进选型评审会。

## 知识点清单

### 知识点 1：决策维度清单

- 关键点：四维打分卡：需求匹配 / 技术栈匹配 / 运维能力 / 许可证合规
- 关键点：权重设计：不同团队类型下四维的优先级差异
- 关键点：一票否决项：哪些条件直接出局（如纯 k8s 环境的重复建设）

### 知识点 2：典型场景结论

- 关键点：k8s 原生环境：Service/DNS 已内建，Consul 的增量价值判断
- 关键点：多语言 + 多 DC + 异构（VM+容器混合）：Consul 的高光区
- 关键点：Java/Spring Cloud 单技术栈：Nacos 优先的判断依据
- 关键点：小团队轻量起步：最小可用方案的取舍

### 知识点 3：决策清单与落地路线

- 关键点：该用/不该用的判据清单（可勾选版）
- 关键点：混合策略：注册发现用 A、配置用 B 的组合拳何时合理
- 关键点：试点路线：POC 验证点清单 → 灰度接入 → 全面落地
