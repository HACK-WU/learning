# 教程检索（ki-search 教程库）

## 概述

**目的**：让 AI 在学习场景中把已导入 ki-search 的教程库作为第一信息源——准确检索教程内容并附来源，帮助用户学习、复习与溯源；并在发现教程与实际情况不符时修订回写，保持教程库准确。

**功能**：按教程 scope 检索（一门教程 = 一个 scope）——自然语言疑问走语义检索（默认 hybrid），用户粘贴原文片段走全文检索（fulltext，返回命中行号可精确溯源）；支持读原文、目录导航与本地文件深读；发现教程有误/需补充/需优化时，全文检索定位文件 → 修订工作区文件 → `ki import` 回写更新。

**使用场景**：
- 用户在学/复习某门教程时提问（如"Kafka 的 rebalance 触发条件是什么"）
- 用户粘贴一段教程原文，问"这段出自哪里 / 上下文是什么 / 后面怎么讲"
- 用户说"查教程"、"教程里怎么讲"、"帮我从教程里找找"
- 发现教程内容与实际不符、需补充或需优化时（修订并回写 ki）
- 其他教学类 skill 需要引用教程库内容时

## 定位

**输入**：学习问题（自然语言）；或用户粘贴的教程原文片段；可选的教程名提示

**输出**：检索到的教程内容 + 来源标注（文档路径 / 行号区间）+ 基于教程的回答；修订场景输出改动说明与回写结果

**边界**：
- 查询不改动任何内容；修订时**只改工作区教程文件**，回写**只经 `ki import`**——不直接操作 ki 内部数据
- 数据域是"教程知识"；开发任务的项目记忆查询走 `ki-search-first` / `ki-memory-lookup`，两者不混用
- 检索不到时如实说明，不编造"教程内容"

## 核心原则

1. **先锁 scope，不臆测**：教程在 ki 中以 scope 隔离，scope 名 = 教程名。检索前必须先用 `ki_scope_list` 确认 scope 真实名称——可能有拼写误差（如 kafka 导入为 `kafak`），近似时向用户确认，不自行猜测
2. **未确认教程先反问**：本对话尚未确认教程范围 → 先反问"查哪门教程"（附候选）；已确认过 → 直接复用，不重复问
3. **按输入分流检索模式**：问题无教程原文 → 默认模式（hybrid，语义为主）；消息含粘贴原文 → `mode="fulltext"`（全文精确匹配，不调 embedding）
4. **回答以教程内容为准**：回答优先基于检索到的教程原文；教程未覆盖处用自身知识补充时，必须明确标注"教程未覆盖"
5. **来源必标**：回答附来源（文档路径 + 行号区间；行号不可得时至少给文档 / relation），让用户能跳回原文
6. **深读优先本地文件**：命中后优先用 `sourcePath` 读工作区中的教程原文；拼不出本地文件时回退 `ki_get_module_info` 读 ki 副本
7. **降级不阻塞**：ki 不可用 / 教程未导入 / 未命中 → 如实说明并给出替代路径，不阻塞学习对话
8. **修订走固定三步**：全文检索定位 → 改工作区文件 → `ki import ... --conflict-mode overwrite` 回写；回写**必须带 overwrite**（默认 suffix 会新增副本而非覆盖原文档）

## 执行流程

### Step 0：确认教程 scope

| 输入情况 | 动作 |
|----------|------|
| 本对话已确认过教程 | 直接复用（用户明确换了教程则更新） |
| 本次消息明确提到教程名（"Kafka 教程"、"kafka 那门课"） | 用 `ki_scope_list` 确认 scope 名后检索 |
| 其余（未提教程名，含只提到领域词） | **先反问**确认教程范围，附候选清单（来自 `ki_scope_list`） |

反问示例："你想查哪门教程？（是《Kafka 基础》吗？）"——问题已有领域线索时用**推断 + 请确认**的形态，用户一个"是"即可推进。

找 scope 名：

1. `ki_scope_list` 列出全部 scope（同一对话内已查过可复用结果）
2. 教程名精确匹配 → 直接使用
3. 无精确匹配 → 列出 1-3 个最相近候选向用户确认（**不自行猜测**，如 "kafka" → `kafak`）
4. 列表中确实没有 → 告知"该教程尚未导入"，可转本地文件路径（见「异常与降级」）

反问要点：只列与学习场景相关的候选（教程类 scope），不罗列测试类 scope（如 `iso-*`、`perf-test` 等）；用户需要跨教程对比时，scope 支持逗号分隔聚合检索。

### Step 1：判定检索模式

| 用户输入形态 | 模式 | 理由 |
|---|---|---|
| 问题 / 困惑（无教程原文） | 默认（hybrid：语义 + 全文） | 靠语义召回相关内容 |
| 粘贴了教程原文片段 | `mode="fulltext"` | 精确命中同文段落，返回行号可溯源；不调用 embedding |
| 粘贴原文 + 延伸提问 | 先 fulltext 定位，再基于定位内容回答延伸问题 | 两个需求叠加：先溯源、再回答 |

判据是**消息里有没有教程原文**，不是问题长短或语气。

提取查询片段（fulltext 场景）：优先取**定位特征最强**的片段——含专有名词、命令、代码、唯一表述的句子；粘贴多段时可只取其中一段。

### Step 2：执行检索

**语义检索**（默认，疑问场景）：

`ki_search(scope="<教程scope>", query="<自然语言问题 + 教程关键术语>")`

- query 用自然语言描述问题本质，并带上教程内可能出现的关键术语（专有名词 / 参数名 / 命令名，如 `rebalance`、`max.poll.interval.ms`）——显著提高命中准确度
- 返回 `ok=false` / `degraded=true`（如"向量检索暂不可用"）→ 自动降级为全文检索（见「异常与降级」）

**全文检索**（粘贴原文场景）：

`ki_search(scope="<教程scope>", query="<原文片段>", mode="fulltext")`

- 返回项含 `matches[]`（`lineStart` / `lineEnd` + 原文片段）与 `totalLines`——直接用于定位出处
- 未命中时：截取更独特的一段重试，或换默认模式语义召回
- 导入时会对内容做清洗（代码围栏、frontmatter、代码路径等）——检索片段与本地原文可能有差异、行号可能偏移，**深读、引用与修改一律以本地文件为准**（按内容匹配定位，不唯行号）；query 片段优先取正文表述（避免含完整代码路径的片段）
- 结果中如出现 `ki-path` 标记的路径条目（无正文，无法取原文），属内部路径记录，忽略即可

结果条数按需（学习场景通常看前 3-5 条）；多条命中时按相关度取舍。

### Step 3：深读与定位

- **fulltext 命中** → `sourcePath` + 行号区间即出处，可直接回答"出自哪里"
- **需要上下文**（前后文、完整知识点、关联课程）：
  1. **本地文件优先**：按 `sourcePath` 定位工作区文件——形态依导入方式而异（可能是完整相对路径，也可能只是文件名）；直接拼不出时**按文件名在工作区搜索**，找到唯一匹配后读该文件行号附近内容（前后各 30 行左右）
  2. **ki 副本回退**：本地文件确实找不到 → `ki_get_module_info(scope, group, relation)` 读 ki 中的原文（`group` / `relation` 取自检索结果字段）
- 用 `ki_query_group` 可做目录导航（看教程有哪些文档、按结构找内容）

### Step 4：组织回答

- 先直接回答，再附来源；来源含教程名与行号
- 教程原文与自身知识补充分开标注（补充内容标注"教程未覆盖，以下为补充"）
- 教程中提示的关联课（如"详见课 17"）可顺带提示，帮助用户续学

## 教程修订与回写

**触发**：发现教程内容与实际不符 / 需补充 / 需优化时（用户指出，或问答中对照发现）。多处修改分布在多个文档时，逐文档重复本流程。

**流程**：

1. **全文检索定位**：用出问题的原文表述做 query（`ki_search(scope, query, mode="fulltext")`）→ 取命中项的 `sourcePath`（目标文件）、`group`（ki 落点）、行号

   手上没有可匹配的原文片段时：先用语义检索找到候选段落，再以该段落做全文检索精确定位

2. **读文件确认**：读目标文件的行号附近内容，确认修改点与上下文；向用户说明拟修改内容与**依据来源**（用户指出 / 官方文档 / 实测证据）——**不单独凭模型记忆判定"教程有误"**，存疑时先向用户求证；用户已明确要求修改时直接执行

3. **修改工作区文件**：直接编辑教程文件——改动最小化，保持教程原有体例与风格

4. **回写 ki**（更新索引）：

   ```bash
   ki import -s <教程scope> --source "<修改后的文档绝对路径>" --group "<原group>" --conflict-mode overwrite
   ```

   - `-s`：教程 scope（本对话已确认的）
   - `--source`：修改后的文档路径（工作区绝对路径）
   - `--group`：原文档在 ki 中的落点（取自第 1 步检索结果的 `group` 字段，**原样复制**，不要臆造）
   - `--conflict-mode overwrite`：覆盖原文档完成更新；**不可省略**——默认 suffix 会新增 `_1` 副本而不是更新
   - `--no-vector`（可选）：**向量不可用时加上这个参数**（FTS-only：不调 embedding），**依然可以进行全文索引查询**

5. **验证回写**：用全文检索搜修改后的新表述，确认 ki 中已是新内容；未生效时重跑一次并检查命令输出

**注意**：`ki import` 是终端命令（CLI），`ki_search` 等是 MCP 工具——两者途径不同，勿混淆。

## 输出格式

**检索命中**：

```text
{基于教程原文的回答}

**来源**（《{教程名}》）
- {sourcePath} 第 {N}-{M} 行
```

**检索未命中**：

```text
未在《{教程名}》中检索到与「{主题}」相关的内容（已尝试：{查询词}）。
可尝试：换个说法/术语重试、换检索模式、确认教程是否覆盖该主题。
```

**修订回写完成**：

```text
已修订《{教程名}》：
- 文件：{sourcePath}（第 {N}-{M} 行）
- 改动：{一句话说明}
- ki 回写：ki import ... --conflict-mode overwrite ✅
```

## 异常与降级

| 情况 | 处理 |
|------|------|
| ki 工具不可用 | 说明"教程库暂不可达"；若工作区即教程仓库，用本地 Glob/Grep 检索教程文件兜底 |
| 教程未导入（scope 列表无对应项） | 如实告知未导入；工作区有对应教程目录时可转本地文件路径 |
| 检索无命中 | 换查询词或模式重试一次；仍无 → 如实说明"未收录或表述不同" |
| 语义检索不可用（返回 `ok=false` / `degraded=true`，如"向量检索暂不可用"） | 自动降级为 `mode="fulltext"`、query 改关键词组合（术语并排、去虚词）；回答中标注"语义检索当前不可用，已用全文检索" |
| 结果明显与问题不相关 | **不要强行解读**——疑似该 scope 内容异常（如混入其他教程），用 `ki_query_group` 抽查 scope 内容后向用户如实说明 |
| 粘贴原文未命中 | 请用户确认片段是否来自该教程；截取更独特片段重试 |
| 回写失败（ki import 报错） | 输出错误信息，核对 scope / `--source` 路径 / `--group` 落点后重试；文件修改本身不受影响 |
| 回写后检索不到新内容 | 可能索引更新延迟，稍后重试检索；确认 import 命令输出无报错 |
| 回写后仍能检索到旧内容 | 检查是否有后缀副本残留（`_1` 等，早期非 overwrite 导入的产物）——用 `ki_query_group` 查看该文档所在 group 的 relation 列表，确有副本时与用户确认后清理 |

## 与其他 skill 的关系

| skill | 关系 |
|-------|------|
| ki-search-first | 场景互补：开发任务"先查项目记忆"走它；学习提问"先查教程库"走本 skill |
| ki-memory-lookup | 平行查询器：同用 ki MCP 但数据域不同——它查项目记忆（专题 / 接口 / 数据流 / 强关联等 7 类，scope = 项目标识）；本 skill 查教程库（scope = 教程名） |
| topic-teach | 消费方：教学材料生成需要引用教程库内容时调用本 skill |
