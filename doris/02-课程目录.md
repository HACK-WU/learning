## 综合实战项目（Phase 3）✅ 已完成 2026-09-03

### [电商实时数仓：从 MySQL 到四层 Doris 数仓](projects/1-电商实时数仓/README.md) ✅

> 把 12 课、36 个知识点串进一条能真跑的链路：ODS → DWD → DWS → ADS 四层建模，
> 批量（MinIO + S3 TVF）与实时（Kafka + Routine Load）双链路接入，
> Rollup / MV / Colocate / Profile 加速调优，副本 / 隔离 / 变更 / 备份生产化，
> 最后验收并划清边界。

| # | Task | 锚定课程 |
|---|------|---------|
| 1 | [需求与建模](projects/1-电商实时数仓/task-1-需求与建模.md) ✅ | 课 1、3、4、12 |
| 2 | [数据接入：批量 + 实时双链路](projects/1-电商实时数仓/task-2-数据接入.md) ✅ | 课 6、4 |
| 3 | [查询加速与调优](projects/1-电商实时数仓/task-3-查询加速与调优.md) ✅ | 课 5、7、8 |
| 4 | [生产化：副本、隔离、变更、备份](projects/1-电商实时数仓/task-4-生产化.md) ✅ | 课 9、10、11 |
| 5 | [验收与边界](projects/1-电商实时数仓/task-5-验收与边界.md) ✅ | 全课程 + 课 12 |

**交付脚本**（`assets/`）：`phase3-task1-setup.sh` → `phase3-task2-load.sh` → `phase3-task3-tune.sh` → `phase3-task4-prod.sh` → `phase3-task5-accept.sh`（须按序执行）

**五个最贵的收获（全部实测复现）**：维表值必须来自数据（否则 INNER JOIN 静默丢 4 个省）、代理主键用 `ROW_NUMBER() OVER (PARTITION BY order_date ...)` 而非业务列拼装（否则撞车丢 58%）、`order_id` 只在当天唯一（`WHERE order_id=xxx` 的「单行」DELETE 实测删 331 行）、RESTORE 默认 3 副本不沿用原表（失败藏在 `SHOW RESTORE`）、分区 MV 在本机刷不出数据（改用非分区版）
